添加您信任的列表来源，让 Sinkhole 在防火墙上保留规范化的最后有效副本，供 DNS 立即使用。

## 为什么使用已保存列表？ \{#why-use-saved-lists}

1. 让 DNS 不依赖列表主机，因此缓慢或失败的下载不会中断名称解析。
2. 每个来源只下载一次，因此同一份已保存副本可以用于全局、网络和设备作用域。
3. 新下载或解析失败时保留上一份有效副本，因此损坏的输入不会替换可用策略。
4. 在后台更新列表，因此 Resolver 重启或重新加载永远不必等待网络。

## 通过 URL 添加列表 \{#add-a-list-by-url}

打开 **Firewall → Sinkhole → Lists**，选择阻止列表表格下方的 **Add**，然后在编辑页面填写 **Add Block List**：

| 字段      | 说明                        |
|---------|---------------------------|
| Name    | 在分配、警报和 Status 中显示的本地标签。  |
| URL     | 不包含嵌入凭据的 HTTP 或 HTTPS 来源。 |
| Enabled | 下载来源，并使其可供已分配的作用域使用。      |
| Global  | 在设备和网络决定之后，将来源应用于每个客户端。   |

保存后会返回 Lists 选项卡，并启动同一条经过验证的后台应用路径。选择某行的铅笔图标或双击该行即可编辑。禁用的行仍保留配置，但会在表格中显示为灰色，更新程序和编译策略也不会使用它。

## 可接受的 DNS 格式 \{#accepted-dns-formats}

Sinkhole 接受以下标准格式，并将有效名称规范化为一个已保存域名集合：

| 格式           | 示例                                            | 行为            |
|--------------|-----------------------------------------------|---------------|
| Hosts 文件     | `0.0.0.0 blocked.example`                     | 仅阻止地址后的每个域名。  |
| 纯域名列表        | `blocked.example`                             | 仅阻止每行中的域名。    |
| Adblock 风格规则 | <code>{'\u007c\u007cblocked.example^'}</code> | 阻止该域名及其所有子域名。 |

如果希望一个条目阻止该名称及其所有子域名，请使用 Adblock 风格的 `||name^` 形式。

装饰过滤器和格式错误的行不会成为 DNS 策略。Status 会报告来源错误；如果失败列表已有有效副本，则会继续保留该副本。

## 搜索目录 \{#search-the-catalogs}

在 Lists 选项卡选择 **Add from Catalog**，搜索 AdGuard Home 的列表注册表和 pfBlockerNG 源目录的 DNS 部分。Sinkhole 仅在搜索打开或您选择 **Refresh** 时获取两者；不会捆绑目录，也不会按计划下载目录。

结果以卡片形式显示。组合使用搜索、来源和维护者控件，选择类别芯片，并在 **Category** 和 **Maintainer** 之间切换 **Group by**。类别芯片显示当前搜索、来源和维护者筛选器的计数，而维护者菜单会把匹配列表最多的所有者排在最前面。

每张卡片显示列表名称、维护者或类别（以当前未作为分组依据的一项为准）、源目录、两行说明、主页以及 **Add** 或 **Added** 状态。卡片不显示评分、徽章或推荐。选择 **Add** 会创建一个普通列表行，其 URL 可像任何手动输入的来源一样分配。

每张卡片的 **Contents** 行显示 **Domains**。添加目录结果时，其目录名称保持不变。

目录副本在 `/var/db` 下缓存一天。刷新失败时会保留最后一份有效目录副本，并在 Status 上显示获取错误。

## 设置全局允许域名 \{#set-global-allowed-domains}

列表和目录面板下方的 **Allowed Domains** 部分定义全局例外。每一行允许该域名及其子域名通过继承的全局列表。选择该部分下方的 **Save** 以应用这项页面级设置。

全局允许域名在设备和网络规则之后检查，因此不能覆盖已在更具体的设备或网络层级阻止查询的列表。

## 选择更新频率 \{#choose-the-update-frequency}

**General → Update Frequency** 设置控制计划 DNS 列表更新；启用 IP 阻止时，它也提供更新计划：

| 设置            | 计划                     |
|---------------|------------------------|
| Hourly        | 每小时在防火墙稳定的随机分钟运行一次。    |
| Every 6 hours | 每六小时在同一个稳定随机分钟运行。      |
| Daily         | 每天在该分钟运行一次，计划小时为 `00`。 |
| Weekly        | 每周日该分钟运行一次，计划小时为 `00`。 |

`Daily` 是默认值。**Status → Update Now** 会启动手动完整更新，但不会改变已保存计划。

## 更新期间发生的操作 \{#what-happens-during-an-update}

1. 通过有界下载客户端下载每个已启用来源。
2. 将其解析并规范化为临时副本。
3. 仅在新副本有效时原子替换已保存副本。
4. 编译当前的全局、网络、设备、允许域名和警报策略。
5. 部署新的本地代次，并让 Unbound 模块加载它。

当新增阻止名称扩大策略时，Sinkhole 会等待模块加载该代次，然后重新加载 Unbound 一次以清除缓存应答。[更新的工作方式](/docs/safety/how-updates-work)介绍完整的可用性和回退模型。

使用包含空格或大于 `0x7f` 的字节等异常但有效的 DNS 标签查询被阻止的子树时，Sinkhole 会在响应中保留线格式名称，并仍返回正常的 `0.0.0.0` 或 `::` 响应。查询不会仅因标签不是主机名格式而变成 SERVFAIL。
