Bloquee sitios no deseados con políticas separadas para toda la red, una VLAN o un dispositivo, todo dentro de pfSense.

## Qué hace Sinkhole \{#what-sinkhole-does}

Sinkhole for pfSense permite a familias y empleadores controlar qué <Terminology title="Nombres o direcciones a bloquear, tomados de su URL" to="/docs/reference/terminology#lists-and-scopes">listas de bloqueo</Terminology> se aplican a cada parte de una red. Conserva las últimas copias válidas en el firewall para que el DNS responda inmediatamente después de un reinicio o una recarga mientras se descargan copias más recientes en segundo plano.

Los nombres bloqueados responden con `0.0.0.0` o `::`. También se bloquea una cadena CNAME que alcance un nombre bloqueado, mientras que un nombre permitido en el nivel decisivo sigue permitido.

## ¿Por qué usar Sinkhole? \{#why-use-sinkhole}

1. Aplica políticas en <Terminology title="A quién se aplica una lista: la red, una VLAN o un dispositivo" to="/docs/reference/terminology#lists-and-scopes">ámbitos</Terminology> globales, de red y de dispositivo para que niños, invitados, empleados y dispositivos individuales puedan recibir listas diferentes.
2. Usa <Terminology title="La última copia válida: el DNS nunca espera una descarga" to="/docs/reference/terminology#lists-and-scopes">listas guardadas</Terminology> para que el DNS nunca espere una descarga ni pierda una lista funcional tras una actualización fallida.
3. Envía una <Terminology title="Avisa cuando las listas elegidas bloquean a clientes elegidos" to="/docs/reference/terminology#alerts">regla de alerta</Terminology> solo para las listas y los clientes que elija, mediante el sistema de notificaciones propio de pfSense.
4. Proporciona <Terminology title="Impide que los dispositivos eludan Sinkhole con su propio DNS" to="/docs/reference/terminology#bypass-protection">protección contra evasiones</Terminology> opcional para DNS simple, descubrimiento y proveedores de DNS cifrado, relays de Tor y proveedores o puertos de VPN.
5. Añade bloqueo IP y por país por separado cuando el filtrado DNS no basta, sin requerir otro host ni un servicio en la nube.
6. Fija los buscadores en <Terminology title="El modo seguro de un buscador, forzado en cada dispositivo de un ámbito" to="/docs/reference/terminology#lists-and-scopes">SafeSearch</Terminology> para los ámbitos que elija, de modo que los resultados filtrados no dependan de los ajustes de cada dispositivo.

## Cómo funciona la integración DNS \{#how-dns-integration-works}

Sinkhole se ejecuta como módulo Python dentro del <Terminology title="El DNS Unbound integrado de pfSense, donde se ejecuta Sinkhole" to="/docs/reference/terminology#dns-basics">DNS Resolver</Terminology> de pfSense, basado en Unbound. El módulo carga únicamente archivos locales compilados cuando se inicia Unbound y observa generaciones locales más recientes sin hacer esperar ninguna consulta DNS.

El DNS Resolver ofrece un único espacio para un script Python. Sinkhole solo lo ocupa cuando está libre o ya pertenece a Sinkhole, y se niega a sustituir a otro propietario, como el módulo DNSBL de pfBlockerNG.

:::warning

Sinkhole y pfBlockerNG no pueden filtrar DNS al mismo tiempo. Sinkhole permanece inactivo mientras pfBlockerNG esté instalado y activado, incluso cuando su DNSBL funciona en modo Unbound sin el espacio Python.

:::

## Qué permanece bajo su control \{#what-stays-under-your-control}

- **Lists** — Añada por URL las fuentes en las que confíe o búsquelas mediante la <Terminology title="Encuentre listas de bloqueo conocidas sin buscar URL" to="/docs/reference/terminology#lists-and-scopes">búsqueda de listas populares</Terminology> neutral. Sinkhole no publica ni recomienda ninguna lista.
- **Clientes y bloqueo** — Definí una red para una interfaz o VLAN de pfSense y un dispositivo identificado por una o varias direcciones IP, asignaciones DHCP estáticas y direcciones MAC, y después elegí las listas de Global, de cada red y de cada dispositivo.
- **Allowed domains** — Permita un dominio y sus subdominios en el nivel global, de red o de dispositivo sin retirar una lista completa.
- **SafeSearch** — Elija qué buscadores quedan fijados en su modo seguro para cada ámbito y si YouTube usa Moderate o Strict.
- **Alerts** — Elija las combinaciones de lista y cliente que crean avisos locales en la WebGUI o usan los servicios de notificación remota configurados en pfSense.
- **Bypass** — Mantenga todos los controles desactivados o seleccione interfaces orientadas a clientes y active explícitamente la redirección de DNS simple, las señales de DNS cifrado, las listas de proveedores o las protecciones de túneles.
- **IP blocking** — Manténgalo desactivado o seleccione listas IP, países, interfaces, direcciones y direcciones permitidas.

## Límites \{#limits}

El bloqueo DNS no constituye un control completo del tráfico. La protección contra evasiones solo cubre rutas alternativas comunes cuando se activa cada control y no puede identificar todos los túneles cifrados o personalizados.

Los eventos de bloqueo y los avisos revelan qué intentaron visitar los clientes. Esa información permanece en el firewall, salvo las notificaciones que decida enviar mediante pfSense.

## Idiomas \{#languages}

La WebGUI usa el idioma seleccionado en pfSense y está disponible en inglés y en las otras 17 configuraciones regionales de pfSense.
