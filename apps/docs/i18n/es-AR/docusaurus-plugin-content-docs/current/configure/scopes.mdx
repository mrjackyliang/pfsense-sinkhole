Defina cada red y cada dispositivo una sola vez en **Clients** y después elija en **Blocking** qué bloquea cada uno. Cada cliente recibe la política prevista para su ubicación actual.

## ¿Por qué usar redes y dispositivos? \{#why-use-networks-and-devices}

1. Proporciona a cada interfaz o VLAN de pfSense su propia política y conserva a la vez reglas globales para todos.
2. Proporciona a un dispositivo una decisión más específica sin requerir un servidor DNS separado.
3. Permite que los dominios permitidos corrijan falsos positivos en el nivel donde importan sin retirar una lista completa.
4. Mantiene las direcciones de los clientes separadas de las listas compiladas para que los cambios de DHCP, vecinos o interfaces no recarguen Unbound.

## Contextos \{#contexts}

Blocking, Services, SafeSearch, Alerts, Bypass e IP comparten una segunda fila de pestañas debajo de las pestañas principales:

| Pestaña  | Qué edita la página                                                                                                              |
|----------|----------------------------------------------------------------------------------------------------------------------------------|
| All      | Nada. Una tabla de solo lectura lista cada contexto que tiene configuración propia; seleccione una fila para abrir ese contexto. |
| Global   | La configuración para todos los clientes.                                                                                        |
| Networks | Una red. Una fila de chips de red elige cuál.                                                                                    |
| Devices  | Un dispositivo. Una fila de chips de dispositivo elige cuál, y el cuadro de búsqueda filtra los chips por nombre.                |

Un banner debajo de la fila indica qué está editando, por ejemplo **Editing: Network: IOT · applies to clients on IOT** o **Editing: Device: Tablet · this device only**. Cada contexto muestra solo su propia configuración; nada heredado de un contexto más amplio aparece en su formulario.

El contexto seleccionado se mantiene al cambiar de pestaña hasta que elija otro. Una red o un dispositivo desactivado puede seguir editándose, y una advertencia indica que su configuración no se aplica a ningún cliente hasta que se vuelva a activar.

## Definir redes \{#define-networks}

Abra **Firewall → Sinkhole → Clients** y seleccione **Add** debajo de la tabla Networks. El editor usa de forma predeterminada LAN, o la primera interfaz disponible que no sea WAN, y omite las interfaces que ya tengan una red. Un cliente pertenece a esa red cuando su dirección está dentro de una de las subredes IPv4 o IPv6 actuales de la interfaz.

Cada fila de red tiene una interfaz y una casilla **Enabled**. Al guardar se vuelve a Clients; seleccione el lápiz o haga doble clic en una fila para editarla. Un dispositivo que cambia de red recibe la política de la red con la que coincide su dirección actual.

## Definir dispositivos \{#define-devices}

Seleccione **Add** debajo de la tabla Devices, indique un nombre y agregue una o más filas de identificadores. Cada fila tiene un tipo y el valor que corresponde a ese tipo:

| Tipo de identificador | Direcciones usadas para el dispositivo                                                       |
|-----------------------|----------------------------------------------------------------------------------------------|
| IP address            | La dirección IPv4 o IPv6 configurada.                                                        |
| DHCP static mapping   | Su dirección configurada y las direcciones actuales observadas para la MAC de la asignación. |
| MAC address           | Las direcciones actuales de ARP, NDP y concesiones DHCP para esa MAC.                        |

Use **Add Identifier** y los botones de papelera para mantener las filas. Un dispositivo necesita al menos un identificador. Toda dirección alcanzada mediante cualquiera de sus identificadores corresponde al mismo dispositivo y, por lo tanto, comparte una única configuración y un único estado de activación. Al guardar se vuelve a Clients; seleccione el lápiz o haga doble clic en una fila para editarla. Un trabajo en segundo plano actualiza cada minuto las subredes y direcciones de dispositivos mientras el bloqueo DNS tenga una red o un dispositivo activado, o mientras la protección DNS de Bypass necesite identificar clientes. Sync del paquete inicia la misma actualización solo bajo esa condición.

Eliminar una red o un dispositivo en Clients también elimina su configuración de Blocking, Services, SafeSearch, Bypass e IP.

## Elegir listas y dominios permitidos \{#choose-lists-and-allowed-domains}

Abra **Firewall → Sinkhole → Blocking** y elija un contexto:

- **Global** selecciona las listas que se aplican a todos los clientes después de las decisiones de dispositivo y red, y contiene los dominios permitidos globales.
- **Networks** selecciona las listas y los dominios permitidos adicionales para los clientes de la red elegida.
- **Devices** selecciona las listas y los dominios permitidos adicionales para el dispositivo elegido.

Cada contexto tiene un cuadro **Lists** y un cuadro **Allowed Domains** con un dominio por línea. Seleccione **Save** para aplicar ese contexto. Arrastre la esquina inferior del cuadro **Lists** para agrandarlo cuando tenga muchas listas. Las listas en sí se agregan y editan en la pestaña [Lists](/docs/configure/lists).

**All** muestra una fila por cada contexto que tiene listas o dominios permitidos, con los nombres de sus listas y la cantidad de dominios permitidos.

## Orden de decisión \{#decision-order}

El nivel coincidente más específico decide cada consulta en este orden exacto:

1. **Dominios permitidos del dispositivo** — Permiten inmediatamente si coincide el nombre consultado.
2. **Listas del dispositivo** — Bloquean inmediatamente si coincide una lista seleccionada del dispositivo.
3. **Dominios permitidos de la red** — Permiten inmediatamente si coincide la excepción de la red.
4. **Listas de la red** — Bloquean inmediatamente si coincide una lista seleccionada de la red.
5. **Dominios permitidos globales** — Permiten inmediatamente si coincide la excepción global.
6. **Listas globales** — Bloquean si coincide una lista global.

La consulta se permite cuando ningún paso toma una decisión. Un cliente que no coincide con ninguna red ni ningún dispositivo activado recibe solo los pasos globales. Los dominios permitidos de un nivel anulan las listas heredadas de niveles menos específicos, pero no las listas de un nivel más específico que ya haya decidido.

## Comportamiento de los dominios permitidos \{#allowed-domain-behavior}

Cada entrada de dominio permitido se aplica al dominio exacto y a todos sus subdominios. Por ejemplo, permitir `service.example` también permite `api.service.example` en ese nivel.

- Una excepción de dispositivo puede atravesar las listas del dispositivo, de la red y globales porque se comprueba primero.
- Una excepción de red puede atravesar las listas de la red y globales, pero no una decisión de lista del dispositivo.
- Una excepción global solo puede atravesar las listas globales.

## Conflictos de direcciones \{#address-conflicts}

Varios identificadores del mismo dispositivo pueden alcanzar una dirección sin generar un conflicto. Cuando dos dispositivos diferentes reclaman la misma dirección actual, gana el primer dispositivo de la tabla Clients. La tabla Clients y **Status → Clients** muestran la dirección en **Conflict** para cada fila afectada, de modo que puedan corregirse el orden o los identificadores.

## Verificar una red o un dispositivo \{#verify-a-network-or-device}

1. Ejecute `/usr/local/sbin/sinkhole --refresh-clients` o espere a la actualización por minuto.
2. Abra **Status → Clients** y confirme las subredes actuales de la red y las direcciones actuales del dispositivo.
3. Consulte un nombre desde un cliente de esa red o desde ese dispositivo y compare el resultado con el orden de decisión anterior.
4. Compruebe si hay un conflicto de dirección antes de depender del comportamiento específico del dispositivo.
