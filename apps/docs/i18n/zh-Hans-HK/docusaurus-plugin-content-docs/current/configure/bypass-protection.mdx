让所选客户端接口的 DNS 查询始终沿着 Sinkhole 可以检查的路径传输。所有保护功能默认关闭，默认不选择任何接口，升级也不会启用任何保护功能或列表。

## 选择接口 \{#choose-the-interfaces}

打开 **Firewall → Sinkhole → Bypass**，并在启用保护功能之前选择 **Apply to** 接口。此选择属于 **Global**，决定 Global 的设置在哪里生效。保护功能只检查从这些接口上的客户端传入的流量；不会影响防火墙自身的查询或出站流量。

网络和设备匹配与普通 Sinkhole 作用域一样，使用这些接口的当前子网。所选子网之外的客户端不会收到 Bypass DNS 响应。

## 按网络和设备设置保护 \{#set-protections-per-network-and-device}

选项卡下方的一行决定您要编辑的内容：**All**、**Global**、某个网络或某个设备。其下方的一行列出这些设置适用的客户端。每个选项只显示自己的设置；绝不会显示更宽泛选项的设置。

客户端遵循现有设置中最具体的一项：先是其设备的设置，然后是其网络的设置，最后是 Global 的设置。在 Clients 选项卡上已关闭的网络或设备会被跳过。

只有 **Global** 包含：

- **Apply to** 接口。
- **Plain DNS** 重定向及其豁免。

网络或设备还包含 **Enable**，用于开启其保护功能。

Global 以及每个网络或设备都包含：

- **Bypass Lists**，即其使用的已启用来源。来源在 [Lists → Bypass](/docs/configure/lists#add-bypass-lists) 中添加、启用和更新。没有已启用的来源时，该字段会改为显示一行带有 **Open Lists** 链接的文字。
- 加密 DNS 设置、**Discovery**、隧道拦截和 **Block Exemptions**。

没有自身设置的网络或设备会在空白表单上方显示一行，例如“此网络未单独设置，将使用全局。”如果设备所属网络有自身设置且已开启，设备会在此处注明该网络。设置已关闭的网络或设备则会改为显示“已关闭，将使用全局。”，并注明同样的更宽泛设置。保存表单即可创建设置，**Remove settings for this network** 或 **Remove settings for this device** 会删除设置，让更宽泛的设置重新生效。在 Clients 选项卡上删除网络或设备也会删除其设置。

**All** 列出 Global 以及每个有自身设置的网络和设备，并显示已开启的保护功能。选择某行即可编辑。

将 Sinkhole 升级到 1.3.0 时，现有设置会保留在 Global 中，并复制到每个网络和设备。此后每份副本相互独立。只有当网络的接口，或设备某个标识符的接口，已在 **Apply to** 中选中时，该副本才会开启；其他副本均以关闭状态保存，因此之前未被过滤的客户端不会因此被过滤。

Global 与每个网络和设备一样选择自己的 Bypass Lists。将 Sinkhole 升级到 1.3.1 时，Global 的选择会变为当时已存在的所有 Bypass List，因此在您编辑之前不会有任何变化。之后添加的 Bypass List 在 Global、某个网络或某台设备选择它之前不会在任何地方使用。

每个已开启设置的网络或设备都会在 `sinkhole/bypass` 锚点中获得自己的客户端表。设备的地址会从其网络的表和 Global 的表中移除，网络的子网会从 Global 的表中移除，因此客户端只会被其最具体的设置拦截。Sinkhole 不会为此添加 pass 规则。

## 重定向普通 DNS \{#redirect-plain-dns}

选择 **Redirect → Send port 53 to the firewall**，将所选接口上的普通 TCP 和 UDP DNS 流量发送到 pfSense。Sinkhole 会保留源地址，因此网络和设备策略仍然适用。

重定向会保留现有的监听器感知目标和豁免：

| 地址族  | 目标                                                     |
|------|--------------------------------------------------------|
| IPv4 | Resolver 监听 localhost 时使用 `127.0.0.1`；否则使用接口的 IPv4 地址。 |
| IPv6 | 使用接口的 IPv6 地址，绝不使用 `::1`。                              |

- **Exempt Sources** 仍可访问其他解析器。
- **Exempt Destinations** 仍可接收 DNS 流量，从而支持其他网络上的内部解析器。

每项豁免每行接受一个 IPv4 地址、IPv6 地址、CIDR 网络或现有 pfSense 主机/网络别名。无效的已保存豁免会暂停所有重定向规则，直到修复或删除该豁免。重定向的客户端仍需获得 Resolver 访问控制设置的允许。

只要 Sinkhole 在 **General** 选项卡中已启用且 DNS Resolver 正在运行，重定向规则就会加载。它们不依赖 Resolver 的 Python 模块，因此在 pfBlockerNG 或其他脚本占用该模块时（例如从 pfBlockerNG 迁移期间）仍会继续工作。当 Redirect 已开启但其规则未加载时，**Redirect** 下方的 **Warning** 行会给出原因：

- Sinkhole 已禁用。
- DNS Resolver 未运行。
- 某个已保存的豁免无效。
- 正在移除 Sinkhole。

**Status** 也会在页面顶部显示同样的警告。

## 保护加密 DNS \{#protect-encrypted-dns}

各项加密 DNS 设置彼此独立：

- **TLS and QUIC** 拦截发往防火墙以外任何目标的 TCP 和 UDP 端口 853。
- **Providers** 拦截种类为 **Encrypted DNS** 的已选择且已启用 Bypass Lists 中的名称和地址。
- **Firefox** 对 `use-application-dns.net` 及其子域返回 `NXDOMAIN`，从而关闭 Firefox 自动选择 DNS over HTTPS 的功能。
- **Private Relay** 对 `mask.icloud.com` 和 `mask-h2.icloud.com` 返回 `NXDOMAIN`，告知兼容的 Apple 设备此网络不提供 Private Relay。

提供商列表中的名称在 DNS 中被拦截。同一列表中的 IPv4 地址、IPv6 地址和 CIDR 会在独立的 `sinkhole/bypass` 防火墙锚点中针对所有端口和协议进行拦截。Sinkhole 会在加载这些表之前，从中删除防火墙的接口地址以及网关和 DNS 服务器地址，包括通过 DHCP 或 PPP 获取的地址。

Bypass 选项卡上的每条防火墙拦截规则都会像 pfSense 的 **Reject** 操作一样拒绝连接，而不是直接丢弃：TCP 会收到重置，UDP 会收到 ICMP 目标不可达消息。被拦截的客户端会立即失败并改用防火墙的 Resolver，无需等待超时。

允许的域名优先于提供商列表的名称拦截。它们不会覆盖 Firefox、Private Relay 或 Discovery 响应，因为这些响应是网络信号，而不是列表拦截。

## 配置 Resolver 发现 \{#configure-resolver-discovery}

Discovery 控制对 `_dns.resolver.arpa` 的查询，该名称是 RFC 9462 定义的 Designated Resolver Discovery 名称：

| 选项                                        | 响应                                                   |
|-------------------------------------------|------------------------------------------------------|
| **Off**                                   | 不更改查询。                                               |
| **Advertise the firewall's DNS over TLS** | 返回包含 `alpn=dot`、端口 `853` 和 Resolver 证书中主机名的 SVCB 响应。 |
| **Answer with no records**                | 返回空响应和 `NOERROR`。                                    |

**Advertise** 要求启用 DNS Resolver 的 SSL/TLS 服务，并提供可用的证书主机名。Bypass 页面会报告该服务是否已开启；服务不可用时，保存会失败并显示清晰的验证消息。

启用 Sinkhole 并选择 **Apply to** 接口后，开启 Discovery 会将以下托管块添加到 DNS Resolver 的 **Custom options**：

```text
# Sinkhole: begin (managed by the Sinkhole package)
server:
local-zone: "_dns.resolver.arpa." transparent
# Sinkhole: end
```

关闭 Discovery 或移除 Sinkhole 会删除该区域行。同一个块还承载所有 [Resolver 设置](/docs/configure/resolver-settings)，并且 Sinkhole 不会更改 **Custom options** 中的任何其他行。所选接口之外的客户端（包括防火墙本身）仍会收到 `_dns.resolver.arpa` 的 `NXDOMAIN`。

## 防范隧道 \{#protect-against-tunnels}

- **Tor → Block listed Tor relays** 应用种类为 **Tor** 的已选择且已启用 Bypass Lists。
- **VPN → Block listed VPN providers** 应用种类为 **VPN** 的已选择且已启用 Bypass Lists。
- **VPN → Block standard VPN ports** 拦截发往防火墙以外任何目标的 TCP 和 UDP `1194`、UDP `51820`、UDP `500` 和 `4500` 以及 ESP。

Tor 和 VPN 列表中的名称和地址使用与加密 DNS 提供商列表相同的 DNS 和防火墙行为。这些控制可以减少常见的替代路径，但无法识别所有加密或自定义隧道。

## 让设备和服务器免受拦截 \{#exempt-devices-and-servers-from-the-blocks}

**Block Exemptions** 包含一个 **Exempt Sources** 列表和一个 **Exempt Destinations** 列表，由 Bypass 标签页上的所有防火墙拦截共用：**TLS and QUIC**、**Providers**、**Tor**、**Block listed VPN providers** 和 **Block standard VPN ports**。每行接受一个 IPv4 地址、IPv6 地址、CIDR 网络或现有 pfSense 主机/网络别名，与重定向豁免接受的值相同。每个列表最多包含 16 个别名。

- **Exempt Sources** 会跳过这些拦截。可将其用于必须访问外部 DNS 服务器的客户端，例如通过 DNS over TLS 连接 `1.1.1.1` 的 NAS。
- **Exempt Destinations** 对所选接口上的每个客户端始终可达，不受这些拦截影响，例如一个您信任的公共解析器。

豁免本身绝不会打开任何路径。Sinkhole 不添加任何 pass 规则：豁免流量只是不匹配 Bypass 拦截，然后继续交给您自己的防火墙规则，由它们决定是否放行。

豁免只覆盖防火墙拦截。对豁免客户端来说，Bypass Lists 中的提供商、Tor 和 VPN 名称在 DNS 中仍会被拦截，因此通过名称查找服务器的客户端（例如 `cloudflare-dns.com`）还需要将该名称加入 **Allowed Domains**。端口 53 上的普通 DNS 则遵循 **Redirect** 及其自身的豁免。

如果已保存的拦截豁免变为无效，例如别名被重命名或删除，Sinkhole 会保留所有拦截且不应用任何豁免，写入一条系统日志，并在 **Invalid Saved Values** 中显示该值，直到它被修正或移除。

## 管理 Bypass Lists \{#manage-bypass-lists}

Bypass List 来源在 [Lists → Bypass](/docs/configure/lists#add-bypass-lists) 中添加、编辑、启用和删除，该处还提供 **Add from Catalog** 以及每个列表的 **Used By** 计数。Bypass 选项卡只选择每个上下文使用哪些已启用列表。已启用的 Bypass List 仅在其对应的 **Providers**、**Tor** 或 **VPN** 保护开启时才会加入计划更新。

## 验证活动状态 \{#verify-the-active-state}

保存后，打开 **Status → Bypass**，确认每项预期保护均为 `On`、所选接口正确，并且 Discovery 开启时 **Discovery Zone** 为 `Present`。确认防火墙保护的 **Firewall Rules Loaded** 和 **Firewall Rules Current** 均为 `Yes`。Bypass Lists 表会显示已保存条目数和上次获取时间。

普通 DNS 重定向会在 Resolver 监听器更改后保留现有的两次观察分钟协调。`sinkhole/bypass` 锚点独立于 `sinkhole/ip` 加载，因此禁用任一功能都不会干扰另一个功能。
