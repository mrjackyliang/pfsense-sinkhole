Sinkhole отделяет загрузку от службы DNS, поэтому удалённый источник никогда не оказывается в пути обработки запросов Resolver.

## Процесс обновления списков DNS \{#dns-list-update-flow}

Для каждого включённого списка DNS Sinkhole:

1. Загружает источник с ограничениями по времени и размеру.
2. Разбирает поддерживаемые записи hosts, обычных доменов и правил в стиле adblock во временный нормализованный набор.
3. Атомарно заменяет сохранённую копию только после успешной проверки нового содержимого.
4. Компилирует глобальную, сетевую и устройственную политики, а также политики разрешённых доменов и оповещений из локально сохранённых данных.
5. Развёртывает поколение в `/var/unbound`, где его обнаруживает уже загруженный модуль Python.

При ошибке загрузки, разбора или проверки записывается ошибка, но последняя исправная копия не заменяется. В течение всей попытки DNS продолжает использовать развёрнутое локальное поколение.

## Развёртывание и кэши Resolver \{#deployment-and-resolver-caches}

Модуль Unbound проверяет наличие нового манифеста между запросами и переключается на полное поколение, только когда готовы все указанные файлы. Status отдельно показывает идентификаторы скомпилированного, развёрнутого и загруженного поколений, чтобы можно было проверить каждый этап.

Когда политика добавляет заблокированные имена или расширяет заблокированное поддерево, Sinkhole ждёт, пока модуль сообщит о новом поколении, а затем один раз перезагружает Unbound. Перезагрузка очищает кэши сообщений и RRset, которые один `flush_zone` может оставить доступными для **Serve Expired**.

## Обновление карты клиентов \{#client-map-refreshes}

Сетевые подсети и адреса устройств хранятся отдельно от скомпилированных данных доменов. Когда для блокировки DNS включена область сети или устройства либо DNS-защите Bypass требуется определение клиентов, Sinkhole обновляет карту клиентов каждую минуту без перезагрузки Unbound.

Sync пакета запускает то же обновление только при этом условии. Это охватывает изменения интерфейсов, аренды DHCP, соседей и статических сопоставлений, происходящие вне обновления списка. После отключения всех функций Sinkhole следующий Sync удаляет рабочую карту клиентов и её необязательную копию на RAM-диске.

## Процесс обновления IP и стран \{#ip-and-country-update-flow}

Когда включена блокировка IP-адресов и стран, то же запланированное или ручное обновление загружает включённые списки IP и обновляет подходящие данные GeoLite2. Sinkhole разбирает и объединяет каждое семейство адресов, вычитает список разрешений администратора и защищённые адреса межсетевого экрана, затем атомарно заменяет файлы таблиц семейств.

После успешного обновления существующий якорь `sinkhole/ip` может получить только замену таблицы через `pfctl -T replace`. Sync и ежеминутная проверка целостности загружают якорь полностью, если правила или таблицы отсутствуют либо отличаются.

## Расписания и блокировка \{#schedules-and-locking}

По умолчанию списки обновляются с частотой Daily. Расписания Hourly, Every 6 hours, Daily и Weekly используют стабильные случайные минуты, поэтому время задания межсетевого экрана не меняется при каждом сохранении.

Обновления списков DNS, IP и стран, работа по применению из каталогов и самообновление пакета координируются через `/var/run/sinkhole-update.lock`. Действие Update пакета ждёт завершения активного обновления списка, а не меняет установленный пакет во время его работы.

## Обновление каталогов выполняется отдельно \{#catalog-refreshes-are-separate}

Реестр AdGuard Home и каталог источников pfBlockerNG загружаются только при открытии поиска по каталогу или выборе **Refresh**. Их кэш последней исправной копии можно использовать повторно в течение одного дня, а ошибка загрузки не меняет настроенные списки.

Результаты каталога — метаданные для поиска, а не политика. Результат влияет на блокировку DNS или IP только после добавления в качестве обычного настроенного списка и прохождения стандартного процесса обновления.

## Проверка состояния обновления \{#read-update-state}

Откройте **Firewall → Sinkhole → Status** и сравните ошибки источников, число сохранённых записей, флаг выполняемого обновления и скомпилированное, развёрнутое и загруженное поколения. Для блокировки IP также сравните число записей в таблицах и состояние якоря `sinkhole/ip`.

Для проверки версий пакета и самообновления используйте раздел [Обновления](/docs/reference/updates). Если этап сообщает об ошибке или остаётся в ожидании, используйте раздел [Устранение неполадок](/docs/operate/troubleshooting).
