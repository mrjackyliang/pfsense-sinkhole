## Панели Status \{#status-panels}

Откройте **Firewall → Sinkhole → Status**, чтобы увидеть следующие панели:

| Панель                  | Сведения                                                                                                                                        |
|-------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------|
| Summary                 | Компиляция, развёртывание, поколение, операция, владелец Resolver, общее состояние Sinkhole и **Update Now** под панелью.                       |
| Lists                   | URL списка DNS, число сохранённых записей, последнее успешное обновление и последняя ошибка.                                                    |
| Popular-List Catalogs   | Последняя загрузка и ошибка для источников каталогов AdGuard Home и pfBlockerNG.                                                                |
| Invalid Saved Rows      | Неправильно сформированные строки списков, которые остаются доступными для исправления; отображаются только при их наличии.                     |
| Scopes                  | Время и ошибка перестроения карты клиентов, затем отдельные панели Networks и Devices.                                                          |
| Alerts                  | Последний запуск, прочитанные или устаревшие события, отправленные или отложенные уведомления, отброшенные события и последняя ошибка.          |
| Bypass                  | Все механизмы защиты, интерфейсы, состояние правил перенаправления, состояние и счётчики якоря Bypass, затем Bypass Lists и панели исправления. |
| IP and Country Blocking | Выбранные политики, число таблиц и правил, обновления, ошибки и состояние якоря, затем отдельная панель IP Lists.                               |

Выключенные строки списков и областей действия отображаются приглушённо. Источник с ошибкой может по-прежнему показывать записи и более раннее успешное обновление, поскольку последняя исправная копия остаётся активной.

## Состояние Sinkhole \{#sinkhole-state}

Последняя строка **Sinkhole** на панели Summary — самый быстрый способ проверить интеграцию с Resolver:

| Состояние                                | Значение                                                                                                            |
|------------------------------------------|---------------------------------------------------------------------------------------------------------------------|
| `Active`                                 | Sinkhole включён, владеет местом Python, использует режим Python и `pre_validator` и имеет данные среды выполнения. |
| `Inactive: Sinkhole is disabled.`        | **Enable** в General выключено.                                                                                     |
| `Inactive: DNS Resolver is disabled.`    | DNS Resolver в pfSense выключен.                                                                                    |
| `Inactive: ... slot is owned by ...`     | Единственным местом владеет другой сценарий Python, например pfBlockerNG DNSBL.                                     |
| `Inactive: Sinkhole does not own ...`    | Настроенный сценарий не является Sinkhole, хотя другой владелец не указан.                                          |
| `Inactive: ... Python mode is disabled.` | В Resolver больше не включён режим Python.                                                                          |
| `Inactive: ... pre-validator position.`  | Порядок модулей больше не размещает Sinkhole в позиции `pre_validator`.                                             |
| `Inactive: ... runtime files ...`        | Отсутствует сценарий или текущее скомпилированное поколение.                                                        |

Когда Sinkhole намеренно выключен, **Deployment Needed** имеет значение `No`, **Loaded Generation** — `Module not loaded.`, а предупреждение о развёртывании не отображается. При другом неактивном состоянии интеграции **Deployment Needed** принудительно становится `Yes`, а **Loaded Generation** — `Module not loaded.`. Устраните указанную причину, прежде чем считать скомпилированные данные активными.

## Состояние компиляции и развёртывания \{#compile-and-deployment-state}

| Поле                | Значение                                                                                  |
|---------------------|-------------------------------------------------------------------------------------------|
| Compile Needed      | Сохранённая политика изменилась или последняя компиляция не завершилась успешно.          |
| Compiled Generation | Идентификатор, созданный последней успешной компиляцией.                                  |
| Deployment Needed   | Скомпилированные данные не совпадают с развёрнутыми для Unbound или интеграция неактивна. |
| Deployed Generation | Идентификатор в текущем развёрнутом манифесте среды выполнения.                           |
| Loaded Generation   | Идентификатор, который модуль Unbound сообщает как загруженный.                           |
| Update Running      | Отображается только пока обновление списка или IP удерживает общую блокировку обновления. |
| Removal in Progress | Отображается только пока установлен постоянный маркер удаления и интеграция отзывается.   |
| Python Script Owner | Текущее значение единственного места `python_script` в Resolver или `None`.               |

Если компиляция или развёртывание ожидаются, страница показывает предупреждение с записанной причиной. Совпадение идентификаторов скомпилированного, развёрнутого и загруженного поколений означает, что сохранённая политика достигла работающего модуля.

## Состояние областей действия и оповещений \{#scope-and-alert-state}

Сводка Scopes показывает состояние перестроения карты клиентов. На отдельных панелях **Networks** и **Devices** отображаются текущие CIDR каждого интерфейса и текущие адреса каждого устройства. Конфликт указывает адрес, на который претендуют несколько устройств; для политики адрес получает первое устройство в порядке таблицы.

Панель **Alerts** описывает только последнее минутное задание. **Notifications held back** включает подавление из-за пределов или непрочитанных уведомлений, а **Events dropped by module** означает, что ограниченная очередь событий в памяти или на диске переполнилась.

## Состояние Bypass \{#bypass-state}

Панель Bypass показывает `On` или `Off` для TLS and QUIC, списков поставщиков, Firefox, Private Relay, Tor, списков поставщиков VPN и стандартных портов VPN. **Discovery** показывает выбранный режим. **Interfaces** подтверждает общий выбор клиентских интерфейсов.

Независимый якорь межсетевого экрана показывает:

| Поле                    | Значение                                                                                                          |
|-------------------------|-------------------------------------------------------------------------------------------------------------------|
| Firewall rules loaded   | Существует ли якорь `sinkhole/bypass`, когда он требуется текущими настройками.                                   |
| Firewall rules current  | Соответствуют ли загруженные дайджест, правила и таблицы текущим настройкам и последним исправным данным списков. |
| Firewall rule count     | Число активных правил в якоре Bypass.                                                                             |
| IPv4/IPv6 table entries | Итоговое число адресов поставщиков, Tor и VPN после удаления защищённых адресов межсетевого экрана.               |

Таблица **Bypass Lists** показывает тип, состояние включения, число сохранённых записей, последнюю загрузку и последнюю ошибку каждой строки. Поэтому при сбое загрузки рядом с записями из сохранённой последней исправной копии может отображаться ошибка.

### Состояние перенаправления обычного DNS \{#plain-dns-redirect-state}

| Состояние | Значение                                                                                                                   |
|-----------|----------------------------------------------------------------------------------------------------------------------------|
| Off       | Перенаправление обычного DNS выключено.                                                                                    |
| On        | Redirect включён, и все сохранённые исключения допустимы.                                                                  |
| Paused    | Хотя бы одно сохранённое исключение источника или назначения недопустимо, поэтому правила перенаправления не используются. |

Поле **pfSense loaded rules** имеет три состояния:

| Состояние   | Значение                                                                                          |
|-------------|---------------------------------------------------------------------------------------------------|
| Yes         | `/tmp/rules.debug` содержит именно тот блок перенаправления, который сейчас нужен Sinkhole.       |
| No          | Требуемый блок не загружен.                                                                       |
| Out of Date | Блок Sinkhole загружен, но его текст не соответствует текущим настройкам или слушателям Resolver. |

Цель каждого семейства — выбранный адрес слушателя или причина, по которой правило нельзя построить. **Last parse error** отображается только пока текущий блок отсутствует после его отклонения pfSense.

## Состояние IP и стран \{#ip-and-country-state}

Основное состояние панели IP — **On** или **Off**. Поле **IP Anchor** использует **Yes**, **No** и **Out of Date** с тем же различием между загруженным и текущим состоянием, что и якорь Bypass.

Число записей в таблицах показывает окончательные объединённые сети IPv4 и IPv6 после вычитания разрешённых и защищённых адресов.

**Skipped Lines** подсчитывает недопустимые входные строки списка IP. Строки комментариев и пустые строки не учитываются.

**GeoLite2 Last Update** не зависит от последнего обновления списка.

## Запуск Update Now \{#run-update-now}

При выборе **Update Now** под Summary команда `/usr/local/sbin/sinkhole --manual` запускается в фоновом режиме, а страница сразу возвращается. Кнопка не передаёт поток вывода, поэтому результат показывают **Update Running**, строки списков DNS/Bypass/IP, поля компиляции и последние ошибки.

Задание вручную использует ту же общую блокировку обновления, что и запланированные обновления списков и самообновление пакета. Если блокировкой владеет другое обновление, существующее задание продолжается, а ожидающая работа по применению сохраняется.
