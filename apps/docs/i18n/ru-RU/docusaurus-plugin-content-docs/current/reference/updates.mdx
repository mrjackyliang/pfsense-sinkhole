Sinkhole может проверять свои выпуски GitHub, уведомлять через pfSense и устанавливать проверенный новый пакет со вкладки About.

## Запланированные проверки выпусков \{#scheduled-release-checks}

**General → Update Checks** выбирает Daily, Weekly, Monthly или Never; значение по умолчанию — Weekly. Sinkhole хранит стабильные случайные компоненты расписания, поэтому сохранение настроек не переносит время проверки постоянно.

Проверка записывает последнюю версию, страницу выпуска, время проверки и последнюю ошибку. **About → Check Now** немедленно запускает ту же проверку.

## Уведомления об обновлениях \{#update-notices}

Каждая впервые обнаруженная версия создаёт одно локальное уведомление pfSense WebGUI со ссылкой на вкладку About в Sinkhole. Повторные проверки не создают дубликаты для той же версии.

Выберите **Remote Notifications**, чтобы также использовать службы, настроенные в **System → Advanced → Notifications**. По умолчанию эта настройка выключена и влияет на уведомления о версиях, а не на правила оповещения о блокировке списков.

## Панель обновления About \{#about-update-bar}

На панели обновления отображаются установленная версия, последняя проверенная версия, последняя проверка, ссылка на выпуск, ошибка и ход отдельного обновления. Визуальные состояния различают отсутствие ожидающего обновления, новый выпуск, выполняемое обновление, успех и ошибку.

**Update** отображается, когда записанная последняя версия новее. Страница опрашивает отдельное задание и сообщает результат, не удерживая открытым запрос браузера.

## Проверка перед установкой \{#verification-before-installation}

Самообновление принимает файлы только с пути загрузки выпусков GitHub этого проекта и ограничивает размер и время загрузки. Оно требует стабильный пакет и его файл `.sha256`, проверяет дайджест SHA-256, а затем анализирует метаданные пакета перед установкой с помощью `pkg add -f`.

Если `/usr/local/share/pfSense-pkg-Sinkhole/release-signing.pub` содержит доверенные ключи Ed25519 OpenSSH, соответствующий отдельный файл `.sig` становится обязательным. Sinkhole проверяет эту подпись в пространстве имён выпуска, прежде чем разрешить `pkg` анализировать пакет.

Пустой установленный список доверия означает, что подпись не требуется, однако проверка контрольной суммы и метаданных пакета всё равно выполняется. Отсутствующий, неправильно сформированный, недоверенный, слишком большой или не соответствующий файл останавливает обновление и оставляет установленный пакет на месте.

## Блокировка обновлений \{#update-locking}

Проверка пакета и самообновление используют `/var/run/sinkhole-update.lock` совместно с обновлениями списков DNS и IP/стран. Если выполняется обновление списка, действие **Update** в About не начнётся до его завершения.

Блокировка не позволяет менять файлы пакета, пока текущий пакет загружает, разбирает, компилирует или применяет политику. Повторите попытку в About после того, как Status перестанет показывать выполняемое обновление.

## Обновление пакета вручную \{#manual-package-update}

Стабильная команда остаётся доступной, если действие About использовать нельзя:

```sh
pkg add -f https://github.com/mrjackyliang/pfsense-sinkhole/releases/latest/download/pfSense-pkg-Sinkhole.pkg
```

Перед запуском загрузите стабильный файл `.sha256` и сравните его хеш с пакетом, как описано в разделе [Установка](/docs/installation#verify-the-checksum). Флаг `-f` необходим, чтобы `pkg` установил новую сборку, даже если она получена с того же стабильного URL.

Привилегия About предоставляет только чтение. **Check Now** и **Update** отображаются и принимаются только для вошедшего пользователя с привилегией общих настроек Sinkhole или привилегией pfSense `page-all`. Пользователь только с привилегией About по-прежнему может просматривать установленную версию, состояние выпуска и ссылку на выпуск.
