Sinkhole использует обработчики пакетов pfSense для установки, повторного Sync, обновления и удаления, намеренно сохраняя Resolver и сохранённые данные.

## Установка и обновление \{#install-and-upgrade}

Установите или обновите пакет со стабильного URL выпуска:

```sh
pkg add -f https://github.com/mrjackyliang/pfsense-sinkhole/releases/latest/download/pfSense-pkg-Sinkhole.pkg
```

Обработчик установки записывает интеграцию пакета до любой требуемой перезагрузки службы или фильтра. Обработчики обновления допускают повторное выполнение и сохраняют настройки и списки при замене установленных программных файлов.

Пакеты, установленные напрямую с GitHub, не отображаются на странице **System → Package Manager → Installed Packages** в pfSense. Используйте командную строку или проверенное действие обновления на странице Sinkhole About, а не ищите запись репозитория Netgate.

## Sync пакета \{#package-sync}

pfSense вызывает Sync пакета при загрузке и после каждого изменения адреса WAN. Sinkhole использует его, чтобы при необходимости восстановить расписания, текущие адреса клиентов, интеграцию с Resolver, поколения среды выполнения, правила перенаправления обычного DNS и независимые якоря Bypass и IP.

Если изменений нет, Sync не записывает новую редакцию конфигурации, ничего не компилирует и не затрагивает Unbound. В системе с RAM-диском Sync при загрузке восстанавливает отсутствующее содержимое `/var/unbound` из постоянного зеркала и перезапускает Resolver только при необходимости.

## Почему обновление pfSense сохраняет Sinkhole \{#why-a-pfsense-upgrade-keeps-sinkhole}

Пакеты выпусков объявляют ABI как `FreeBSD:*` и устанавливают флаг жизненно важного пакета. Подстановочный знак позволяет устанавливать один пакет выпуска на разные основные версии FreeBSD, а vital-флаг не позволяет автоматическому удалению при обновлении pfSense удалить пакет, отсутствующий в репозитории Netgate.

Такое сохранение не заявляет о совместимости с непроверенным выпуском pfSense. Ознакомьтесь с разделом [Совместимость](/docs/compatibility) и проверьте пакет на тестовом межсетевом экране после обновления платформы.

## Keep Settings \{#keep-settings}

**General → Keep Settings** выбрано по умолчанию. При таком выборе удаление пакета сохраняет конфигурацию Sinkhole в pfSense и данные `/cf/conf/sinkhole`, чтобы списки и политика оставались доступными после повторной установки.

Это значение по умолчанию также защищает данные при обновлении через диспетчер пакетов, выполняющем удаление, а затем установку. Снимайте выбор, только если требуется полностью удалить конфигурацию и сохранённые данные.

## Удаление Sinkhole \{#remove-sinkhole}

Пакет выпуска является жизненно важным, поэтому явно принудительно удалите его, сохранив обычные обработчики жизненного цикла:

```sh
pkg delete -f pfSense-pkg-Sinkhole
```

При удалении останавливаются запланированные задания, блокируется новая работа по обновлению, восстанавливаются предыдущие настройки Python в Resolver, из **Custom options** DNS Resolver удаляется управляемый Sinkhole блок Discovery, удаляется содержимое среды выполнения `/var/unbound`, очищаются временные блокировки и состояние, отзываются правила перенаправления обычного DNS, очищаются якоря `sinkhole/bypass` и `sinkhole/ip`, а также удаляются кэшированные Bypass Lists и файлы таблиц. Управляемый блок Discovery удаляется независимо от того, включено или выключено **Keep Settings**. Также удаляются файлы пакета, установленные в `/usr/local`.

Когда **Keep Settings** включено, конфигурация и постоянные сохранённые списки остаются для повторной установки. Когда оно выключено, удаляются все настройки и сохранённые данные Sinkhole, включая `/cf/conf/sinkhole` и всю ветвь Sinkhole в конфигурации пакетов pfSense.

## Проверка удаления \{#verify-removal}

1. Убедитесь, что **Firewall → Sinkhole** больше не отображается.
2. Убедитесь, что сценарий Python и порядок DNS Resolver соответствуют значениям до установки Sinkhole.
3. Убедитесь, что не осталось заданий cron Sinkhole, блока перенаправления обычного DNS, якоря `sinkhole/bypass` или якоря `sinkhole/ip`.
4. Если Keep Settings было выключено, убедитесь, что `/cf/conf/sinkhole` отсутствует.

Если обновление было активно, маркер удаления просит его остановиться между ограниченными этапами до изменения постоянных данных. Удаление записывает первую ошибку очистки, продолжая выполнять остальные независимые этапы.
