Используйте **Firewall → Sinkhole → Services**, чтобы блокировать бренд целиком без выбора и сопровождения отдельного URL списка.

## Выбор контекста \{#choose-a-context}

Выберите **Global**, сеть или устройство в [ряду контекстов](/docs/configure/scopes#contexts) под основными вкладками; страница показывает только собственный выбор этого контекста. Найдите службу, отфильтруйте плитки с помощью метки группы, установите флажок каждой службы, затем выберите **Save** под плитками служб.

**All** перечисляет каждый контекст, который блокирует хотя бы одну службу, с названиями служб; выберите строку, чтобы изменить этот контекст.

Выбор компилируется на существующем уровне этого контекста. Разрешённые домены устройства по-прежнему имеют приоритет над правилами служб устройства, разрешённые домены сети — над правилами служб сети, а глобальные разрешённые домены — над глобальными правилами служб.

Сервисы, охваченные отдельной защитой Bypass, не отображаются в сетке, счётчиках групп или поиске. Private Relay настраивается только на вкладке Bypass.

## Реестр и исправление \{#registry-and-repair}

Sinkhole загружает реестр служб AdGuard Home, только когда открывается эта страница или выбирается **Refresh**. Последняя исправная копия хранится в `/var/db` один день, поэтому компиляция никогда не ждёт сеть.

Логотипы служб отображаются как изолированные изображения data URI. Если логотип отсутствует или слишком велик, используется стандартное изображение. Если сохранённая служба исчезает из нового реестра, Sinkhole сохраняет её идентификатор и показывает службу в разделе **Needs Repair**; снимите её флажок и сохраните настройки, чтобы удалить этот выбор.

На вкладке **Status** отображаются время загрузки реестра, последняя ошибка и число заблокированных служб, выбранных для Global и для каждой сети и каждого устройства.
