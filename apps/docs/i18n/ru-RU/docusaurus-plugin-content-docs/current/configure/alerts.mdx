Отправляйте уведомления только для заблокированных ответов, список и клиент которых соответствуют включённому правилу оповещения.

## Зачем использовать правила оповещения? \{#why-use-alert-rules}

1. Отслеживают выбранные списки и клиенты, чтобы обычные блокировки вне этой политики не создавали сообщений.
2. Используют существующие локальные и удалённые каналы уведомлений pfSense, поэтому Sinkhole не нужна отдельная служба доставки.
3. Подавляют повторы и обобщают всплески, чтобы часто запрашиваемый домен не переполнил WebGUI или почтовый ящик.
4. Ограничивают очередь событий и обрабатывают её вне запросов DNS, поэтому доставка никогда не задерживает ответ.

## Создание правила \{#create-a-rule}

Откройте **Firewall → Sinkhole → Alerts**, выберите **Add** под таблицей правил оповещения, затем заполните **Add Alert Rule** на странице редактора:

| Поле                 | Описание                                                                                       |
|----------------------|------------------------------------------------------------------------------------------------|
| Description          | Локальное имя правила, отображаемое в тексте уведомлений и сводках.                            |
| Any block list       | Соответствует блокировке из любого списка, а не только из выбранных.                           |
| Chosen block lists   | Списки, которые могут удовлетворить правилу, когда **Any** выключено.                          |
| Everyone             | Соответствует любому клиенту, а не только выбранным сетям и устройствам.                       |
| Chosen networks      | Сетевые области действия, которые могут удовлетворить правилу, когда **Everyone** выключено.   |
| Chosen devices       | Области действия устройств, которые могут удовлетворить правилу, когда **Everyone** выключено. |
| Repeat after         | Число минут до повторного уведомления для тех же правила, клиента, домена и списка.            |
| WebGUI notice        | Добавляет локальное уведомление Sinkhole в pfSense.                                            |
| Remote notifications | Использует удалённые службы, настроенные в pfSense.                                            |
| Enabled              | Разрешает заблокированным ответам соответствовать этому правилу.                               |

Поле выбранных списков скрыто, пока выбрано **Any block list**, а поля сетей и устройств скрыты, пока выбрано **Everyone**. После сохранения открывается Alerts; для редактирования выберите значок карандаша или дважды щёлкните строку.

Блокировка соответствует правилу, только если правило выбирает один из заблокировавших имя списков и того же клиента. Интервал повторения по умолчанию равен 60 минутам, допустимый диапазон — от 1 до 1 440 минут.

## Каналы доставки \{#delivery-channels}

- **WebGUI notice** использует локальный канал `file_notice()` pfSense и содержит ссылку на вкладку Alerts.
- **Remote notifications** использует настроенные в pfSense службы `notify_all_remote()`.

Sinkhole не создаёт собственных каналов электронной почты, чатов, webhook или других способов доставки. Удалённые службы настраиваются и проверяются в **System → Advanced → Notifications** в pfSense.

## Фиксированные пределы \{#fixed-limits}

| Предел                              | Поведение                                                                                            |
|-------------------------------------|------------------------------------------------------------------------------------------------------|
| 20 сообщений за минутный запуск     | Дополнительные блокировки объединяются в одну или несколько сводок правил в пределах того же лимита. |
| 60 сообщений на правило в час       | Шестидесятое место зарезервировано для часовой сводки переполнения.                                  |
| 50 непрочитанных уведомлений WebGUI | Дополнительные локальные уведомления ждут, пока часть уведомлений Sinkhole не будет прочитана.       |
| 40 секунд на обработку              | Незавершённые отправки остаются для следующего минутного задания, а не удерживают текущее.           |
| Возраст события 10 минут            | Более старые события в очереди отбрасываются как устаревшие.                                         |

Status подсчитывает прочитанные и устаревшие события, отправленные и отложенные уведомления, а также события, отброшенные модулем. Когда не остаётся включённых правил оповещения, Sinkhole удаляет файл событий и состояние повторов.

## Конфиденциальность и журналирование \{#privacy-and-logging}

Текст оповещения содержит заблокированное имя, клиента, сеть, список и правило. При блокировке CNAME также указывается цель CNAME, находящаяся в списке.

Функция локальных уведомлений pfSense записывает `New alert found: <message>` в системный журнал, поэтому домен и устройство также появляются в **Status → System Logs → System → General**. Рекомендуется считать и уведомления, и журналы записями политики просмотра.

## Проверка оповещения \{#verify-an-alert}

1. Убедитесь, что правило, выбранный список и выбранная область действия клиента включены.
2. В Status убедитесь, что клиент сейчас сопоставлен с нужной сетью или устройством.
3. Запросите имя, которое блокируется выбранным списком, и проверьте настроенный канал pfSense.
4. Если второе уведомление не поступило, сопоставьте попытку с интервалом повторения правила и фиксированными пределами.
