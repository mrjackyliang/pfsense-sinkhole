Определите каждую сеть и каждое устройство один раз на вкладке **Clients**, затем выберите на вкладке **Blocking**, что блокирует каждое из них. Каждый клиент получает политику, предназначенную для его текущего расположения.

## Зачем использовать сети и устройства? \{#why-use-networks-and-devices}

1. Предоставляют каждому интерфейсу pfSense или VLAN собственную политику, сохраняя правила Global для всех.
2. Позволяют принять более конкретное решение для одного устройства без отдельного DNS-сервера.
3. Позволяют разрешённым доменам исправлять ложные срабатывания на нужном уровне без удаления всего списка.
4. Хранят адреса клиентов отдельно от скомпилированных списков, поэтому изменения DHCP, соседей или интерфейсов не перезагружают Unbound.

## Контексты \{#contexts}

Вкладки Blocking, Services, SafeSearch, Alerts, Bypass и IP используют общий второй ряд вкладок под основными вкладками:

| Вкладка  | Что редактирует страница                                                                                                           |
|----------|------------------------------------------------------------------------------------------------------------------------------------|
| All      | Ничего. Таблица только для чтения перечисляет каждый контекст с собственными настройками; выберите строку, чтобы открыть контекст. |
| Global   | Настройки для всех клиентов.                                                                                                       |
| Networks | Одну сеть. Ряд чипов сетей определяет, какую именно.                                                                               |
| Devices  | Одно устройство. Ряд чипов устройств определяет, какое именно, а поле поиска сужает чипы по имени.                                 |

Баннер под рядом показывает, что вы редактируете, например **Editing: Network: IOT · applies to clients on IOT** или **Editing: Device: Tablet · this device only**. Каждый контекст показывает только собственные настройки; ничего унаследованного от более широкого контекста в его форме не отображается.

Выбранный контекст сохраняется при переходе между вкладками, пока вы не выберете другой. Отключённую сеть или отключённое устройство по-прежнему можно редактировать, а предупреждение сообщает, что их настройки не применяются ни к одному клиенту, пока они снова не будут включены.

## Определение сетей \{#define-networks}

Откройте **Firewall → Sinkhole → Clients**, затем выберите **Add** под таблицей Networks. По умолчанию редактор выбирает LAN или первый доступный интерфейс, не являющийся WAN, и не показывает интерфейсы, для которых уже создана сеть. Клиент принадлежит этой сети, если его адрес входит в одну из текущих подсетей IPv4 или IPv6 интерфейса.

В каждой строке сети есть интерфейс и флажок **Enabled**. После сохранения открывается Clients; для редактирования выберите карандаш или дважды щёлкните строку. Устройство, перемещающееся между сетями, получает политику сети, которой соответствует его текущий адрес.

## Определение устройств \{#define-devices}

Выберите **Add** под таблицей Devices, укажите имя и добавьте одну или несколько строк идентификаторов. В каждой строке есть тип и соответствующее ему значение:

| Тип идентификатора  | Адреса, используемые для устройства                                           |
|---------------------|-------------------------------------------------------------------------------|
| IP address          | Настроенный адрес IPv4 или IPv6.                                              |
| DHCP static mapping | Настроенный адрес и текущие адреса, обнаруженные для MAC этого сопоставления. |
| MAC address         | Текущие адреса из ARP, NDP и аренды DHCP для этого MAC.                       |

Управляйте строками с помощью **Add Identifier** и кнопок корзины. У устройства должен быть хотя бы один идентификатор. Каждый адрес, найденный через любой из его идентификаторов, относится к одному устройству и поэтому использует общий набор настроек и общее состояние включения. После сохранения открывается Clients; для редактирования выберите карандаш или дважды щёлкните строку. Фоновое задание обновляет текущие подсети и адреса устройств каждую минуту, когда для блокировки DNS включена сеть или устройство либо когда DNS-защите Bypass требуется определение клиентов. Sync пакета запускает то же обновление только при этом условии.

Удаление сети или устройства на вкладке Clients также удаляет их настройки Blocking, Services, SafeSearch, Bypass и IP.

## Выбор списков и разрешённых доменов \{#choose-lists-and-allowed-domains}

Откройте **Firewall → Sinkhole → Blocking** и выберите контекст:

- **Global** выбирает списки, которые применяются ко всем клиентам после решений устройства и сети, и содержит глобальные разрешённые домены.
- **Networks** выбирает дополнительные списки и разрешённые домены для клиентов выбранной сети.
- **Devices** выбирает дополнительные списки и разрешённые домены для выбранного устройства.

В каждом контексте есть поле **Lists** и поле **Allowed Domains** с одним доменом на строку. Выберите **Save**, чтобы применить этот контекст. Если списков много, перетащите нижний угол поля **Lists**, чтобы сделать его выше. Сами списки добавляются и редактируются на вкладке [Lists](/docs/configure/lists).

**All** показывает по одной строке для каждого контекста, у которого есть списки или разрешённые домены, с именами списков и количеством разрешённых доменов.

## Порядок принятия решений \{#decision-order}

Наиболее конкретный совпавший уровень принимает решение по каждому запросу в следующем точном порядке:

1. **Device allowed domains** — Немедленно разрешает запрос при совпадении имени.
2. **Device lists** — Немедленно блокирует запрос при совпадении выбранного списка устройства.
3. **Network allowed domains** — Немедленно разрешает запрос при совпадении сетевого исключения.
4. **Network lists** — Немедленно блокирует запрос при совпадении выбранного сетевого списка.
5. **Global allowed domains** — Немедленно разрешает запрос при совпадении глобального исключения.
6. **Global lists** — Блокирует запрос при совпадении глобального списка.

Если решение не принято ни на одном шаге, запрос проходит. Клиент, который не соответствует ни одной включённой сети или устройству, проходит только шаги Global. Разрешённые домены уровня переопределяют списки, унаследованные от менее конкретных уровней, но не переопределяют списки более конкретного уровня, который уже принял решение.

## Поведение разрешённых доменов \{#allowed-domain-behavior}

Каждая запись разрешённого домена применяется к самому домену и всем его поддоменам. Например, разрешение `service.example` также разрешает `api.service.example` на этом уровне.

- Исключение устройства может пропустить списки устройства, сети и глобальные списки, поскольку проверяется первым.
- Исключение сети может пропустить сетевые и глобальные списки, но не решение списка устройства.
- Глобальное исключение может пропустить только глобальные списки.

## Конфликты адресов \{#address-conflicts}

Несколько идентификаторов одного устройства могут приводить к одному адресу без конфликта. Если два разных устройства претендуют на один текущий адрес, побеждает первое устройство в таблице Clients. Таблица Clients и **Status → Clients** показывают адрес в поле **Conflict** для каждой затронутой строки, чтобы можно было исправить порядок или идентификаторы.

## Проверка сети или устройства \{#verify-a-network-or-device}

1. Выполните `/usr/local/sbin/sinkhole --refresh-clients` или дождитесь ежеминутного обновления.
2. Откройте **Status → Clients** и проверьте текущие подсети сети и текущие адреса устройства.
3. Запросите имя с клиента в этой сети или на этом устройстве и сопоставьте результат с приведённым выше порядком решений.
4. Перед использованием поведения для конкретного устройства проверьте отсутствие конфликта адресов.
