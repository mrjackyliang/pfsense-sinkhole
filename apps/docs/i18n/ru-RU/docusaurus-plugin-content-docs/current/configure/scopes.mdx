Назначайте списки и разрешённые домены на глобальном, сетевом и устройственном уровнях, чтобы каждый клиент получал политику для своего текущего расположения.

## Зачем использовать области действия? \{#why-use-scopes}

1. Предоставляют каждому интерфейсу pfSense или VLAN собственную политику, сохраняя глобальные правила для всех.
2. Позволяют принять более конкретное решение для одного устройства без отдельного DNS-сервера.
3. Позволяют разрешённым доменам исправлять ложные срабатывания на нужном уровне без удаления всего списка.
4. Хранят адреса клиентов отдельно от скомпилированных списков, поэтому изменения DHCP, соседей или интерфейсов не перезагружают Unbound.

## Глобальная область действия \{#global-scope}

Список с выбранным **Global** применяется ко всем клиентам после решений устройства и сети. Глобальные разрешённые домены вводятся на вкладке **Lists** и позволяют указанному домену и его поддоменам проходить через глобальные списки.

Клиент, который не соответствует ни одной включённой области сети или устройства, получает только этот уровень.

## Сетевые области действия \{#network-scopes}

Откройте **Firewall → Sinkhole → Scopes**, затем выберите **Add** под таблицей Networks. По умолчанию редактор выбирает LAN или первый доступный интерфейс, не являющийся WAN, и не показывает интерфейсы, для которых уже создана сетевая область. Клиент принадлежит этой сети, если его адрес входит в одну из текущих подсетей IPv4 или IPv6 интерфейса.

В каждой строке сети выбираются дополнительные списки, разрешённые домены и состояние включения области. После сохранения открывается Scopes; для редактирования выберите карандаш или дважды щёлкните строку. Устройство, перемещающееся между сетями, получает политику сети, которой соответствует его текущий адрес.

## Области действия устройств \{#device-scopes}

Выберите **Add** под таблицей Devices, укажите имя и выберите один способ идентификации. Редактор показывает только поле идентификатора, соответствующее выбранному способу:

| Способ              | Адреса, используемые для устройства                                           |
|---------------------|-------------------------------------------------------------------------------|
| IP address          | Настроенный адрес IPv4 или IPv6.                                              |
| DHCP static mapping | Настроенный адрес и текущие адреса, обнаруженные для MAC этого сопоставления. |
| MAC address         | Текущие адреса из ARP, NDP и аренды DHCP для этого MAC.                       |

В строке устройства выбираются его списки, разрешённые домены и состояние включения. После сохранения открывается Scopes; для редактирования выберите карандаш или дважды щёлкните строку. Фоновое задание обновляет текущие подсети и адреса устройств каждую минуту, когда для блокировки DNS включена область сети или устройства либо когда DNS-защите Bypass требуется определение клиентов. Sync пакета запускает то же обновление только при этом условии.

## Порядок принятия решений \{#decision-order}

Наиболее конкретный совпавший уровень принимает решение по каждому запросу в следующем точном порядке:

1. **Device allowed domains** — Немедленно разрешает запрос при совпадении имени.
2. **Device lists** — Немедленно блокирует запрос при совпадении выбранного списка устройства.
3. **Network allowed domains** — Немедленно разрешает запрос при совпадении сетевого исключения.
4. **Network lists** — Немедленно блокирует запрос при совпадении выбранного сетевого списка.
5. **Global allowed domains** — Немедленно разрешает запрос при совпадении глобального исключения.
6. **Global lists** — Блокирует запрос при совпадении глобального списка.

Если решение не принято ни на одном шаге, запрос проходит. Разрешённые домены уровня переопределяют списки, унаследованные от менее конкретных уровней, но не переопределяют списки более конкретного уровня, который уже принял решение.

## Поведение разрешённых доменов \{#allowed-domain-behavior}

Каждая запись разрешённого домена применяется к самому домену и всем его поддоменам. Например, разрешение `service.example` также разрешает `api.service.example` на этом уровне.

- Исключение устройства может пропустить списки устройства, сети и глобальные списки, поскольку проверяется первым.
- Исключение сети может пропустить сетевые и глобальные списки, но не решение списка устройства.
- Глобальное исключение может пропустить только глобальные списки.

## Конфликты адресов \{#address-conflicts}

Если две строки устройств претендуют на один текущий адрес, побеждает первое устройство в порядке таблицы. В **Status → Scopes** адрес отображается в поле **Conflict** для каждой затронутой строки, чтобы можно было исправить порядок или идентификаторы.

## Проверка области действия \{#verify-a-scope}

1. Выполните `/usr/local/sbin/sinkhole --refresh-clients` или дождитесь ежеминутного обновления.
2. Откройте **Status → Scopes** и проверьте текущие подсети сети и текущие адреса устройства.
3. Запросите имя с клиента в этой области и сопоставьте результат с приведённым выше порядком решений.
4. Перед использованием поведения для конкретного устройства проверьте отсутствие конфликта адресов.
