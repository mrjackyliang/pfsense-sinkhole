Настройте один доверенный список и проверьте его сохранённое, скомпилированное, развёрнутое и загруженное состояние, прежде чем расширять политику.

## Проверка Resolver \{#check-the-resolver}

1. Откройте **Services → DNS Resolver** и убедитесь, что Resolver включён.
2. Если включён pfBlockerNG DNSBL, выберите пакет, который будет управлять фильтрацией DNS, поскольку оба пакета не могут одновременно использовать место Python в Unbound.
3. Откройте **Firewall → Sinkhole → General** и не включайте **Enable**, пока готовится первая политика.

Sinkhole отказывается сохранять **Enable**, пока место занято другим сценарием Python. Если позднее отключить Sinkhole, предыдущие настройки Python в Resolver восстанавливаются при условии, что они всё ещё принадлежат Sinkhole.

## Добавление списка \{#add-a-list}

1. Откройте **Lists** и добавьте URL доверенного источника или откройте **Add from Catalog**, чтобы выполнить поиск в двух каталогах, загружаемых по запросу.
2. Задайте источнику локальное имя и оставьте **Enabled** выбранным, чтобы Sinkhole загрузил его.
3. Оставьте **Global** выбранным, только если список должен применяться после всех правил устройств и сетей.
4. Добавьте глобальные **Allowed Domains**, по одному домену в строке, если требуется пропустить известное ложное срабатывание.

Sinkhole не рекомендует источники. Раздел [Списки и сохранённые копии](/docs/configure/lists) описывает поддерживаемые форматы и преобразование результатов каталога в обычные строки списка.

## Добавление необязательных областей действия \{#add-optional-scopes}

Откройте **Scopes**, если сети или устройству требуется политика сверх глобального уровня:

- Добавьте **Network** для одного настроенного интерфейса pfSense, затем выберите его списки и разрешённые домены.
- Добавьте **Device** по IP-адресу, статическому сопоставлению DHCP или MAC-адресу, затем выберите его списки и разрешённые домены.

Устройство наследует сеть, в которой оно сейчас находится, а сеть наследует глобальные списки. Раздел [Области действия и разрешённые домены](/docs/configure/scopes) показывает порядок принятия решений, определяющий, будет имя разрешено или заблокировано.

## Включение и обновление \{#enable-and-update}

1. Вернитесь на **General** и выберите **Enable**.
2. Выберите **Update Frequency** для включённых списков DNS и сохраните настройки.
3. Откройте **Status** и выберите **Update Now**.
4. Дождитесь, пока **Update running** снова примет значение `No`.

Переключатель General включает запланированные обновления списков DNS и интеграцию с DNS Resolver. Включённые Bypass Lists и политики IP/стран независимо используют одно расписание обновлений; вся защита Bypass и IP остаётся выключенной, пока администратор её не включит.

## Проверка активного состояния \{#verify-the-active-state}

Первое обновление готово, когда на панелях Status отображаются все следующие результаты:

- В **Lists** для каждого рабочего источника показаны ненулевое число записей и **Last Successful Update**.
- **Compile Needed** и **Deployment Needed** имеют значение `No` в разделе **Summary**.
- **Compiled Generation**, **Deployed Generation** и **Loaded Generation** указывают текущее поколение.
- **DNS Resolver Python Script Owner** имеет значение `sinkhole`.
- **Sinkhole** имеет значение `Active` без указания причины.

Если страница сообщает причину неактивного состояния или ожидающее поколение, раздел [Status](/docs/operate/status) поясняет состояние, а [Устранение неполадок](/docs/operate/troubleshooting) разбирает каждую вероятную причину.

## Осторожное добавление оповещений и защиты Bypass \{#add-alerts-and-bypass-protection-carefully}

Рекомендуется проверить ответы DNS для каждой области действия до добавления правила оповещения или защиты Bypass. Оповещения могут раскрывать активность клиентов, а настройки Bypass могут перенаправлять или блокировать трафик, поступающий на выбранных интерфейсах.

- [Оповещения](/docs/configure/alerts) ограничивают доставку по списку, клиенту, интервалу повторения и фиксированным пределам.
- [Защита от обхода](/docs/configure/bypass-protection) описывает перенаправление обычного DNS, сигналы шифрованного DNS, списки провайдеров и защиту от туннелей.
- [Блокировка IP-адресов и стран](/docs/configure/ip-and-country-blocking) описывает независимый пакетный фильтр, по умолчанию выключенный.
