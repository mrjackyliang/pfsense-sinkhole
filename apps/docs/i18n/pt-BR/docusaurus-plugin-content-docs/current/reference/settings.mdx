Consulte a finalidade e o comportamento padrão de cada área de configuração do Sinkhole em **Firewall → Sinkhole**.

## General \{#general}

| Campo            | Padrão | Descrição                                                                                                 |
|------------------|--------|-----------------------------------------------------------------------------------------------------------|
| Enable           | Off    | Habilita as atualizações agendadas das listas e a integração do Sinkhole com o DNS Resolver.              |
| Update Frequency | Daily  | Seleciona Hourly, Every 6 hours, Daily ou Weekly para o agendamento de listas DNS, Bypass e de IP/países. |
| Keep Settings    | On     | Preserva a configuração e os dados salvos duráveis quando o pacote é removido.                            |

Os horários agendados usam componentes aleatórios estáveis. Hourly é executado em um minuto estável, Every 6 hours usa o mesmo minuto a cada seis horas, Daily é executado às `00:<minute>` e Weekly é executado no domingo às `00:<minute>`.

## Resolver \{#resolver}

| Campo                   | Padrão | Descrição                                                                                                      |
|-------------------------|--------|----------------------------------------------------------------------------------------------------------------|
| Rebind Exceptions       | Empty  | Domínios autorizados a responder com endereços privados apesar da proteção contra DNS rebinding, um por linha. |
| Expired Answer Lifetime | Empty  | Segundos durante os quais uma resposta expirada do cache ainda pode ser servida; `0` significa sem limite.     |
| Expired Answer Wait     | Empty  | Milissegundos de espera por uma resposta nova antes de servir uma expirada; `0` responde na hora.              |

Rebind Exceptions aceita no máximo 100 domínios. Expired Answer Lifetime aceita segundos inteiros de `0` a `31536000`, e Expired Answer Wait aceita milissegundos inteiros de `0` a `60000`.

Um campo vazio não grava nada e mantém o padrão do Resolver. [Configurações do Resolver](/docs/configure/resolver-settings) explica quando os valores se aplicam.

## Package Updates \{#package-updates}

| Campo                | Padrão | Descrição                                                                              |
|----------------------|--------|----------------------------------------------------------------------------------------|
| Update Checks        | Weekly | Seleciona verificações Daily, Weekly, Monthly ou Never para novas versões no GitHub.   |
| Remote Notifications | Off    | Também envia cada aviso de nova versão pelos serviços remotos configurados no pfSense. |

Cada nova versão encontrada por uma verificação agendada cria um aviso local no pfSense. **About → Check Now** executa a mesma verificação limitada de versão sem alterar o agendamento, não cria nenhum aviso e impede que uma verificação agendada posterior anuncie essa versão.

## Lists \{#lists}

| Campo   | Padrão | Descrição                                                              |
|---------|--------|------------------------------------------------------------------------|
| Name    | Empty  | Rótulo local usado por Blocking, alertas e Status.                     |
| URL     | Empty  | Origem HTTP ou HTTPS sem credenciais incorporadas.                     |
| Enabled | On     | Inclui a origem nas atualizações e na política compilada quando usada. |

**Add from Catalog** pesquisa sob demanda o registro de listas do AdGuard Home e o catálogo de feeds do pfBlockerNG. Adicionar um resultado cria a mesma linha comum que a inserção manual da URL.

Os feeds de bypass são excluídos deste catálogo.

Lists alterna entre os tipos **DNS**, **Bypass** e **IP**. A tabela acima é o tipo DNS; as [Bypass Lists](#bypass-lists) e as [linhas de listas de IP](#ip-and-country-blocking) também são gerenciadas ali, e a tabela de cada tipo tem uma contagem **Used By** de Global mais cada rede e cada dispositivo que seleciona a lista.

## Blocking \{#blocking}

Cada contexto (Global, uma rede ou um dispositivo) tem seus próprios dois campos:

| Campo           | Padrão | Descrição                                                                                                                                          |
|-----------------|--------|----------------------------------------------------------------------------------------------------------------------------------------------------|
| Lists           | Empty  | Listas de DNS que bloqueiam nesse contexto. As listas Global se aplicam a todos os clientes após as decisões de dispositivos e redes.              |
| Allowed Domains | Empty  | Uma exceção por linha; cada uma permite o domínio exato e todos os seus subdomínios antes das listas desse contexto e de cada contexto mais amplo. |

## Serviços \{#services}

As seleções de serviços ficam vazias por padrão em cada contexto. Um serviço do registro coberto por uma proteção de Bypass dedicada fica oculto em Serviços e é removido das seleções salvas; Private Relay é configurado somente na guia Bypass.

## SafeSearch \{#safesearch}

As seleções de SafeSearch ficam vazias por padrão em cada contexto. Cada contexto pode travar Google, YouTube (Moderate ou Strict), Bing, DuckDuckGo, Brave Search, Startpage, Ecosia, Yandex e Pixabay, ou bloquear o Qwant. [SafeSearch](/docs/configure/safesearch) lista os nomes e os hosts seguros.

## Networks \{#networks}

| Campo     | Padrão | Descrição                                                                                                                                                   |
|-----------|--------|-------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Interface | LAN    | Interface configurada no pfSense cujas sub-redes IPv4 e IPv6 atuais identificam a rede. Sem LAN, a primeira interface livre que não seja WAN é selecionada. |
| Enabled   | On     | Inclui a linha na correspondência de clientes e na política compilada.                                                                                      |

Cada interface pode aparecer apenas uma vez. Uma interface salva que não esteja disponível continua visível para correção, em vez de ser descartada.

## Devices \{#devices}

| Campo               | Padrão                  | Descrição                                                                                                                |
|---------------------|-------------------------|--------------------------------------------------------------------------------------------------------------------------|
| Name                | Empty                   | Rótulo local exibido na política e em Status.                                                                            |
| Identifiers → Type  | Uma linha de IP address | Seleciona IP address, DHCP static mapping ou MAC address em cada linha que pode ser adicionada ou removida.              |
| Identifiers → Value | Empty                   | Endereço IP ou MAC exato, ou um mapeamento estático DHCP existente. Pelo menos uma linha de identificador é obrigatória. |
| Enabled             | On                      | Inclui a linha na correspondência de clientes e na política compilada.                                                   |

Todas as linhas de identificador pertencem ao mesmo dispositivo e compartilham suas configurações. Os mapeamentos estáticos usam o endereço configurado e os endereços atuais observados para o MAC do mapeamento. Uma linha de MAC usa dados atuais de ARP, NDP e concessões DHCP. Endereços alcançados por vários identificadores do mesmo dispositivo não são conflitos.

## Alert Rules \{#alert-rules}

| Campo                | Padrão   | Descrição                                                                                                 |
|----------------------|----------|-----------------------------------------------------------------------------------------------------------|
| Description          | Empty    | Rótulo local da regra.                                                                                    |
| Lists                | Any      | Corresponde a qualquer lista ou apenas às listas configuradas selecionadas.                               |
| Clients              | Everyone | Corresponde a todos ou às redes e aos dispositivos selecionados.                                          |
| Repeat After         | 60       | Minutos antes que a mesma regra, cliente, domínio e lista possam notificar novamente; aceita de 1 a 1440. |
| WebGUI Notice        | On       | Adiciona um aviso do pfSense quando a regra corresponde.                                                  |
| Remote Notifications | On       | Usa os serviços de notificação configurados no pfSense quando a regra corresponde.                        |
| Enabled              | On       | Inclui a regra na política compilada de alertas.                                                          |

O processador por minuto envia no máximo 20 mensagens por execução e 60 mensagens por regra por hora, depois resume o excedente. Ele mantém no máximo 50 avisos não lidos do Sinkhole na WebGUI e usa um limite de execução de 40 segundos; eventos com mais de 10 minutos são considerados obsoletos.

## Proteção Bypass \{#bypass-protection}

| Campo                                  | Padrão | Descrição                                                                                                                 |
|----------------------------------------|--------|---------------------------------------------------------------------------------------------------------------------------|
| Apply to                               | Empty  | Interfaces de chegada voltadas aos clientes compartilhadas por todas as proteções Bypass.                                 |
| Redirect                               | Off    | Envia ao firewall o tráfego DNS comum das portas UDP e TCP 53 nas interfaces selecionadas.                                |
| Exempt Sources                         | Empty  | Um endereço IPv4 ou IPv6, rede CIDR ou alias de host/rede existente por linha que ignora o redirecionamento de DNS comum. |
| Exempt Destinations                    | Empty  | Um endereço IP de destino, CIDR ou alias por linha que ignora o redirecionamento de DNS comum.                            |
| Bypass Lists                           | Empty  | Bypass Lists ativadas que este contexto usa; as próprias fontes são gerenciadas em Lists.                                 |
| TLS and QUIC                           | Off    | Bloqueia as portas TCP e UDP 853 para destinos que não sejam o firewall.                                                  |
| Providers                              | Off    | Bloqueia nomes e endereços das Bypass Lists **Encrypted DNS** selecionadas.                                               |
| Firefox                                | Off    | Retorna `NXDOMAIN` para o nome canário de DNS-over-HTTPS automático do Firefox e seus subdomínios.                        |
| Private Relay                          | Off    | Retorna `NXDOMAIN` para os dois nomes de disponibilidade do Private Relay da Apple.                                       |
| Discovery                              | Off    | Mantém DDR inalterado, anuncia o DNS over TLS do firewall ou responde `NOERROR` sem registros.                            |
| Tor                                    | Off    | Bloqueia nomes e endereços das Bypass Lists **Tor** selecionadas.                                                         |
| VPN (Block listed VPN providers)       | Off    | Bloqueia nomes e endereços das Bypass Lists **VPN** selecionadas.                                                         |
| VPN (Block standard VPN ports)         | Off    | Bloqueia portas UDP de OpenVPN, WireGuard e IPsec e ESP para destinos que não sejam o firewall.                           |
| Block Exemptions → Exempt Sources      | Empty  | Um endereço IP, CIDR ou alias por linha cujo tráfego escapa de todos os bloqueios de firewall do Bypass.                  |
| Block Exemptions → Exempt Destinations | Empty  | Um endereço IP de destino, CIDR ou alias por linha que nenhum bloqueio de firewall do Bypass impede.                      |

Todas as exceções de redirecionamento salvas precisam ser válidas antes que qualquer regra de redirecionamento seja usada. O IPv4 usa `127.0.0.1` como destino somente quando o Resolver está escutando nesse endereço; caso contrário, usa o endereço da interface. O IPv6 sempre usa o endereço da interface. **Discovery → Advertise** exige o serviço SSL/TLS do DNS Resolver e o nome de host do certificado.

As exceções de bloqueio não adicionam nenhuma regra pass, então o tráfego isento continua passando pelas suas próprias regras de firewall. Cada lista aceita no máximo 16 aliases. Uma exceção de bloqueio salva inválida mantém todos os bloqueios de firewall do Bypass sem exceções até ser corrigida ou removida.

### Bypass Lists \{#bypass-lists}

As linhas das Bypass Lists são gerenciadas em **Lists → Bypass**.

| Campo   | Padrão        | Descrição                                                                          |
|---------|---------------|------------------------------------------------------------------------------------|
| Name    | Empty         | Rótulo local exibido em Lists, Bypass e Status.                                    |
| Kind    | Encrypted DNS | Seleciona a política **Encrypted DNS**, **Tor** ou **VPN**.                        |
| URL     | Empty         | Fonte HTTP ou HTTPS contendo uma combinação de domínios, endereços e CIDRs.        |
| Enabled | Off           | Inclui a lista salva nas buscas agendadas e na proteção habilitada correspondente. |

A entrada de uma Bypass List usa uma entrada por linha e comentários com `#`. Uma busca malsucedida mantém a última cópia válida salva. As decisões de domínios permitidos das listas têm prioridade sobre nomes das Bypass Lists, mas não sobre os sinais do Firefox, Private Relay ou Discovery.

**Add from Catalog** pesquisa feeds de bypass no registro do AdGuard Home e nas seções DNS, IPv4 e IPv6 do pfBlockerNG somente quando é aberto ou atualizado. Cada resultado tem um tipo fixo **Encrypted DNS**, **Tor** ou **VPN** e é adicionado como uma Bypass List habilitada.

## IP and Country Blocking \{#ip-and-country-blocking}

| Campo               | Padrão | Descrição                                                                                                                |
|---------------------|--------|--------------------------------------------------------------------------------------------------------------------------|
| Enable              | Off    | Habilita a âncora de firewall `sinkhole/ip`, carregada de forma independente.                                            |
| Interfaces          | Empty  | Interfaces de entrada nas quais as regras de bloqueio se aplicam.                                                        |
| Directions          | Empty  | Seleciona o bloqueio de origem de entrada, o bloqueio de destino de saída ou ambos.                                      |
| Countries           | Empty  | Um código de país de duas letras do GeoLite2 por linha.                                                                  |
| MaxMind Account ID  | Empty  | Conta usada para obter o arquivo GeoLite2 Country.                                                                       |
| MaxMind License Key | Unset  | Chave somente para gravação fornecida pelo administrador; deixá-la em branco preserva o valor armazenado.                |
| Clear License Key   | Off    | Exclui a chave MaxMind armazenada quando a configuração é salva.                                                         |
| IP Allowlist        | Empty  | Um endereço IPv4 ou IPv6, rede CIDR ou alias de host/rede existente por linha, subtraído das tabelas finais de bloqueio. |

Cada linha de lista de IP tem nome, URL, seleção de família IPv4/IPv6/Both e opção Enabled, e é gerenciada em **Lists → IP**. O campo **IP Lists** de cada contexto escolhe as listas de IP ativadas que ele usa. O Sinkhole também remove das tabelas finais os endereços das interfaces do firewall, dos gateways e de DNS, para que suas próprias regras não bloqueiem a infraestrutura protegida.

O catálogo de IP exclui todos os feeds de Encrypted DNS, Tor e VPN que pertencem ao catálogo Bypass.

## Language \{#language}

A WebGUI do Sinkhole segue a configuração de idioma do pfSense e possui catálogos completos para todas as 18 localidades compatíveis. Se uma chave de catálogo estiver inesperadamente ausente, o Sinkhole usará o inglês para essa chave.
