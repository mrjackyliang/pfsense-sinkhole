Defina cada rede e cada dispositivo uma vez em **Clients** e depois escolha em **Blocking** o que cada um bloqueia. Cada cliente recebe a política destinada à sua localização atual.

## Por que usar redes e dispositivos? \{#why-use-networks-and-devices}

1. Dá a cada interface ou VLAN do pfSense sua própria política, mantendo as regras Global para todos.
2. Dá a um dispositivo uma decisão mais específica sem exigir um servidor DNS separado.
3. Permite que domínios permitidos corrijam falsos positivos no nível em que importam, sem remover uma lista inteira.
4. Mantém os endereços dos clientes separados das listas compiladas, para que mudanças de DHCP, vizinho ou interface não recarreguem o Unbound.

## Contextos \{#contexts}

Blocking, Services, SafeSearch, Alerts, Bypass e IP compartilham uma segunda linha de abas abaixo das abas principais:

| Aba      | O que a página edita                                                                                                           |
|----------|--------------------------------------------------------------------------------------------------------------------------------|
| All      | Nada. Uma tabela somente leitura lista cada contexto com configurações próprias; selecione uma linha para abrir esse contexto. |
| Global   | As configurações para todos os clientes.                                                                                       |
| Networks | Uma rede. Uma linha de chips de rede escolhe qual.                                                                             |
| Devices  | Um dispositivo. Uma linha de chips de dispositivo escolhe qual, e a caixa de pesquisa filtra os chips pelo nome.               |

Um banner abaixo da linha indica o que você está editando, como **Editing: Network: IOT · applies to clients on IOT** ou **Editing: Device: Tablet · this device only**. Cada contexto mostra apenas as próprias configurações; nada herdado de um contexto mais amplo aparece no formulário.

O contexto selecionado acompanha você de aba em aba até que você escolha outro. Uma rede ou um dispositivo desativado ainda pode ser editado, e um aviso informa que suas configurações não se aplicam a nenhum cliente até que seja ativado novamente.

## Defina redes \{#define-networks}

Abra **Firewall → Sinkhole → Clients** e selecione **Add** abaixo da tabela Networks. O editor usa LAN por padrão, ou a primeira interface disponível que não seja WAN, e omite interfaces que já tenham uma rede. Um cliente pertence a essa rede quando seu endereço está dentro de uma das sub-redes IPv4 ou IPv6 atuais da interface.

Cada linha de rede tem uma interface e uma caixa de seleção **Enabled**. Ao salvar, você volta para Clients; selecione o lápis ou clique duas vezes em uma linha para editá-la. Um dispositivo que muda de rede recebe a política da rede correspondente ao seu endereço atual.

## Defina dispositivos \{#define-devices}

Selecione **Add** abaixo da tabela Devices, informe um nome e adicione uma ou mais linhas de identificador. Cada linha tem um tipo e o valor correspondente a esse tipo:

| Tipo de identificador | Endereços usados para o dispositivo                                               |
|-----------------------|-----------------------------------------------------------------------------------|
| IP address            | O endereço IPv4 ou IPv6 configurado.                                              |
| DHCP static mapping   | O endereço configurado e os endereços atuais observados para o MAC do mapeamento. |
| MAC address           | Os endereços atuais de ARP, NDP e concessões DHCP desse MAC.                      |

Use **Add Identifier** e os botões de lixeira para manter as linhas. Um dispositivo precisa de pelo menos um identificador. Todo endereço alcançado por qualquer um de seus identificadores pertence ao mesmo dispositivo e, portanto, compartilha um único conjunto de configurações e um único estado de ativação. Ao salvar, você volta para Clients; selecione o lápis ou clique duas vezes em uma linha para editá-la. Um processo em segundo plano atualiza as sub-redes e os endereços atuais dos dispositivos a cada minuto quando o bloqueio de DNS tem uma rede ou um dispositivo ativado, ou quando a proteção DNS do Bypass precisa identificar clientes. O Sync do pacote inicia a mesma atualização apenas nessa condição.

Excluir uma rede ou um dispositivo em Clients também exclui suas configurações de Blocking, Services, SafeSearch, Bypass e IP.

## Escolha listas e domínios permitidos \{#choose-lists-and-allowed-domains}

Abra **Firewall → Sinkhole → Blocking** e escolha um contexto:

- **Global** seleciona as listas que se aplicam a todos os clientes depois das decisões de dispositivo e rede e guarda os domínios permitidos globais.
- **Networks** seleciona as listas adicionais e os domínios permitidos para os clientes da rede escolhida.
- **Devices** seleciona as listas adicionais e os domínios permitidos para o dispositivo escolhido.

Cada contexto tem uma caixa **Lists** e uma caixa **Allowed Domains** com um domínio por linha. Selecione **Save** para aplicar esse contexto. Arraste o canto inferior da caixa **Lists** para deixá-la mais alta quando você tiver muitas listas. As listas em si são adicionadas e editadas na aba [Lists](/docs/configure/lists).

**All** mostra uma linha por contexto que tenha listas ou domínios permitidos, com os nomes das listas e a contagem de domínios permitidos.

## Ordem de decisão \{#decision-order}

O nível correspondente mais específico decide cada consulta nesta ordem exata:

1. **Domínios permitidos do dispositivo** — Permite imediatamente quando o nome consultado corresponde.
2. **Listas do dispositivo** — Bloqueia imediatamente quando uma lista selecionada do dispositivo corresponde.
3. **Domínios permitidos da rede** — Permite imediatamente quando a exceção da rede corresponde.
4. **Listas da rede** — Bloqueia imediatamente quando uma lista selecionada da rede corresponde.
5. **Domínios permitidos globais** — Permite imediatamente quando a exceção global corresponde.
6. **Listas globais** — Bloqueia quando uma lista global corresponde.

A consulta é permitida quando nenhuma etapa decide. Um cliente que não corresponda a nenhuma rede ou dispositivo ativado recebe somente as etapas Global. Os domínios permitidos de um nível substituem listas herdadas de níveis menos específicos, mas não substituem listas de um nível mais específico que já tenha decidido.

## Comportamento dos domínios permitidos \{#allowed-domain-behavior}

Cada entrada de domínio permitido se aplica ao domínio exato e a todos os seus subdomínios. Por exemplo, permitir `service.example` também permite `api.service.example` nesse nível.

- Uma exceção de dispositivo pode superar listas de dispositivo, rede e globais porque é verificada primeiro.
- Uma exceção de rede pode superar listas de rede e globais, mas não uma decisão de lista de dispositivo.
- Uma exceção global pode superar somente listas globais.

## Conflitos de endereço \{#address-conflicts}

Vários identificadores do mesmo dispositivo podem alcançar o mesmo endereço sem criar conflito. Quando dois dispositivos diferentes reivindicam o mesmo endereço atual, o primeiro dispositivo da tabela Clients vence. A tabela Clients e **Status → Clients** mostram o endereço em **Conflict** para cada linha afetada, para que a ordem ou os identificadores possam ser corrigidos.

## Verifique uma rede ou um dispositivo \{#verify-a-network-or-device}

1. Execute `/usr/local/sbin/sinkhole --refresh-clients` ou aguarde a atualização por minuto.
2. Abra **Status → Clients** e confirme as sub-redes atuais da rede e os endereços atuais do dispositivo.
3. Consulte um nome a partir de um cliente nessa rede ou nesse dispositivo e compare o resultado com a ordem de decisão acima.
4. Verifique se existe algum conflito de endereço antes de depender do comportamento específico do dispositivo.
