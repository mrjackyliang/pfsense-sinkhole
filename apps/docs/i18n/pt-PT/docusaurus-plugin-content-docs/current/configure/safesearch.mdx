Use **Firewall → Sinkhole → SafeSearch** para manter os motores de pesquisa no modo seguro numa rede ou num dispositivo, sem alterar nenhuma definição do navegador ou do dispositivo.

## Porquê usar o SafeSearch? \{#why-use-safesearch}

1. Bloqueia o modo seguro na rede, para que um navegador sem sessão iniciada, um dispositivo novo ou uma janela privada continuem a receber resultados filtrados.
2. Abrange todos os domínios de país do Google, não apenas `google.com`, pelo que mudar para `google.co.uk` não contorna o bloqueio.
3. Segue os mesmos âmbitos das listas de bloqueio, para que uma VLAN das crianças tenha SafeSearch enquanto o resto da rede não tem.

## Escolha um âmbito e os motores \{#choose-a-scope-and-engines}

1. Selecione **Global**, uma rede configurada ou um dispositivo configurado em **Scope**.
2. Assinale cada motor a bloquear e escolha **Moderate** ou **Strict** para o YouTube.
3. Selecione **Save**.

Uma rede ou um dispositivo tem de existir em **Scopes** antes de aparecer aqui. Guardar consulta de imediato cada anfitrião seguro e aplica a alteração em segundo plano.

## Como os âmbitos se combinam \{#how-scopes-combine}

Um cliente recebe, combinados, todos os motores escolhidos para **Global**, para a rede em que se encontra e para o próprio dispositivo. Quando o YouTube aparece com os dois níveis, prevalece **Strict**.

O SafeSearch é aplicado depois do bloqueio. Um nome que uma lista ou um serviço bloqueado bloqueia para o cliente continua bloqueado, e os domínios permitidos não desativam o SafeSearch. Tal como qualquer cliente sem âmbito, as consultas da própria firewall recebem os motores escolhidos para **Global**.

## Como funciona a resposta \{#how-the-answer-works}

Para um motor escolhido, o Sinkhole responde ao nome do motor com um CNAME para o anfitrião seguro e os endereços desse anfitrião, a mesma resposta que uma view do Unbound escrita à mão daria. Outros tipos de registo, como registos HTTPS, recebem apenas o CNAME, para que o navegador não possa usar indicações que contornem o anfitrião seguro.

O Sinkhole consulta os endereços de cada anfitrião seguro ao guardar e em cada atualização de listas, e mantém os últimos endereços válidos quando uma consulta falha. Um motor cujo anfitrião seguro nunca devolveu um endereço fica bloqueado nos respetivos âmbitos até uma consulta ter êxito.

As respostas de SafeSearch nunca ficam guardadas na cache do Resolver, pelo que a resposta de um cliente nunca chega a um cliente fora do âmbito.

## Verifique o SafeSearch \{#verify-safesearch}

1. Abra **Status** e confirme que o painel **SafeSearch** lista cada anfitrião seguro com endereços e sem erro.
2. Num cliente dentro do âmbito, consulte um nome de motor, como `nslookup www.google.com`, e confirme que a resposta indica o anfitrião seguro.
3. Num cliente fora do âmbito, confirme que a mesma consulta devolve a resposta normal do motor.

O DNS encriptado que um cliente envia para outro destino ignora todas as políticas de DNS, incluindo o SafeSearch. A [Proteção contra evasão](/docs/configure/bypass-protection) mantém as interfaces selecionadas no caminho de DNS do Sinkhole.
