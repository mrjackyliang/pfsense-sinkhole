直接在 pfSense 內，為整個網路、一個 VLAN 或一台設備分別封鎖不需要的網站。

## Sinkhole 的作用 \{#what-sinkhole-does}

Sinkhole for pfSense 讓家長和雇主可以控制哪些<Terminology title="要封鎖的名稱或地址，來自您新增的 URL" to="/docs/reference/terminology#lists-and-scopes">封鎖清單</Terminology>應用於網路的各個部分。它在防火牆上保留最後一份有效副本，因此重啓或重新載入後，DNS 可以立即回應，同時在後台下載較新的副本。

被封鎖的名稱會返回 `0.0.0.0` 或 `::`。如果 CNAME 鏈到達被封鎖的名稱，該查詢也會被封鎖；而在決定層級明確允許的名稱仍會被允許。

## 為什麼使用 Sinkhole？ \{#why-use-sinkhole}

1. 在全局、網路和設備<Terminology title="清單作用於誰：整個網路、某個 VLAN 或單個設備" to="/docs/reference/terminology#lists-and-scopes">作用域</Terminology>應用策略，讓兒童、訪客、員工和單台設備可以使用不同的清單。
2. 使用<Terminology title="最後一份有效副本，DNS 從不等待下載" to="/docs/reference/terminology#lists-and-scopes">已儲存清單</Terminology>，因此 DNS 不必等待下載，更新失敗後也不會失去可用清單。
3. 僅針對您選擇的清單和用戶端，通過 pfSense 自帶的通知系統發送<Terminology title="所選清單封鎖所選用戶端時發出通知" to="/docs/reference/terminology#alerts">警報規則</Terminology>通知。
4. 為普通 DNS、加密 DNS 探索和供應商、Tor 中繼以及 VPN 供應商或端口提供可選的<Terminology title="防止設備用自己的 DNS 繞過 Sinkhole" to="/docs/reference/terminology#bypass-protection">防止繞過</Terminology>。
5. 當 DNS 過濾不足時提供獨立的 IP 和國家/地區封鎖功能，而且不需要第二台主機或雲服務。
6. 為您選擇的作用域將搜尋引擎鎖定在 <Terminology title="搜尋引擎的安全模式，對作用域內每台設備強制啟用" to="/docs/reference/terminology#lists-and-scopes">SafeSearch</Terminology> 模式，讓過濾結果不依賴每台設備本身的設定。

## DNS 集成的工作方式 \{#how-dns-integration-works}

Sinkhole 作為 Python 模塊執行在 pfSense 基於 Unbound 的<Terminology title="pfSense 內建的 Unbound DNS，Sinkhole 在其中執行" to="/docs/reference/terminology#dns-basics">DNS Resolver</Terminology>中。Unbound 啓動時，該模塊只載入本地編譯檔案，並監視較新的本地代次，不會讓 DNS 查詢等待。

DNS Resolver 只提供一個 Python 腳本槽位。只有當該槽位為空或已經屬於 Sinkhole 時，Sinkhole 才會使用它；它拒絕替換其他所有者，例如 pfBlockerNG 的 DNSBL 模塊。

:::warning

Sinkhole 和 pfBlockerNG 無法同時過濾 DNS。只要 pfBlockerNG 已安裝並啓用，即使其 DNSBL 以 Unbound 模式執行、不使用 Python 槽位，Sinkhole 也會保持非活動狀態。

:::

## 仍由您控制的內容 \{#what-stays-under-your-control}

- **Lists** — 通過 URL 新增您信任的來源，或使用中立的<Terminology title="無需四處找 URL，即可找到知名封鎖清單" to="/docs/reference/terminology#lists-and-scopes">常用清單搜索</Terminology>查找來源。Sinkhole 不發佈也不推薦任何清單。
- **Scopes** — 選擇全局清單、某個 pfSense 介面或 VLAN 的清單，以及通過 IP 地址、DHCP 靜態映射或 MAC 地址識別的設備清單。
- **Allowed Domains** — 在全局、網路或設備層級允許某個域名及其子域名，而無需放棄整份清單。
- **SafeSearch** — 為每個作用域選擇哪些搜尋引擎鎖定在安全模式，以及 YouTube 使用 Moderate 還是 Strict。
- **Alerts** — 選擇哪些清單和用戶端組合創建本地 WebGUI 通知，或使用 pfSense 已配置的遠程通知服務。
- **Bypass** — 保持所有控制關閉，或選擇用戶端介面並明確啟用普通 DNS 重定向、加密 DNS 訊號、供應商列表或隧道保護。
- **IP blocking** — 保持關閉，或選擇 IP 清單、國家/地區、介面、方向和允許的地址。

## 限制 \{#limits}

DNS 封鎖並不是完整的流量控制。防止繞過只有在啟用各項控制後才涵蓋常見的替代路徑，並且無法識別所有加密或自訂隧道。

封鎖事件和通知會透露用戶端嘗試訪問的內容。除了您選擇通過 pfSense 發送的通知外，這些信息都保留在防火牆上。

## 語言 \{#languages}

WebGUI 遵循 pfSense 中選擇的語言，並提供英語和 pfSense 的其他 17 個區域設定。

文檔站點提供英語和 pfSense 的其他 17 個區域設定。翻譯頁面保留英語錨點，因此每種語言的連結都會到達相同章節。
