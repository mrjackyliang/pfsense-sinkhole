在全局、網路和設備層級分配清單和允許的域名，讓每個用戶端獲得適合其當前位置的策略。

## 為什麼使用作用域？ \{#why-use-scopes}

1. 為每個 pfSense 介面或 VLAN 提供自己的策略，同時為所有人保留全局規則。
2. 為一台設備提供更具體的決定，而不需要單獨的 DNS 伺服器。
3. 允許域名可以在誤報相關的層級糾正誤報，無需放棄整份清單。
4. 將用戶端地址與編譯清單分開，因此 DHCP、鄰居或介面變化不會重新載入 Unbound。

## 全局作用域 \{#global-scope}

選中 **Global** 的清單會在設備和網路決定之後應用於每個用戶端。全局允許域名在 **Lists** 選項卡中輸入，並允許指定域名及其子域名通過全局清單。

未匹配任何已啓用網路或設備作用域的用戶端只會獲得此層級。

## 網路作用域 \{#network-scopes}

打開 **Firewall → Sinkhole → Scopes**，然後選擇 Networks 表格下方的 **Add**。編輯器預設選擇 LAN；如果沒有 LAN，則選擇第一個可用的非 WAN 介面，並省略已有網路作用域的介面。當用戶端地址位於該介面當前 IPv4 或 IPv6 子網之一時，該用戶端屬於該網路。

每個網路行選擇額外清單、允許的域名以及是否啓用作用域。儲存後會返回 Scopes；選擇鉛筆圖示或雙擊某行即可編輯。在網路之間移動的設備會獲得其當前地址所匹配網路的策略。

## 設備作用域 \{#device-scopes}

選擇 Devices 表格下方的 **Add**，提供名稱並選擇一種識別方式。編輯器只顯示與所選方式對應的識別欄位：

| 方式                  | 用於設備的地址                        |
|---------------------|--------------------------------|
| IP address          | 配置的 IPv4 或 IPv6 地址。            |
| DHCP static mapping | 配置的地址，加上為該映射 MAC 觀察到的當前地址。     |
| MAC address         | 該 MAC 當前的 ARP、NDP 和 DHCP 租約地址。 |

設備行選擇其清單、允許的域名和啓用狀態。儲存後會返回 Scopes；選擇鉛筆圖示或雙擊某行即可編輯。僅當 DNS 封鎖具有已啓用的網路或設備作用域，或 Bypass DNS 保護需要識別用戶端時，後台作業才會每分鐘刷新當前子網和設備地址。套件 Sync 也只會在相同條件下啓動此刷新。

## 決定順序 \{#decision-order}

最具體的匹配層級按以下準確順序決定每個查詢：

1. **Device allowed domains** — 查詢名稱匹配時立即允許。
2. **Device lists** — 所選設備清單匹配時立即封鎖。
3. **Network allowed domains** — 網路例外匹配時立即允許。
4. **Network lists** — 所選網路清單匹配時立即封鎖。
5. **Global allowed domains** — 全局例外匹配時立即允許。
6. **Global lists** — 全局清單匹配時封鎖。

沒有任何步驟作出決定時，查詢會通過。某層級的允許域名會覆蓋從較不具體層級繼承的清單，但不會覆蓋已經在更具體層級作出決定的清單。

## 允許域名的行為 \{#allowed-domain-behavior}

每個允許域名項目適用於準確域名及其所有子域名。例如，允許 `service.example` 也會在該層級允許 `api.service.example`。

- 設備例外先檢查，因此可以通過設備、網路和全局清單。
- 網路例外可以通過網路和全局清單，但不能覆蓋設備清單決定。
- 全局例外只能通過全局清單。

## 地址衝突 \{#address-conflicts}

當兩個設備行聲明同一個當前地址時，表格順序中的第一台設備獲勝。**Status → Scopes** 會在每個受影響行的 **Conflict** 下顯示該地址，以便修正順序或識別碼。

## 驗證作用域 \{#verify-a-scope}

1. 執行 `/usr/local/sbin/sinkhole --refresh-clients`，或等待每分鐘刷新。
2. 打開 **Status → Scopes**，確認網路的當前子網和設備的當前地址。
3. 從該作用域中的用戶端查詢一個名稱，並將結果與上述決定順序比較。
4. 在依靠設備特定行為前檢查地址衝突。
