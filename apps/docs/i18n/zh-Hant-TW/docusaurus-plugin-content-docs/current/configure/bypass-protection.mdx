讓所選用戶端介面的 DNS 查詢始終沿著 Sinkhole 可以檢查的路徑傳輸。所有保護功能預設關閉，預設不選擇任何介面，升級也不會啟用任何保護功能或列表。

## 選擇介面 \{#choose-the-interfaces}

開啟 **Firewall → Sinkhole → Bypass**，並在啟用保護功能之前選擇 **Apply to** 介面。此選擇屬於 **Global**，決定 Global 的設定在哪裡生效。保護功能只檢查從這些介面上的用戶端傳入的流量；不會影響防火牆本身的查詢或輸出流量。

網路和設備比對與普通 Sinkhole 作用域一樣，使用這些介面的目前子網路。所選子網路以外的用戶端不會收到 Bypass DNS 回應。

## 依網路和裝置設定保護 \{#set-protections-per-network-and-device}

分頁下方的一列決定您要編輯的內容：**All**、**Global**、某個網路或某個裝置。其下方的一行列出這些設定適用的用戶端。每個選項只顯示自己的設定；絕不會顯示範圍更廣選項的設定。

用戶端遵循現有設定中最具體的一項：先是其裝置的設定，然後是其網路的設定，最後是 Global 的設定。在 Clients 分頁上已關閉的網路或裝置會被略過。

只有 **Global** 包含：

- **Apply to** 介面。
- **Plain DNS** 重定向及其豁免。

網路或裝置還包含 **Enable**，用於開啟其保護功能。

Global 以及每個網路或裝置都包含：

- **Bypass Lists**，即其使用的已啟用來源。來源在 [Lists → Bypass](/docs/configure/lists#add-bypass-lists) 中新增、啟用和更新。沒有任何已啟用來源時，該欄位改為顯示一行，並附上 **Open Lists** 連結。
- 加密 DNS 設定、**Discovery**、隧道封鎖和 **Block Exemptions**。

沒有自身設定的網路或裝置會在空白表單上方顯示一行，例如「此網路未單獨設定，將使用全域。」如果裝置所屬網路有自身設定且已開啟，裝置會在此處註明該網路。設定已關閉的網路或裝置則會改為顯示「已關閉，將使用全域。」，並註明同一個範圍更廣的設定。儲存表單即可建立設定，**Remove settings for this network** 或 **Remove settings for this device** 會刪除設定，讓範圍更廣的設定重新生效。在 Clients 分頁上刪除網路或裝置也會刪除其設定。

**All** 列出 Global 以及每個有自身設定的網路和裝置，並顯示已開啟的保護功能。選取某列即可編輯。

將 Sinkhole 升級到 1.3.0 時，現有設定會保留在 Global 中，並複製到每個網路和裝置。此後每份副本彼此獨立。只有當網路的介面，或裝置某個識別碼的介面，已在 **Apply to** 中選取時，該副本才會開啟；其他副本均以關閉狀態儲存，因此先前未被過濾的用戶端不會因此被過濾。

Global 與每個網路和裝置一樣選擇自己的 Bypass Lists。將 Sinkhole 升級到 1.3.1 時，Global 的選擇會設為當時存在的所有 Bypass List，因此在您編輯之前不會有任何變化。之後新增的 Bypass List 在 Global、某個網路或某個裝置選取它之前，不會在任何地方使用。

每個已開啟設定的網路或裝置都會在 `sinkhole/bypass` 錨點中取得自己的用戶端表。裝置的地址會從其網路的表和 Global 的表中移除，網路的子網路會從 Global 的表中移除，因此用戶端只會被其最具體的設定封鎖。Sinkhole 不會為此新增 pass 規則。

## 重定向普通 DNS \{#redirect-plain-dns}

選擇 **Redirect → Send port 53 to the firewall**，將所選介面上的普通 TCP 和 UDP DNS 流量傳送到 pfSense。Sinkhole 會保留源地址，因此網路和設備策略仍然適用。

重定向會保留現有的監聽器感知目標和豁免：

| 地址族  | 目標                                                     |
|------|--------------------------------------------------------|
| IPv4 | Resolver 監聽 localhost 時使用 `127.0.0.1`；否則使用介面的 IPv4 地址。 |
| IPv6 | 使用介面的 IPv6 地址，絕不使用 `::1`。                              |

- **Exempt Sources** 仍可存取其他解析器。
- **Exempt Destinations** 仍可接收 DNS 流量，從而支援其他網路上的內部解析器。

每項豁免每行接受一個 IPv4 地址、IPv6 地址、CIDR 網路或現有 pfSense 主機/網路別名。無效的已儲存豁免會暫停所有重定向規則，直到修復或刪除該豁免。重定向的用戶端仍需獲得 Resolver 存取控制設定的允許。

只要 Sinkhole 在 **General** 分頁中已啓用且 DNS Resolver 正在執行，重定向規則就會載入。它們不依賴 Resolver 的 Python 模塊，因此在 pfBlockerNG 或其他腳本佔用該模塊時（例如從 pfBlockerNG 遷移期間）仍會繼續運作。當 Redirect 已開啓但其規則未載入時，**Redirect** 下方的 **Warning** 行會給出原因：

- Sinkhole 已停用。
- DNS Resolver 未執行。
- 某個已儲存的豁免無效。
- 正在移除 Sinkhole。

**Status** 也會在頁面頂部顯示同樣的警告。

## 保護加密 DNS \{#protect-encrypted-dns}

各項加密 DNS 設定彼此獨立：

- **TLS and QUIC** 封鎖傳送到防火牆以外任何目標的 TCP 和 UDP 端口 853。
- **Providers** 封鎖種類為 **Encrypted DNS** 且已選取、已啟用的 Bypass Lists 中的名稱和地址。
- **Firefox** 對 `use-application-dns.net` 及其子網域傳回 `NXDOMAIN`，從而關閉 Firefox 自動選擇 DNS over HTTPS 的功能。
- **Private Relay** 對 `mask.icloud.com` 和 `mask-h2.icloud.com` 傳回 `NXDOMAIN`，告知相容的 Apple 設備此網路不提供 Private Relay。

供應商列表中的名稱會在 DNS 中被封鎖。同一列表中的 IPv4 地址、IPv6 地址和 CIDR 會在獨立的 `sinkhole/bypass` 防火牆錨點中針對所有端口和協定進行封鎖。Sinkhole 會在載入這些表格之前，從中移除防火牆的介面位址以及閘道和 DNS 伺服器位址，包括透過 DHCP 或 PPP 取得的位址。

Bypass 分頁上的每條防火牆封鎖規則都會像 pfSense 的 **Reject** 動作一樣拒絕連線，而不是直接丟棄：TCP 會收到重設，UDP 會收到 ICMP 目標無法到達訊息。被封鎖的用戶端會立即失敗並改用防火牆的 Resolver，無需等待逾時。

允許的網域優先於供應商列表的名稱封鎖。它們不會覆寫 Firefox、Private Relay 或 Discovery 回應，因為這些回應是網路訊號，而不是列表封鎖。

## 設定 Resolver 探索 \{#configure-resolver-discovery}

Discovery 控制對 `_dns.resolver.arpa` 的查詢，該名稱是 RFC 9462 定義的 Designated Resolver Discovery 名稱：

| 選項                                        | 回應                                                    |
|-------------------------------------------|-------------------------------------------------------|
| **Off**                                   | 不變更查詢。                                                |
| **Advertise the firewall's DNS over TLS** | 傳回包含 `alpn=dot`、端口 `853` 和 Resolver 憑證中主機名稱的 SVCB 回應。 |
| **Answer with no records**                | 傳回空回應和 `NOERROR`。                                     |

**Advertise** 要求啟用 DNS Resolver 的 SSL/TLS 服務，並提供可用的憑證主機名稱。Bypass 頁面會報告該服務是否已開啟；服務不可用時，儲存會失敗並顯示清楚的驗證訊息。

啟用 Sinkhole 並選取 **Apply to** 介面後，開啟 Discovery 會將以下受管理區塊加入 DNS Resolver 的 **Custom options**：

```text
# Sinkhole: begin (managed by the Sinkhole package)
server:
local-zone: "_dns.resolver.arpa." transparent
# Sinkhole: end
```

關閉 Discovery 或移除 Sinkhole 會刪除該 zone 列。同一個區塊也承載所有 [Resolver 設定](/docs/configure/resolver-settings)，而 Sinkhole 不會變更 **Custom options** 中的任何其他列。所選介面以外的用戶端（包括防火牆本身）仍會收到 `_dns.resolver.arpa` 的 `NXDOMAIN`。

## 防範隧道 \{#protect-against-tunnels}

- **Tor → Block listed Tor relays** 套用種類為 **Tor** 且已選取、已啟用的 Bypass Lists。
- **VPN → Block listed VPN providers** 套用種類為 **VPN** 且已選取、已啟用的 Bypass Lists。
- **VPN → Block standard VPN ports** 封鎖傳送到防火牆以外任何目標的 TCP 和 UDP `1194`、UDP `51820`、UDP `500` 和 `4500` 以及 ESP。

Tor 和 VPN 列表中的名稱和地址使用與加密 DNS 供應商列表相同的 DNS 和防火牆行為。這些控制可以減少常見的替代路徑，但無法識別所有加密或自訂隧道。

## 讓裝置和伺服器免受封鎖 \{#exempt-devices-and-servers-from-the-blocks}

**Block Exemptions** 包含一個 **Exempt Sources** 列表和一個 **Exempt Destinations** 列表，由 Bypass 分頁上的所有防火牆封鎖共用：**TLS and QUIC**、**Providers**、**Tor**、**Block listed VPN providers** 和 **Block standard VPN ports**。每行接受一個 IPv4 地址、IPv6 地址、CIDR 網路或現有 pfSense 主機/網路別名，與重定向豁免接受的值相同。每個列表最多包含 16 個別名。

- **Exempt Sources** 會略過這些封鎖。可將其用於必須存取外部 DNS 伺服器的用戶端，例如透過 DNS over TLS 連線到 `1.1.1.1` 的 NAS。
- **Exempt Destinations** 對所選介面上的每個用戶端始終可達，不受這些封鎖影響，例如一個您信任的公共解析器。

豁免本身絕不會開啟任何路徑。Sinkhole 不新增任何 pass 規則：豁免流量只是不符合 Bypass 封鎖，然後繼續交由您自己的防火牆規則決定是否放行。

豁免只涵蓋防火牆封鎖。對豁免用戶端而言，Bypass Lists 中的供應商、Tor 和 VPN 名稱在 DNS 中仍會被封鎖，因此透過名稱尋找伺服器的用戶端（例如 `cloudflare-dns.com`）還需要將該名稱加入 **Allowed Domains**。連接埠 53 上的普通 DNS 則遵循 **Redirect** 及其自身的豁免。

如果已儲存的封鎖豁免變為無效，例如別名被重新命名或刪除，Sinkhole 會保留所有封鎖且不套用任何豁免，寫入一筆系統記錄，並在 **Invalid Saved Values** 中顯示該值，直到它被修正或移除。

## 管理 Bypass Lists \{#manage-bypass-lists}

Bypass List 來源在 [Lists → Bypass](/docs/configure/lists#add-bypass-lists) 中新增、編輯、啟用和刪除，該處也提供 **Add from Catalog**，並為每個列表顯示 **Used By** 計數。Bypass 分頁只選擇每個情境使用哪些已啟用的列表。已啟用的 Bypass List 只有在其對應的 **Providers**、**Tor** 或 **VPN** 保護開啟時，才會加入排程更新。

## 驗證活動狀態 \{#verify-the-active-state}

儲存後，開啟 **Status → Bypass**，確認每項預期保護均為 `On`、所選介面正確，並且 Discovery 開啟時 **Discovery Zone** 為 `Present`。確認防火牆保護的 **Firewall Rules Loaded** 和 **Firewall Rules Current** 均為 `Yes`。Bypass Lists 表格會顯示已儲存項目數和上次擷取時間。

普通 DNS 重定向會在 Resolver 監聽器變更後保留現有的兩次觀察分鐘協調。`sinkhole/bypass` 錨點獨立於 `sinkhole/ip` 載入，因此停用任一功能都不會干擾另一個功能。
