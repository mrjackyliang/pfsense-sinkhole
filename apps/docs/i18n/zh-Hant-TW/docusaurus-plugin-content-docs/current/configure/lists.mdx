新增您信任的清單來源，讓 Sinkhole 在防火牆上保留規範化的最後有效副本，供 DNS 立即使用。

## 為什麼使用已儲存清單？ \{#why-use-saved-lists}

1. 讓 DNS 不依賴清單主機，因此緩慢或失敗的下載不會中斷名稱解析。
2. 每個來源只下載一次，因此同一份已儲存副本可以用於全局、網路和設備作用域。
3. 新下載或解析失敗時保留上一份有效副本，因此損壞的輸入不會替換可用策略。
4. 在後台更新清單，因此 Resolver 重啓或重新載入永遠不必等待網路。

## 通過 URL 新增清單 \{#add-a-list-by-url}

打開 **Firewall → Sinkhole → Lists**，選擇封鎖清單表格下方的 **Add**，然後在編輯頁面填寫 **Add Block List**：

| 字段      | 說明                        |
|---------|---------------------------|
| Name    | 在分配、警報和 Status 中顯示的本地標籤。  |
| URL     | 不包含嵌入憑據的 HTTP 或 HTTPS 來源。 |
| Enabled | 下載來源，並使其可供已分配的作用域使用。      |
| Global  | 在設備和網路決定之後，將來源應用於每個用戶端。   |

儲存後會返回 Lists 分頁，並啟動同一條經過驗證的後台套用路徑。選擇某行的鉛筆圖示或雙擊該行即可編輯。停用的行仍保留設定，但會在表格中顯示為灰色，更新程式和編譯策略也不會使用它。

## 可接受的 DNS 格式 \{#accepted-dns-formats}

Sinkhole 接受以下標準格式，並將有效名稱規範化為一個已儲存域名集合：

| 格式           | 示例                                            | 行為            |
|--------------|-----------------------------------------------|---------------|
| Hosts 檔案     | `0.0.0.0 blocked.example`                     | 僅封鎖地址後的每個域名。  |
| 純域名清單        | `blocked.example`                             | 僅封鎖每行中的域名。    |
| Adblock 風格規則 | <code>{'\u007c\u007cblocked.example^'}</code> | 封鎖該域名及其所有子域名。 |

如果希望一個項目封鎖該名稱及其所有子域名，請使用 Adblock 風格的 `||name^` 形式。

裝飾過濾器和格式錯誤的行不會成為 DNS 策略。Status 會報告來源錯誤；如果失敗清單已有有效副本，則會繼續保留該副本。

## 搜索目錄 \{#search-the-catalogs}

在 Lists 選項卡選擇 **Add from Catalog**，搜索 AdGuard Home 的清單註冊表和 pfBlockerNG 源目錄的 DNS 部分。Sinkhole 僅在搜索打開或您選擇 **Refresh** 時獲取兩者；不會捆綁目錄，也不會按計劃下載目錄。

結果以卡片形式顯示。組合使用搜尋、來源和維護者控制項，選擇類別晶片，並在 **Category** 和 **Maintainer** 之間切換 **Group by**。類別晶片顯示目前搜尋、來源和維護者篩選器的計數，而維護者選單會把符合清單最多的擁有者排在最前面。

每張卡片顯示清單名稱、維護者或類別（以目前未作為分組依據的一項為準）、來源目錄、兩行說明、主頁以及 **Add** 或 **Added** 狀態。卡片不顯示評分、徽章或推薦。選擇 **Add** 會建立一個普通清單行，其 URL 可像任何手動輸入的來源一樣分配。

每張卡片的 **Contents** 行顯示 **Domains**。新增目錄結果時，其目錄名稱保持不變。

目錄副本在 `/var/db` 下快取一天。刷新失敗時會保留最後一份有效目錄副本，並在 Status 上顯示獲取錯誤。

指派給 Encrypted DNS、Tor 或 VPN 繞過保護的來源不會顯示在此處。它們只會透過 Bypass 分頁上的 **Add from Catalog** 提供。

## 設定全局允許域名 \{#set-global-allowed-domains}

清單和目錄面板下方的 **Allowed Domains** 部分定義全域例外。每一行允許該網域及其子網域通過繼承的全域清單。選擇該部分下方的 **Save** 以套用這項頁面級設定。

全局允許域名在設備和網路規則之後檢查，因此不能覆蓋已在更具體的設備或網路層級封鎖查詢的清單。

## 選擇更新頻率 \{#choose-the-update-frequency}

**General → Update Frequency** 設定控制計劃 DNS 清單更新；啓用 IP 封鎖時，它也提供更新計劃：

| 設定            | 計劃                     |
|---------------|------------------------|
| Hourly        | 每小時在防火牆穩定的隨機分鐘執行一次。    |
| Every 6 hours | 每六小時在同一個穩定隨機分鐘執行。      |
| Daily         | 每天在該分鐘執行一次，計劃小時為 `00`。 |
| Weekly        | 每周日該分鐘執行一次，計劃小時為 `00`。 |

`Daily` 是預設值。**Status → Update Now** 會啓動手動完整更新，但不會改變已儲存計劃。

## 更新期間發生的操作 \{#what-happens-during-an-update}

1. 通過有界下載用戶端下載每個已啓用來源。
2. 將其解析並規範化為臨時副本。
3. 僅在新副本有效時原子替換已儲存副本。
4. 編譯當前的全局、網路、設備、允許域名和警報策略。
5. 部署新的本地代次，並讓 Unbound 模塊載入它。

當新增封鎖名稱擴大策略時，Sinkhole 會等待模塊載入該代次，然後重新載入 Unbound 一次以清除快取回應。[更新的工作方式](/docs/safety/how-updates-work)介紹完整的可用性和回退模型。

使用包含空格或大於 `0x7f` 的位元組等異常但有效的 DNS 標籤查詢被封鎖的子樹時，Sinkhole 會在回應中保留線路格式名稱，並仍傳回正常的 `0.0.0.0` 或 `::` 回應。查詢不會僅因標籤不是主機名稱格式而變成 SERVFAIL。
