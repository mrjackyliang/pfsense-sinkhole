新增您信任的清單來源，讓 Sinkhole 在防火牆上保留規範化的最後有效副本，供 DNS 立即使用。

## 為什麼使用已儲存清單？ \{#why-use-saved-lists}

1. 讓 DNS 不依賴清單主機，因此緩慢或失敗的下載不會中斷名稱解析。
2. 每個來源只下載一次，因此同一份已儲存副本可以用於 Global、每個網路和每台設備。
3. 新下載或解析失敗時保留上一份有效副本，因此損壞的輸入不會替換可用策略。
4. 在後台更新清單，因此 Resolver 重啓或重新載入永遠不必等待網路。

## 選擇清單類型 \{#choose-a-list-kind}

Lists 是新增、編輯、啟用和刪除所有清單來源的唯一位置。分頁下方的一列可在三種類型之間切換：

| 類型     | 內容                             | 選取位置                                                                               |
|--------|--------------------------------|------------------------------------------------------------------------------------|
| DNS    | 域名封鎖清單。                        | [Blocking](/docs/configure/scopes#choose-lists-and-allowed-domains)                |
| Bypass | Encrypted DNS、Tor 和 VPN 提供者清單。 | [Bypass](/docs/configure/bypass-protection#set-protections-per-network-and-device) |
| IP     | IPv4 和 IPv6 地址及網路清單。           | [IP](/docs/configure/ip-and-country-blocking#set-blocking-per-network-and-device)  |

每種類型都有自己的表格、**Add**、**Add from Catalog**，以及用於修復無效已儲存行的面板。Lists 沒有 Global、網路或設備列；這些選擇屬於使用清單的分頁。

每個表格都有 **Used By** 欄，計入 Global 以及每個設定中選取該清單的網路和設備。任何類型的新清單在某個情境選取它之前都不會封鎖任何內容。

## 通過 URL 新增清單 \{#add-a-list-by-url}

打開 **Firewall → Sinkhole → Lists → DNS**，選擇封鎖清單表格下方的 **Add**，然後在編輯頁面填寫 **Add Block List**：

| 字段      | 說明                                   |
|---------|--------------------------------------|
| Name    | 在 Blocking、Alerts 和 Status 中顯示的本地標籤。 |
| URL     | 不包含嵌入憑據的 HTTP 或 HTTPS 來源。            |
| Enabled | 下載來源，讓 Blocking 可以使用它。               |

儲存後會返回 Lists 分頁，並啟動同一條經過驗證的後台套用路徑。選擇某行的鉛筆圖示或雙擊該行即可編輯。停用的行仍保留設定，但會在表格中顯示為灰色，更新程式和編譯策略也不會使用它。

哪些 DNS 清單套用於 Global、某個網路或某台設備，需在 [Blocking](/docs/configure/scopes#choose-lists-and-allowed-domains) 中選擇。

## 可接受的 DNS 格式 \{#accepted-dns-formats}

Sinkhole 接受以下標準格式，並將有效名稱規範化為一個已儲存域名集合：

| 格式           | 示例                                            | 行為            |
|--------------|-----------------------------------------------|---------------|
| Hosts 檔案     | `0.0.0.0 blocked.example`                     | 僅封鎖地址後的每個域名。  |
| 純域名清單        | `blocked.example`                             | 僅封鎖每行中的域名。    |
| Adblock 風格規則 | <code>{'\u007c\u007cblocked.example^'}</code> | 封鎖該域名及其所有子域名。 |

如果希望一個項目封鎖該名稱及其所有子域名，請使用 Adblock 風格的 `||name^` 形式。

裝飾過濾器和格式錯誤的行不會成為 DNS 策略。Status 會報告來源錯誤；如果失敗清單已有有效副本，則會繼續保留該副本。

## 搜索目錄 \{#search-the-catalogs}

在 **DNS** 下選擇 **Add from Catalog**，搜索 AdGuard Home 的清單註冊表和 pfBlockerNG 源目錄的 DNS 部分。Sinkhole 僅在搜索打開或您選擇 **Refresh** 時獲取兩者；不會捆綁目錄，也不會按計劃下載目錄。

結果以卡片形式顯示。組合使用搜尋、來源和維護者控制項，選擇類別晶片，並在 **Category** 和 **Maintainer** 之間切換 **Group by**。類別晶片顯示目前搜尋、來源和維護者篩選器的計數，而維護者選單會把符合清單最多的擁有者排在最前面。

每張卡片顯示清單名稱、維護者或類別（以目前未作為分組依據的一項為準）、來源目錄、兩行說明、主頁以及 **Add** 或 **Added** 狀態。卡片不顯示評分、徽章或推薦。選擇 **Add** 會建立一個普通清單行，其 URL 可像任何手動輸入的來源一樣分配。

新清單（包括從目錄新增的清單）在您於 Blocking 中為 Global、某個網路或某台設備選取它們之前，不會封鎖任何內容。

每張卡片的 **Contents** 行顯示 **Domains**。新增目錄結果時，其目錄名稱保持不變。

目錄副本在 `/var/db` 下快取一天。刷新失敗時會保留最後一份有效目錄副本，並在 Status 上顯示獲取錯誤。

指派給 Encrypted DNS、Tor 或 VPN 繞過保護的來源不會顯示在此處。它們只會透過 **Bypass** 下的 **Add from Catalog** 提供。

## 新增 Bypass 清單 \{#add-bypass-lists}

打開 **Lists → Bypass**，選擇 **Bypass Lists** 下方的 **Add**，然後輸入本地名稱、類型以及 HTTP 或 HTTPS URL。新行在明確啟用之前保持停用。儲存後會返回 **Lists → Bypass**。表格也會顯示每行已儲存的項目數和最後一次取得時間。

每個來源每行接受一個項目。清單可以混合域名、IPv4 地址、IPv6 地址和 CIDR；`#` 之後的文字為註解。無效和過長的行會被略過。超過固定位元組或接受項目上限的下載會被拒絕，並保留最後一份有效副本。

已啟用的 Bypass List 會依設定的清單排程更新，使用與其他清單相同的有界下載用戶端，但只在其對應的 **Providers**、**Tor** 或 **VPN** 保護開啟時更新。取得失敗時會保留來自同一 URL 的最後一份有效已儲存副本，**Status → Bypass Lists** 會報告每行的項目數、最後一次取得時間和最近一次錯誤。Sinkhole 不會內建或推薦任何 Bypass List。

**Bypass** 下的 **Add from Catalog** 會搜尋 AdGuard Home 清單註冊表，以及 pfBlockerNG 來源目錄的 DNS、IPv4 和 IPv6 部分。結果僅限繞過來源，並具有固定的 **Encrypted DNS**、**Tor** 或 **VPN** 類型，可用卡片上方的晶片篩選。

每張卡片的 **Contents** 行顯示 **Domains**、**IPv4 addresses** 或 **IPv6 addresses**。新增 pfBlockerNG 的 IPv4 或 IPv6 結果時，Sinkhole 會在其儲存名稱後附加 ` (IPv4)` 或 ` (IPv6)`；域名結果保留原本的目錄名稱。新增結果會建立一個已啟用的 Bypass List。

Global、每個網路和每台設備會在 [Bypass](/docs/configure/bypass-protection#set-protections-per-network-and-device) 中選擇各自使用的 Bypass Lists。

## 新增 IP 清單 \{#add-ip-lists}

打開 **Lists → IP**，選擇 IP Lists 表格下方的 **Add** 以開啟 IP 清單編輯器。每行使用 HTTP 或 HTTPS URL，選擇 IPv4、IPv6 或兩者，並控制來源是否啟用。儲存後會返回 **Lists → IP**；選擇鉛筆圖示或雙擊某行即可編輯。

有效行為單一 IPv4 或 IPv6 地址以及 CIDR 網路。範圍大於 `/8` 的 IPv4 網路和大於 `/16` 的 IPv6 網路會被略過，並與其他無效行一起計數；邊界網路 `/8` 和 `/16` 會被接受。沒有任何有效項目的下載不會替換最後一份有效已儲存副本。

**IP** 下的 **Add from Catalog** 會搜尋 pfBlockerNG 來源目錄的 IP 部分。Encrypted DNS、Tor 和 VPN 繞過來源會被排除，只出現在 **Bypass** 下。每張卡片的 **Contents** 行顯示 **IPv4 addresses** 或 **IPv6 addresses**。新增結果時，Sinkhole 會在其儲存名稱後附加 ` (IPv4)` 或 ` (IPv6)`，必要時只截短基本名稱。

Global、每個網路和每台設備會在 [IP](/docs/configure/ip-and-country-blocking#set-blocking-per-network-and-device) 中選擇各自使用的 IP 清單。

## 設定全局允許域名 \{#set-global-allowed-domains}

全域例外位於 **Blocking → Global** 的 **Allowed Domains** 方塊中。每一行允許該網域及其子網域通過全域清單。選擇 **Save** 以套用它們。

全局允許域名在設備和網路規則之後檢查，因此不能覆蓋已在更具體的設備或網路層級封鎖查詢的清單。

## 選擇更新頻率 \{#choose-the-update-frequency}

**General → Update Frequency** 設定在 General 啟用時控制排程 DNS 清單更新。啟用 IP 封鎖時，同一排程也會執行 IP/國家地區更新；已啟用的 Bypass List 只有在其對應的 **Providers**、**Tor** 或 **VPN** 保護開啟時才會依此排程更新：

| 設定            | 計劃                     |
|---------------|------------------------|
| Hourly        | 每小時在防火牆穩定的隨機分鐘執行一次。    |
| Every 6 hours | 每六小時在同一個穩定隨機分鐘執行。      |
| Daily         | 每天在該分鐘執行一次，計劃小時為 `00`。 |
| Weekly        | 每周日該分鐘執行一次，計劃小時為 `00`。 |

`Daily` 是預設值。**Status → Update Now** 會啓動手動完整更新，但不會改變已儲存計劃。

## 更新期間發生的操作 \{#what-happens-during-an-update}

1. 通過有界下載用戶端下載每個已啓用來源。
2. 將其解析並規範化為臨時副本。
3. 僅在新副本有效時原子替換已儲存副本。
4. 編譯當前的全局、網路、設備、允許域名和警報策略。
5. 部署新的本地代次，並讓 Unbound 模塊載入它。

當新增封鎖名稱擴大策略時，Sinkhole 會等待模塊載入該代次，然後重新載入 Unbound 一次以清除快取回應。[更新的工作方式](/docs/safety/how-updates-work)介紹完整的可用性和回退模型。

使用包含空格或大於 `0x7f` 的位元組等異常但有效的 DNS 標籤查詢被封鎖的子樹時，Sinkhole 會在回應中保留線路格式名稱，並仍傳回正常的 `0.0.0.0` 或 `::` 回應。查詢不會僅因標籤不是主機名稱格式而變成 SERVFAIL。
