在將 Sinkhole 的 DNS、NAT 或防火牆策略引入生產網路之前，請先在可丟棄的 pfSense 實驗室中進行測試。

## 驗證軟件下載 \{#verify-the-package-download}

從同一個 GitHub 版本下載穩定套件和 `.sha256` 資源。執行 `pkg add -f` 前，將套件的 SHA-256 摘要與 `pfSense-pkg-Sinkhole.pkg.sha256` 中的單個哈希值進行比較。

僅使用 HTTPS 下載不能替代校驗和比較。通過另一台計算機將檔案傳輸到防火牆時，請將套件和校驗和放在一起。

## 驗證基本安裝 \{#verify-a-basic-installation}

1. 確認 **Firewall → Sinkhole** 可以打開，並且已安裝版本顯示在 **About** 中。
2. 確認 **Services → DNS Resolver** 已啓用，並且其 Python 插槽未被另一個套件佔用。
3. 啓用 Sinkhole、儲存，並確認 **Status → Sinkhole** 為 `Active`。
4. 確認首次成功更新後，編譯、部署和載入代次識別碼一致。

Sinkhole 拒絕替換 Unbound 唯一 Python 模塊插槽中的 pfBlockerNG DNSBL 或其他腳本。應將這種非活動狀態視為配置衝突，而不是安裝失敗。

## 驗證 DNS 策略 \{#verify-dns-policy}

使用您控制的清單中的虛構測試域名，而不是公共清單。從設備和網路身份在 Status 中可見的用戶端逐項測試決定。

1. 確認未列出的名稱可正常解析。
2. 確認全局清單會封鎖其測試名稱。
3. 新增網路允許域名，並確認它可繞過網路和全局清單。
4. 新增設備決定，並確認符合[文檔所述順序](/docs/configure/scopes#decision-order)。
5. 刪除測試資料，並確認下一個已部署代次恢復預期回應。

避免使用 `test.`、`invalid.`、`onion.` 和 `localhost.`，因為 Unbound 會先於 Python 模塊回應這些內置區域。如果結果可能被重復使用，請在檢查之間清除用戶端 DNS 快取。

## 驗證警報 \{#verify-alerts}

為一個虛構測試域名封鎖和已知實驗室用戶端創建一條範圍較窄的規則。確認下一次每分鐘作業記錄事件，並通過 pfSense 配置的通知系統發送。

在規則的重復時間窗口內重復操作，確認通知受到抑制。隨後刪除規則，並確認 Status 不再報告警報處理錯誤。

## 驗證 Bypass 保護 \{#verify-bypass-protection}

選擇一個隔離的實驗室介面，每次啓用一項 Bypass 保護。每次測試後，確認未選擇介面上的同等用戶端不受影響。

1. 啓用 **Redirect**，確認其地址族有 Resolver 監聽地址，並向其他目標發送普通 UDP 和 TCP 端口 53 查詢。確認 pfSense 收到這些查詢。
2. 只在可丟棄配置中新增故意無效的豁免，並確認重定向變為 **Paused**，而不是載入部分規則。恢復有效資料，等待兩次每分鐘觀察，並確認 **pfSense loaded rules** 恢復為 `Yes`。
3. 啓用 **TLS and QUIC**，然後確認前往實驗室目標的 TCP 和 UDP 端口 853 被封鎖，而前往防火牆的流量不受封鎖。
4. 新增一個已停用的 Bypass List，其中僅包含虛構網域、地址、CIDR、註解和無效資料。啓用該清單及其對應保護，然後確認有效名稱和地址被封鎖、無效行被跳過，且後續擷取失敗會保留已儲存副本。
5. 確認 Firefox 和 Private Relay 測試查詢收到 `NXDOMAIN`。確認 DDR 在 **Answer with no records** 模式下傳回空的 `NOERROR` 回應。
6. 在實驗室中配置 Resolver 的 SSL/TLS 服務後，確認 **Advertise** 傳回包含憑證主機名稱、`alpn=dot` 和端口 `853` 的 SVCB。關閉該服務並確認儲存 **Advertise** 無法通過驗證。
7. 啓用標準 VPN 端口，並針對實驗室目標測試 TCP 和 UDP `1194`、UDP `51820`、UDP `500` 和 `4500` 以及 ESP。確認傳送至防火牆的流量未被封鎖。

每次防火牆測試後，確認 **Status → Bypass** 報告預期的規則狀態，並且單獨啓用的 `sinkhole/ip` 仍保持載入。

## 驗證 IP 和國家或地區封鎖 \{#verify-ip-and-country-blocking}

使用虛構的 IP 清單測試夾具，以及不會影響防火牆管理、網關或 DNS 的地址。測試流量前，請確認最終地址族表計數、所選介面和方向以及 **IP Anchor → Yes**。

驗證加入允許清單的測試範圍已從封鎖表中移除。如果測試 GeoLite2，請使用管理員自己的 MaxMind 金鑰，並從任何捕獲輸出中將其刪除。

## 驗證更新和刪除行為 \{#verify-update-and-removal-behavior}

執行手動清單更新，並確認 Status 經過更新、編譯、部署和載入狀態時 DNS 仍繼續回應。故意失敗的來源應保留其先前已儲存副本並顯示錯誤。

刪除前，請決定 **Keep Settings** 是否應保留配置和已儲存清單。使用 `pkg delete -f pfSense-pkg-Sinkhole` 刪除，然後確認 Resolver 集成、計劃任務、普通 DNS 重定向規則、`sinkhole/bypass` 和 `sinkhole/ip` 錨點、快取的 Bypass 資料以及臨時執行時檔案均已消失。

## 記錄環境 \{#record-the-environment}

有用的測試記錄應包含 Sinkhole 版本、pfSense 版本和版本號、FreeBSD 版本、所選功能、Status 狀態以及經過清理的 `Sinkhole:` 系統日誌行。目前沒有任何 pfSense 版本列為正式測試版本；每個 Sinkhole 版本發佈前都會進行兼容性測試。
