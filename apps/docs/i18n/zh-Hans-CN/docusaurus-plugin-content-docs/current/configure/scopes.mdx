在全局、网络和设备层级分配列表和允许的域名，让每个客户端获得适合其当前位置的策略。

## 为什么使用作用域？ \{#why-use-scopes}

1. 为每个 pfSense 接口或 VLAN 提供自己的策略，同时为所有人保留全局规则。
2. 为一台设备提供更具体的决定，而不需要单独的 DNS 服务器。
3. 允许域名可以在误报相关的层级纠正误报，无需放弃整份列表。
4. 将客户端地址与编译列表分开，因此 DHCP、邻居或接口变化不会重新加载 Unbound。

## 全局作用域 \{#global-scope}

选中 **Global** 的列表会在设备和网络决定之后应用于每个客户端。全局允许域名在 **Lists** 选项卡中输入，并允许指定域名及其子域名通过全局列表。

未匹配任何已启用网络或设备作用域的客户端只会获得此层级。

## 网络作用域 \{#network-scopes}

打开 **Firewall → Sinkhole → Scopes**，然后选择 Networks 表格下方的 **Add**。编辑器默认选择 LAN；如果没有 LAN，则选择第一个可用的非 WAN 接口，并省略已有网络作用域的接口。当客户端地址位于该接口当前 IPv4 或 IPv6 子网之一时，该客户端属于该网络。

每个网络行选择额外列表、允许的域名以及是否启用作用域。保存后会返回 Scopes；选择铅笔图标或双击某行即可编辑。在网络之间移动的设备会获得其当前地址所匹配网络的策略。

## 设备作用域 \{#device-scopes}

选择 Devices 表格下方的 **Add**，提供名称并选择一种识别方式。编辑器只显示与所选方式对应的标识符字段：

| 方式                  | 用于设备的地址                        |
|---------------------|--------------------------------|
| IP address          | 配置的 IPv4 或 IPv6 地址。            |
| DHCP static mapping | 配置的地址，加上为该映射 MAC 观察到的当前地址。     |
| MAC address         | 该 MAC 当前的 ARP、NDP 和 DHCP 租约地址。 |

设备行选择其列表、允许的域名和启用状态。保存后会返回 Scopes；选择铅笔图标或双击某行即可编辑。仅当 DNS 阻止具有已启用的网络或设备作用域，或 Bypass DNS 保护需要识别客户端时，后台作业才会每分钟刷新当前子网和设备地址。软件包 Sync 也只会在相同条件下启动此刷新。

## 决定顺序 \{#decision-order}

最具体的匹配层级按以下准确顺序决定每个查询：

1. **Device allowed domains** — 查询名称匹配时立即允许。
2. **Device lists** — 所选设备列表匹配时立即阻止。
3. **Network allowed domains** — 网络例外匹配时立即允许。
4. **Network lists** — 所选网络列表匹配时立即阻止。
5. **Global allowed domains** — 全局例外匹配时立即允许。
6. **Global lists** — 全局列表匹配时阻止。

没有任何步骤作出决定时，查询会通过。某层级的允许域名会覆盖从较不具体层级继承的列表，但不会覆盖已经在更具体层级作出决定的列表。

## 允许域名的行为 \{#allowed-domain-behavior}

每个允许域名条目适用于准确域名及其所有子域名。例如，允许 `service.example` 也会在该层级允许 `api.service.example`。

- 设备例外先检查，因此可以通过设备、网络和全局列表。
- 网络例外可以通过网络和全局列表，但不能覆盖设备列表决定。
- 全局例外只能通过全局列表。

## 地址冲突 \{#address-conflicts}

当两个设备行声明同一个当前地址时，表格顺序中的第一台设备获胜。**Status → Scopes** 会在每个受影响行的 **Conflict** 下显示该地址，以便修正顺序或标识符。

## 验证作用域 \{#verify-a-scope}

1. 运行 `/usr/local/sbin/sinkhole --refresh-clients`，或等待每分钟刷新。
2. 打开 **Status → Scopes**，确认网络的当前子网和设备的当前地址。
3. 从该作用域中的客户端查询一个名称，并将结果与上述决定顺序比较。
4. 在依靠设备特定行为前检查地址冲突。
