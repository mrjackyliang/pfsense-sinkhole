添加您信任的列表来源，让 Sinkhole 在防火墙上保留规范化的最后有效副本，供 DNS 立即使用。

## 为什么使用已保存列表？ \{#why-use-saved-lists}

1. 让 DNS 不依赖列表主机，因此缓慢或失败的下载不会中断名称解析。
2. 每个来源只下载一次，因此同一份已保存副本可以用于 Global、每个网络和每台设备。
3. 新下载或解析失败时保留上一份有效副本，因此损坏的输入不会替换可用策略。
4. 在后台更新列表，因此 Resolver 重启或重新加载永远不必等待网络。

## 选择列表种类 \{#choose-a-list-kind}

Lists 是添加、编辑、启用和删除所有列表来源的唯一位置。选项卡下方的一行可在三种种类之间切换：

| 种类     | 包含                             | 选择位置                                                                               |
|--------|--------------------------------|------------------------------------------------------------------------------------|
| DNS    | 域名阻止列表。                        | [Blocking](/docs/configure/scopes#choose-lists-and-allowed-domains)                |
| Bypass | Encrypted DNS、Tor 和 VPN 提供商列表。 | [Bypass](/docs/configure/bypass-protection#set-protections-per-network-and-device) |
| IP     | IPv4 和 IPv6 地址及网络列表。           | [IP](/docs/configure/ip-and-country-blocking#set-blocking-per-network-and-device)  |

每种种类都有自己的表格、**Add**、**Add from Catalog**，以及用于修复无效已保存行的面板。Lists 没有 Global、网络或设备行；这些选择属于使用这些列表的选项卡。

每个表格都有 **Used By** 列，计入 Global 以及设置中选择该列表的每个网络和设备。任何种类的新列表在某个上下文选择它之前都不会阻止任何内容。

## 通过 URL 添加列表 \{#add-a-list-by-url}

打开 **Firewall → Sinkhole → Lists → DNS**，选择阻止列表表格下方的 **Add**，然后在编辑页面填写 **Add Block List**：

| 字段      | 说明                                   |
|---------|--------------------------------------|
| Name    | 在 Blocking、Alerts 和 Status 中显示的本地标签。 |
| URL     | 不包含嵌入凭据的 HTTP 或 HTTPS 来源。            |
| Enabled | 下载来源，以便 Blocking 可以使用它。              |

保存后会返回 Lists 选项卡，并启动同一条经过验证的后台应用路径。选择某行的铅笔图标或双击该行即可编辑。禁用的行仍保留配置，但会在表格中显示为灰色，更新程序和编译策略也不会使用它。

哪些 DNS 列表应用于 Global、某个网络或某台设备，需在 [Blocking](/docs/configure/scopes#choose-lists-and-allowed-domains) 中选择。

## 可接受的 DNS 格式 \{#accepted-dns-formats}

Sinkhole 接受以下标准格式，并将有效名称规范化为一个已保存域名集合：

| 格式           | 示例                                            | 行为            |
|--------------|-----------------------------------------------|---------------|
| Hosts 文件     | `0.0.0.0 blocked.example`                     | 仅阻止地址后的每个域名。  |
| 纯域名列表        | `blocked.example`                             | 仅阻止每行中的域名。    |
| Adblock 风格规则 | <code>{'\u007c\u007cblocked.example^'}</code> | 阻止该域名及其所有子域名。 |

如果希望一个条目阻止该名称及其所有子域名，请使用 Adblock 风格的 `||name^` 形式。

装饰过滤器和格式错误的行不会成为 DNS 策略。Status 会报告来源错误；如果失败列表已有有效副本，则会继续保留该副本。

## 搜索目录 \{#search-the-catalogs}

在 **DNS** 下选择 **Add from Catalog**，搜索 AdGuard Home 的列表注册表和 pfBlockerNG 源目录的 DNS 部分。Sinkhole 仅在搜索打开或您选择 **Refresh** 时获取两者；不会捆绑目录，也不会按计划下载目录。

结果以卡片形式显示。组合使用搜索、来源和维护者控件，选择类别芯片，并在 **Category** 和 **Maintainer** 之间切换 **Group by**。类别芯片显示当前搜索、来源和维护者筛选器的计数，而维护者菜单会把匹配列表最多的所有者排在最前面。

每张卡片显示列表名称、维护者或类别（以当前未作为分组依据的一项为准）、源目录、两行说明、主页以及 **Add** 或 **Added** 状态。卡片不显示评分、徽章或推荐。选择 **Add** 会创建一个普通列表行，其 URL 可像任何手动输入的来源一样分配。

新列表（包括从目录添加的列表）在您于 Blocking 中为 Global、某个网络或某台设备选择它们之前，不会阻止任何内容。

每张卡片的 **Contents** 行显示 **Domains**。添加目录结果时，其目录名称保持不变。

目录副本在 `/var/db` 下缓存一天。刷新失败时会保留最后一份有效目录副本，并在 Status 上显示获取错误。

分配给 Encrypted DNS、Tor 或 VPN 绕过防护的订阅源不会显示在此处。它们只能通过 **Bypass** 下的 **Add from Catalog** 获取。

## 添加 Bypass Lists \{#add-bypass-lists}

打开 **Lists → Bypass**，选择 **Bypass Lists** 下方的 **Add**，然后输入本地名称、种类以及 HTTP 或 HTTPS URL。新行在明确启用之前保持禁用。保存后会返回 **Lists → Bypass**。表格还会显示每一行的已保存条目数和上次获取时间。

每个来源每行接受一个条目。列表可混合域名、IPv4 地址、IPv6 地址和 CIDR；`#` 后面的文本是注释。无效和过长的行会被跳过。超过固定字节数或已接受条目数限制的下载会被拒绝，并保留最后的有效副本。

已启用的 Bypass List 仅在其对应的 **Providers**、**Tor** 或 **VPN** 保护开启时，才会使用与其他列表相同的受限下载客户端，按照配置的列表计划更新。获取失败时会保留来自同一 URL 的最后有效保存副本，**Status → Bypass Lists** 会报告每一行的条目数、上次获取时间和最新错误。Sinkhole 不捆绑或推荐任何 Bypass List。

**Bypass** 下的 **Add from Catalog** 会搜索 AdGuard Home 列表注册表以及 pfBlockerNG 订阅源目录的 DNS、IPv4 和 IPv6 部分。结果仅包含绕过订阅源，类型固定为 **Encrypted DNS**、**Tor** 或 **VPN**，可使用卡片上方的芯片按类型筛选。

每张卡片的 **Contents** 行显示 **Domains**、**IPv4 addresses** 或 **IPv6 addresses**。添加 pfBlockerNG IPv4 或 IPv6 结果时，Sinkhole 会在保存的名称后附加 ` (IPv4)` 或 ` (IPv6)`；域名结果保留未加后缀的目录名称。添加结果会创建一个已启用的 Bypass List。

Global、每个网络和每台设备在 [Bypass](/docs/configure/bypass-protection#set-protections-per-network-and-device) 中选择各自使用的 Bypass Lists。

## 添加 IP 列表 \{#add-ip-lists}

打开 **Lists → IP**，选择 IP Lists 表格下方的 **Add** 以打开 IP 列表编辑器。每行使用 HTTP 或 HTTPS URL，选择 IPv4、IPv6 或两个地址族，并控制是否启用来源。保存后会返回 **Lists → IP**；选择铅笔图标或双击某行即可编辑。

有效行是单个 IPv4 或 IPv6 地址以及 CIDR 网络。比 IPv4 `/8` 或 IPv6 `/16` 更宽的网络会被跳过，并与其他无效行一起计数；边界网络 `/8` 和 `/16` 可以接受。没有有效条目的下载不会替换最后一份有效副本。

**IP** 下的 **Add from Catalog** 会搜索 pfBlockerNG 源目录的 IP 部分。Encrypted DNS、Tor 和 VPN 绕过订阅源会被排除，只显示在 **Bypass** 下。每张卡片的 **Contents** 行显示 **IPv4 addresses** 或 **IPv6 addresses**。添加结果时，Sinkhole 会在保存的名称后附加 ` (IPv4)` 或 ` (IPv6)`，并在必要时仅截短基础名称。

Global、每个网络和每台设备在 [IP](/docs/configure/ip-and-country-blocking#set-blocking-per-network-and-device) 中选择各自使用的 IP 列表。

## 设置全局允许域名 \{#set-global-allowed-domains}

全局例外位于 **Blocking → Global** 的 **Allowed Domains** 框中。每一行允许该域名及其子域名通过全局列表。选择 **Save** 以应用它们。

全局允许域名在设备和网络规则之后检查，因此不能覆盖已在更具体的设备或网络层级阻止查询的列表。

## 选择更新频率 \{#choose-the-update-frequency}

**General → Update Frequency** 设置在 General 启用时控制计划 DNS 列表更新。启用 IP 阻止时，同一计划也会运行 IP/国家地区更新；已启用的 Bypass List 仅在其对应的 **Providers**、**Tor** 或 **VPN** 保护开启时才按此计划更新：

| 设置            | 计划                     |
|---------------|------------------------|
| Hourly        | 每小时在防火墙稳定的随机分钟运行一次。    |
| Every 6 hours | 每六小时在同一个稳定随机分钟运行。      |
| Daily         | 每天在该分钟运行一次，计划小时为 `00`。 |
| Weekly        | 每周日该分钟运行一次，计划小时为 `00`。 |

`Daily` 是默认值。**Status → Update Now** 会启动手动完整更新，但不会改变已保存计划。

## 更新期间发生的操作 \{#what-happens-during-an-update}

1. 通过有界下载客户端下载每个已启用来源。
2. 将其解析并规范化为临时副本。
3. 仅在新副本有效时原子替换已保存副本。
4. 编译当前的全局、网络、设备、允许域名和警报策略。
5. 部署新的本地代次，并让 Unbound 模块加载它。

当新增阻止名称扩大策略时，Sinkhole 会等待模块加载该代次，然后重新加载 Unbound 一次以清除缓存应答。[更新的工作方式](/docs/safety/how-updates-work)介绍完整的可用性和回退模型。

使用包含空格或大于 `0x7f` 的字节等异常但有效的 DNS 标签查询被阻止的子树时，Sinkhole 会在响应中保留线格式名称，并仍返回正常的 `0.0.0.0` 或 `::` 响应。查询不会仅因标签不是主机名格式而变成 SERVFAIL。
