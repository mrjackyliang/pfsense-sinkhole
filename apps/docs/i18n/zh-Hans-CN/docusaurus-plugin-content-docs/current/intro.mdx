直接在 pfSense 内，为整个网络、一个 VLAN 或一台设备分别阻止不需要的网站。

## Sinkhole 的作用 \{#what-sinkhole-does}

Sinkhole for pfSense 让家长和雇主可以控制哪些<Terminology title="被选中用于阻止的名称或地址" to="/docs/reference/terminology#block-list">阻止列表</Terminology>应用于网络的各个部分。它在防火墙上保留最后一份有效副本，因此重启或重新加载后，DNS 可以立即应答，同时在后台下载较新的副本。

被阻止的名称会返回 `0.0.0.0` 或 `::`。如果 CNAME 链到达被阻止的名称，该查询也会被阻止；而在决定层级明确允许的名称仍会被允许。

## 为什么使用 Sinkhole？ \{#why-use-sinkhole}

1. 在全局、网络和设备<Terminology title="阻止列表的应用范围" to="/docs/reference/terminology#scope">作用域</Terminology>应用策略，让儿童、访客、员工和单台设备可以使用不同的列表。
2. 使用<Terminology title="保存在防火墙上的最后一份有效阻止列表副本" to="/docs/reference/terminology#saved-list">已保存列表</Terminology>，因此 DNS 不必等待下载，更新失败后也不会失去可用列表。
3. 仅针对您选择的列表和客户端，通过 pfSense 自带的通知系统发送<Terminology title="匹配列表和客户端后发送通知的规则" to="/docs/reference/terminology#alert-rule">警报规则</Terminology>通知。
4. 为普通 DNS、加密 DNS 发现和提供商、Tor 中继以及 VPN 提供商或端口提供可选的<Terminology title="让所选客户端保持使用受检查 DNS 路径的控制" to="/docs/reference/terminology#bypass-protection">防绕过保护</Terminology>。
5. 当 DNS 过滤不足时提供独立的 IP 和国家/地区阻止功能，而且不需要第二台主机或云服务。

## DNS 集成的工作方式 \{#how-dns-integration-works}

Sinkhole 作为 Python 模块运行在 pfSense 基于 Unbound 的<Terminology title="pfSense 的 Unbound DNS 服务" to="/docs/reference/terminology#dns-resolver">DNS Resolver</Terminology>中。Unbound 启动时，该模块只加载本地编译文件，并监视较新的本地代次，不会让 DNS 查询等待。

DNS Resolver 只提供一个 Python 脚本槽位。只有当该槽位为空或已经属于 Sinkhole 时，Sinkhole 才会使用它；它拒绝替换其他所有者，例如 pfBlockerNG 的 DNSBL 模块。

:::warning

Sinkhole 和 pfBlockerNG DNSBL 无法同时过滤 DNS，因为两者都需要 Resolver 的唯一 Python 脚本槽位。

:::

## 仍由您控制的内容 \{#what-stays-under-your-control}

- **Lists** — 通过 URL 添加您信任的来源，或使用中立的<Terminology title="WebGUI 中按需使用的目录搜索" to="/docs/reference/terminology#popular-list-search">常用列表搜索</Terminology>查找来源。Sinkhole 不发布也不推荐任何列表。
- **Scopes** — 选择全局列表、某个 pfSense 接口或 VLAN 的列表，以及通过 IP 地址、DHCP 静态映射或 MAC 地址识别的设备列表。
- **Allowed Domains** — 在全局、网络或设备层级允许某个域名及其子域名，而无需放弃整份列表。
- **Alerts** — 选择哪些列表和客户端组合创建本地 WebGUI 通知，或使用 pfSense 已配置的远程通知服务。
- **Bypass** — 保持所有控制关闭，或选择客户端接口并明确启用普通 DNS 重定向、加密 DNS 信号、提供商列表或隧道保护。
- **IP blocking** — 保持关闭，或选择 IP 列表、国家/地区、接口、方向和允许的地址。

## 限制 \{#limits}

DNS 阻止并不是完整的流量控制。防绕过保护只有在启用各项控制后才覆盖常见的替代路径，并且无法识别所有加密或自定义隧道。

阻止事件和通知会透露客户端尝试访问的内容。除了您选择通过 pfSense 发送的通知外，这些信息都保留在防火墙上。

## 语言 \{#languages}

WebGUI 遵循 pfSense 中选择的语言；尚无翻译时会回退到英语。其他 WebGUI 翻译仍在进行中，在每份目录通过审核前都会继续使用该回退。

文档站点提供英语和 pfSense 的其他 17 个区域设置。翻译页面保留英语锚点，因此每种语言的链接都会到达相同章节。
