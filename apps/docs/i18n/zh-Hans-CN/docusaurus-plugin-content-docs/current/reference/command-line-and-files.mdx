使用固定的 `/usr/local/sbin/sinkhole` 命令进行诊断，并运行 cron 和 WebGUI 调用的相同维护模式。

## 命令模式 \{#command-modes}

| 命令                           | 行为                                      |
|------------------------------|-----------------------------------------|
| `sinkhole --update`          | 运行计划的 DNS、Bypass 和已启用 IP/国家或地区列表更新路径。   |
| `sinkhole --manual`          | 运行 **Status → Update Now** 使用的完整手动更新。   |
| `sinkhole --apply`           | 在后台应用已保存配置，并且只执行其所需的下载工作。               |
| `sinkhole --refresh-clients` | 重建客户端映射中的网络子网和设备地址。                     |
| `sinkhole --alerts`          | 读取阻止事件并处理匹配的警报规则。                       |
| `sinkhole --redirect-check`  | 协调所需的普通 DNS 重定向规则和独立加载的 Bypass 与 IP 锚点。 |
| `sinkhole --check-updates`   | 检查最新 GitHub 版本并同步更新通知。                  |
| `sinkhole --self-update`     | 下载、验证、检查并安装最新的排队版本。                     |
| `sinkhole --help`            | 输出支持的用法行。                               |

在自动化中使用安装路径，例如 `/usr/local/sbin/sinkhole --refresh-clients`。这些模式互斥；如果 DNS/Bypass/IP 列表更新或自更新发现共享更新锁已被持有，则会退出而不启动竞争操作。

## `/cf/conf/sinkhole` 下的持久文件 \{#persistent-files}

| 路径                                      | 用途                                |
|-----------------------------------------|-----------------------------------|
| `lists/<id>.domains`                    | 一个 DNS 列表的规范化最后有效域名。              |
| `lists/<id>.json`                       | 该 DNS 列表的更新元数据。                   |
| `ip-lists/<id>.networks`                | 一个 IP 列表的规范化最后有效网络。               |
| `ip-lists/<id>.json`                    | 该 IP 列表的更新元数据。                    |
| `bypass-lists/<id>.entries`             | 一个 Bypass List 的规范化上次成功混合条目。      |
| `bypass-lists/<id>.json`                | 该 Bypass List 的更新元数据。             |
| `state.json`                            | 持久化的编译、部署、先前 Resolver 设置、计划和删除状态。 |
| `updates.json`                          | 最新版本检查和通知去重状态。                    |
| `update-status.json`                    | 分离的软件包自更新进度。                      |
| `unbound/sinkhole/`                     | 当前编译代次的可选持久镜像，用于 RAM 磁盘恢复。        |
| `unbound/sinkhole.d/`                   | 编译代次存储的可选持久镜像。                    |
| `unbound/sinkhole-clients/clients.json` | 客户端映射的可选持久镜像。                     |

当 pfSense 将 `/var` 放在 RAM 磁盘上时，会使用 `unbound/` 镜像。软件包 Sync 会在 Resolver 需要这些内容之前将其恢复到运行时树中。

## `/var/db` 下的工作数据 \{#working-data}

| 路径                                   | 用途                         |
|--------------------------------------|----------------------------|
| `sinkhole-alerts.json`               | 警报重复窗口和每小时上限状态。            |
| `sinkhole-catalog-adguard-home.json` | 缓存的 AdGuard Home 列表注册表。    |
| `sinkhole-catalog-pfblockerng.json`  | 缓存的 pfBlockerNG 源目录。       |
| `sinkhole-block-v4.txt`              | 最终合并并扣除后的 IPv4 阻止表。        |
| `sinkhole-block-v6.txt`              | 最终合并并扣除后的 IPv6 阻止表。        |
| `sinkhole-bypass-v4.txt`             | 扣除受保护地址后的最终 IPv4 Bypass 表。 |
| `sinkhole-bypass-v6.txt`             | 扣除受保护地址后的最终 IPv6 Bypass 表。 |
| `sinkhole-geolite2-country.zip`      | 已验证的 GeoLite2 Country 归档。  |
| `sinkhole-geolite2-country.json`     | GeoLite2 更新元数据。            |

目录缓存和生成的 IP 表都是可重建的工作数据。警报状态用于防止每分钟运行之间重复发送。

## `/var/run` 下的临时文件 \{#transient-files}

| 路径                              | 用途                           |
|---------------------------------|------------------------------|
| `sinkhole-update.lock`          | 列表、IP 和软件包更新共用的长时间运行锁。       |
| `sinkhole-runtime.lock`         | 编译、激活和 Resolver 集成使用的短时锁。    |
| `sinkhole-clients.lock`         | 客户端映射刷新锁。                    |
| `sinkhole-alerts.lock`          | 警报处理锁。                       |
| `sinkhole-redirect-check.lock`  | 重定向每分钟检查锁。                   |
| `sinkhole-redirect-check.json`  | 两次观察重定向检查使用的第一次不匹配观察。        |
| `sinkhole-status.json`          | 当前更新、编译、部署、客户端和警报状态。         |
| `sinkhole-status.json.lock`     | 状态文件协调锁。                     |
| `sinkhole-ip-anchor.conf`       | 为 `sinkhole/ip` 锚点生成的当前规则。   |
| `sinkhole-ip-anchor.sha256`     | 用于比较已生成和已加载 IP 策略的摘要。        |
| `sinkhole-ip-status.json`       | IP 列表、GeoLite2、表和锚点状态。       |
| `sinkhole-bypass-anchor.conf`   | `sinkhole/bypass` 锚点当前生成的规则。 |
| `sinkhole-bypass-anchor.sha256` | 用于比较生成和加载的 Bypass 策略的摘要。     |

锁文件的存在本身并不能证明某个活动进程持有它们。在将锁视为过期之前，请使用 Status 和命令输出进行判断。

## `/var/unbound` 下的 Resolver 运行时 \{#resolver-runtime}

| 路径                                   | 用途                                  |
|--------------------------------------|-------------------------------------|
| `sinkhole.py`                        | 复制到 Unbound 运行时根目录的已审查 Python 模块。   |
| `sinkhole/`                          | 模块读取的清单和活动代次数据。                     |
| `sinkhole.d/`                        | 由 root 拥有的编译代次存储。                   |
| `sinkhole.d/<generation>/bypass.tsv` | 为 Bypass DNS 响应编译的提供商、Tor 和 VPN 名称。 |
| `sinkhole-clients/clients.json`      | 当前客户端地址到作用域的映射。                     |
| `sinkhole-state/loaded`              | 模块报告为已加载的代次标识符。                     |
| `sinkhole-state/events`              | 等待警报处理的合并阻止应答事件。                    |
| `sinkhole-state/events.processing`   | 当前由警报处理器持有的事件批次。                    |
| `sinkhole-state/events-dropped`      | 有界队列填满后丢弃的事件数。                      |

这些文件是运行时材料，而不是配置。Sinkhole 通过软件包 Sync 恢复或重新生成它们，并在卸载软件包时将其删除。

仅当 DNS 阻止具有已启用的网络或设备范围，或 Bypass DNS 保护需要识别客户端时，才会运行每分钟客户端映射任务和 Sync 时的后台刷新。关闭所有 Sinkhole 功能后，下一次 Sync 会删除运行时客户端映射及其可选的 RAM 磁盘镜像，并且不会启动刷新。
