2026년 11월 10일에 출시된 Sinkhole for pfSense 1.0은 방화벽 옆에 두 번째 DNS 서버를 두지 않고도 전체 네트워크, 각 VLAN, 각 장치에 별도의 DNS 차단 목록을 적용하는 네이티브 pfSense 패키지입니다.

## 제가 이 패키지를 만든 이유 \{#why-i-built-it}

저는 네트워크의 부분마다 다른 차단을 원했습니다. 아이들을 위한 목록, 방문자를 위한 목록, 그리고 모두에게 적용할 전역 목록이 따로 필요했습니다. pfBlockerNG는 모든 클라이언트에 같은 DNS 목록을 사용하므로, 저는 응답 정책 영역을 사용하는 일반 Unbound 구성으로 돌아갔습니다.

이 구성은 동작했지만, 방화벽을 재시작하거나 다시 로드할 때마다 목록을 다시 불러오는 동안 약 10분간 인터넷이 끊겼습니다. Pi-hole과 AdGuard Home은 클라이언트마다 다른 목록을 줄 수 있지만, 둘 다 pfSense 밖에 별도의 호스트가 필요합니다. Sinkhole은 제가 필요했지만 찾을 수 없었던 패키지입니다.

## 패키지가 하는 일 \{#what-it-does}

Sinkhole은 pfSense의 DNS Resolver 안에서 Python 모듈로 실행되며, 차단된 이름에는 `0.0.0.0`과 `::`으로 응답합니다.

- **모든 범위의 목록** — 전역 목록은 모두에게 적용됩니다. 네트워크 범위는 한 인터페이스나 VLAN에 목록을 추가하고, 장치 범위는 하나 이상의 IP 주소, DHCP 정적 매핑 또는 MAC 주소로 식별한 한 장치에 공유 목록 하나를 추가합니다.
- **모든 수준의 허용 도메인** — 오탐은 전체 목록을 빼지 않고 필요한 수준에서 바로잡습니다.
- **모든 목록의 저장된 사본** — DNS Resolver를 재시작하거나 재부팅한 직후에도 마지막 정상 데이터로 DNS에 응답하며, RAM 디스크 설치도 마찬가지입니다. 다운로드에 실패하면 이전 사본을 유지합니다.
- **직접 고르는 알림** — 알림 규칙에서 선택한 목록, 네트워크, 장치에 대해서만 pfSense 알림이 오며, 장치와 도메인마다 한 번만 보냅니다.
- **차단된 서비스** — Services 탭은 공개 서비스 레지스트리를 바탕으로 범위별로 서비스 전체를 차단합니다.
- **인기 목록 검색** — 카탈로그 카드로 널리 쓰이는 차단 목록을 카테고리나 관리자별로 찾을 수 있습니다. Sinkhole은 어떤 목록도 게시하거나 추천하지 않습니다.

hosts, 일반 도메인, adblock 형식의 목록은 DNS Resolver를 재시작하지 않고 로드됩니다.

## 검증 결과 \{#proof}

Sinkhole 1.0은 네 가지 pfSense 릴리스(CE 2.9.0, CE 2.8.1, Plus 26.07, Plus 26.03.1)에서 설치, 업데이트, 차단 테스트, 제거를 처음부터 끝까지 통과했습니다. 차단된 이름 300,000개로 측정한 테스트에서 정책 메모리 최대 사용량은 이름당 약 157바이트였습니다.

WebGUI, Status 탭, 알림은 pfSense의 언어 설정을 따르며, pfSense가 제공하는 18개 언어를 모두 지원합니다.

## 시작하기 \{#get-started}

`pkg add` 명령 하나로 패키지를 설치하고 **Firewall → Sinkhole**을 엽니다. 체크섬 확인과 첫 설정은 [패키지 설치](/docs/installation)에서 단계별로 안내합니다.

Sinkhole for pfSense는 범위별 DNS, IP 및 국가 차단을 pfSense에 제공하며, 모든 목록을 방화벽에 저장합니다.
