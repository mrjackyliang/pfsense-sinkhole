목록과 클라이언트가 활성화된 알림 규칙에 일치하는 차단 응답에 대해서만 알림을 보냅니다.

## 알림 규칙을 사용하는 이유 \{#why-use-alert-rules}

1. 선택한 목록과 클라이언트를 감시하므로 해당 정책 밖의 일반 차단은 알림을 만들지 않습니다.
2. pfSense의 기존 로컬 및 원격 알림 채널을 사용하므로 Sinkhole에 별도 전달 서비스가 필요하지 않습니다.
3. 반복을 억제하고 급증한 이벤트를 요약하므로 요청이 잦은 도메인이 WebGUI나 받은편지함을 가득 채우지 않습니다.
4. 이벤트 큐를 제한하고 DNS 쿼리 처리 밖에서 다루므로 알림 전달이 응답을 지연시키지 않습니다.

## 규칙 만들기 \{#create-a-rule}

**Firewall → Sinkhole → Alerts**를 열고 알림 규칙 표 아래의 **Add**를 선택한 다음 편집기 페이지에서 **Add Alert Rule**을 작성합니다.

| 필드                   | 설명                                             |
|----------------------|------------------------------------------------|
| Description          | 알림 문구와 요약에 표시되는 로컬 규칙 이름입니다.                   |
| Any block list       | 선택한 목록뿐 아니라 모든 목록의 차단과 일치합니다.                  |
| Chosen block lists   | **Any**가 꺼져 있을 때 규칙을 충족할 수 있는 목록입니다.           |
| Everyone             | 선택한 네트워크와 장치뿐 아니라 모든 클라이언트와 일치합니다.             |
| Chosen networks      | **Everyone**이 꺼져 있을 때 규칙을 충족할 수 있는 네트워크 범위입니다. |
| Chosen devices       | **Everyone**이 꺼져 있을 때 규칙을 충족할 수 있는 장치 범위입니다.   |
| Repeat after         | 같은 규칙, 클라이언트, 도메인 및 목록이 다시 알림을 보낼 때까지의 분입니다.   |
| WebGUI notice        | pfSense에 로컬 Sinkhole 알림을 추가합니다.                |
| Remote notifications | pfSense에 구성된 원격 서비스를 사용합니다.                    |
| Enabled              | 차단된 응답이 이 규칙과 일치할 수 있게 합니다.                    |

**Any block list**가 선택되어 있으면 선택 목록 필드가 숨겨지고, **Everyone**이 선택되어 있으면 네트워크 및 장치 필드가 숨겨집니다. 저장하면 Alerts로 돌아갑니다. 연필을 선택하거나 행을 두 번 클릭하여 편집합니다.

이름을 차단한 목록 중 하나를 규칙에서 선택하고 같은 규칙에서 클라이언트도 선택한 경우에만 차단이 일치합니다. 기본 반복 간격은 60분이며 허용 범위는 1분부터 1,440분까지입니다.

## 전달 채널 \{#delivery-channels}

- **WebGUI notice**는 pfSense의 로컬 `file_notice()` 채널을 사용하며 Alerts 탭으로 연결됩니다.
- **Remote notifications**는 pfSense에 구성된 `notify_all_remote()` 서비스를 사용합니다.

Sinkhole은 이메일, 채팅, webhook 또는 다른 자체 채널을 만들지 않습니다. 원격 서비스는 pfSense의 **System → Advanced → Notifications**에서 구성하고 테스트합니다.

## 고정 한도 \{#fixed-limits}

| 한도                | 동작                                         |
|-------------------|--------------------------------------------|
| 분당 실행 1회에 메시지 20개 | 추가 차단은 같은 한도 안에서 하나 이상의 규칙 요약으로 합쳐집니다.     |
| 규칙당 시간당 메시지 60개   | 60번째 자리는 시간당 초과 요약을 위해 예약됩니다.              |
| 미확인 WebGUI 알림 50개 | 일부 Sinkhole 알림을 확인할 때까지 추가 로컬 알림이 대기합니다.   |
| 처리 시간 40초         | 완료되지 않은 전송은 현재 작업을 붙잡지 않고 다음 분 작업으로 넘어갑니다. |
| 이벤트 보존 시간 10분     | 더 오래된 큐 이벤트는 만료된 것으로 폐기됩니다.                |

Status에는 읽은 이벤트, 만료된 이벤트, 보낸 알림, 보류된 알림 및 모듈이 삭제한 이벤트 수가 표시됩니다. 활성화된 알림 규칙이 하나도 남지 않으면 Sinkhole이 이벤트 파일과 반복 상태를 제거합니다.

## 개인정보 보호 및 로그 \{#privacy-and-logging}

알림 문구에는 차단된 이름, 클라이언트, 네트워크, 목록 및 규칙이 표시됩니다. CNAME 차단에는 목록에 포함된 CNAME 대상도 표시됩니다.

pfSense의 로컬 알림 함수는 `New alert found: <message>`를 시스템 로그에 기록하므로 도메인과 장치도 **Status → System Logs → System → General**에 나타납니다. 알림과 로그를 모두 탐색 정책 기록으로 취급하는 것이 좋습니다.

## 알림 검증 \{#verify-an-alert}

1. 규칙, 선택한 목록 및 선택한 클라이언트 범위가 활성화되어 있는지 확인합니다.
2. Status에서 클라이언트가 현재 의도한 네트워크나 장치에 매핑되어 있는지 확인합니다.
3. 선택한 목록이 차단하는 이름을 쿼리하고 구성된 pfSense 채널을 확인합니다.
4. 두 번째 알림이 오지 않으면 시도 시점과 규칙의 반복 간격 및 고정 한도를 비교합니다.
