신뢰하는 목록 출처를 추가하면 Sinkhole이 DNS에서 즉시 사용할 수 있도록 정규화된 마지막 정상 사본을 방화벽에 보관합니다.

## 저장된 목록을 사용하는 이유 \{#why-use-saved-lists}

1. DNS가 목록 호스트에 의존하지 않으므로 다운로드가 느리거나 실패해도 이름 확인이 중단되지 않습니다.
2. 각 출처를 한 번만 다운로드하므로 같은 저장 사본을 전역, 네트워크 및 장치 범위에서 사용할 수 있습니다.
3. 새 다운로드나 구문 분석이 실패하면 이전 유효 사본을 유지하므로 잘못된 입력이 정상 정책을 대체하지 않습니다.
4. 목록을 백그라운드에서 업데이트하므로 Resolver를 재시작하거나 다시 로드할 때 네트워크를 기다리지 않습니다.

## URL로 목록 추가 \{#add-a-list-by-url}

**Firewall → Sinkhole → Lists**를 열고 차단 목록 표 아래의 **Add**를 선택한 다음 편집기 페이지에서 **Add Block List**를 작성합니다.

| 필드      | 설명                                  |
|---------|-------------------------------------|
| Name    | 할당, 알림 및 Status에 표시되는 로컬 레이블입니다.    |
| URL     | 자격 증명이 포함되지 않은 HTTP 또는 HTTPS 출처입니다. |
| Enabled | 출처를 다운로드하고 할당된 범위에서 사용할 수 있게 합니다.   |
| Global  | 장치 및 네트워크 판단 후 모든 클라이언트에 출처를 적용합니다. |

저장하면 Lists 탭으로 돌아가며 동일한 검증된 백그라운드 적용 경로가 시작됩니다. 행의 연필을 선택하거나 행을 두 번 클릭하여 편집합니다. 비활성화된 행은 구성에 남아 있지만 표에서 흐리게 표시되며 업데이트 도구나 컴파일된 정책에서 사용하지 않습니다.

## 허용되는 DNS 형식 \{#accepted-dns-formats}

Sinkhole은 다음 표준 형식을 허용하고 유효한 이름을 하나의 저장된 도메인 집합으로 정규화합니다.

| 형식            | 예                                             | 동작                         |
|---------------|-----------------------------------------------|----------------------------|
| Hosts 파일      | `0.0.0.0 blocked.example`                     | 주소 뒤의 각 도메인 이름만 정확히 차단합니다. |
| 일반 도메인 목록     | `blocked.example`                             | 각 줄의 도메인 이름만 정확히 차단합니다.    |
| Adblock 형식 규칙 | <code>{'\u007c\u007cblocked.example^'}</code> | 도메인 이름과 모든 하위 도메인을 차단합니다.  |

하나의 항목으로 해당 이름과 모든 하위 도메인을 차단하려면 Adblock 형식 `||name^`을 사용합니다.

꾸미기 필터와 잘못된 형식의 줄은 DNS 정책에 포함되지 않습니다. Status는 출처 오류를 보고하며 이전 유효 사본이 있는 목록이 실패하면 해당 사본을 유지합니다.

## 카탈로그 검색 \{#search-the-catalogs}

Lists 탭에서 **Add from Catalog**를 선택하여 AdGuard Home 목록 레지스트리와 pfBlockerNG 피드 카탈로그의 DNS 섹션을 검색합니다. Sinkhole은 검색을 열거나 **Refresh**를 선택할 때만 두 카탈로그를 가져옵니다. 카탈로그는 패키지에 포함되지 않으며 일정에 따라 다운로드되지 않습니다.

결과는 카드로 표시됩니다. 검색, 출처 및 관리자 컨트롤을 함께 사용하고 카테고리 칩을 선택한 다음 **Group by**를 **Category**와 **Maintainer** 사이에서 전환합니다. 카테고리 칩은 현재 검색, 출처 및 관리자 필터에 대한 개수를 표시하고, 관리자 메뉴는 일치하는 목록이 가장 많은 소유자를 먼저 표시합니다.

각 카드에는 목록 이름, 관리자 또는 카테고리, 출처 카탈로그, 두 줄 설명, 홈페이지 및 **Add** 또는 **Added** 상태가 표시됩니다. 카드에는 평가, 배지 또는 추천이 없습니다. **Add**를 선택하면 URL을 직접 입력한 출처와 동일하게 할당할 수 있는 일반 목록 행이 생성됩니다.

각 카드의 **Contents** 줄에는 **Domains**가 표시됩니다. 카탈로그 결과를 추가해도 카탈로그 이름은 변경되지 않습니다.

카탈로그 사본은 `/var/db`에 하루 동안 캐시됩니다. 새로 고침에 실패하면 마지막 정상 카탈로그 사본을 유지하고 Status에 가져오기 오류를 표시합니다.

Encrypted DNS, Tor 또는 VPN 우회 보호에 할당된 피드는 여기에 표시되지 않습니다. Bypass 탭의 **Add from Catalog**에서만 사용할 수 있습니다.

## 전역 허용 도메인 설정 \{#set-global-allowed-domains}

목록 및 카탈로그 패널 아래의 **Allowed Domains** 섹션에서 전역 예외를 정의합니다. 각 줄은 해당 도메인과 하위 도메인이 상속된 전역 목록을 통과하도록 허용합니다. 섹션 아래의 **Save**를 선택하여 페이지 전체 설정을 적용합니다.

전역 허용 도메인은 장치 및 네트워크 규칙 다음에 검사됩니다. 따라서 더 구체적인 장치나 네트워크 수준에서 이미 쿼리를 차단한 목록을 재정의할 수 없습니다.

## 업데이트 빈도 선택 \{#choose-the-update-frequency}

**General → Update Frequency** 설정은 예약된 DNS 목록 업데이트를 제어하고 IP 차단이 활성화된 경우에도 업데이트 일정을 제공합니다.

| 설정            | 일정                                    |
|---------------|---------------------------------------|
| Hourly        | 방화벽에서 안정적으로 임의 지정된 분에 매시간 한 번 실행합니다.  |
| Every 6 hours | 같은 안정적인 임의 지정 분에 6시간마다 실행합니다.         |
| Daily         | 해당 분에 매일 한 번 실행하며 예약 시간은 `00`입니다.     |
| Weekly        | 해당 분에 매주 일요일 한 번 실행하며 예약 시간은 `00`입니다. |

기본값은 `Daily`입니다. **Status → Update Now**는 저장된 일정을 변경하지 않고 수동 전체 업데이트를 시작합니다.

## 업데이트 중 수행되는 작업 \{#what-happens-during-an-update}

1. 제한이 적용된 다운로드 클라이언트로 활성화된 각 출처를 다운로드합니다.
2. 구문을 분석하고 정규화하여 임시 사본을 만듭니다.
3. 새 사본이 유효한 경우에만 저장된 사본을 원자적으로 대체합니다.
4. 현재 전역, 네트워크, 장치, 허용 도메인 및 알림 정책을 컴파일합니다.
5. 새 로컬 세대를 배포하고 Unbound 모듈이 이를 로드하도록 합니다.

새 차단 이름으로 정책 범위가 넓어지면 Sinkhole은 모듈이 세대를 로드할 때까지 기다린 다음 Unbound를 한 번 다시 로드하여 캐시된 응답을 지웁니다. 전체 가용성 및 대체 모델은 [업데이트 작동 방식](/docs/safety/how-updates-work)에서 설명합니다.

차단된 하위 트리에 공백이나 `0x7f`보다 큰 바이트를 포함한 특이하지만 유효한 DNS 레이블로 질의해도 Sinkhole은 응답에 와이어 형식 이름을 보존하고 정상적인 `0.0.0.0` 또는 `::` 응답을 반환합니다. 레이블이 호스트 이름 형식이 아니라는 이유만으로 SERVFAIL이 되지 않습니다.
