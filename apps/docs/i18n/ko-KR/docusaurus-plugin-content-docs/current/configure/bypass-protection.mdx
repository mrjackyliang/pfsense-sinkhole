선택한 클라이언트 인터페이스의 DNS 쿼리를 Sinkhole이 검사할 수 있는 경로에 유지합니다. 모든 보호 기능은 기본적으로 꺼져 있고 기본적으로 선택된 인터페이스가 없으며, 업그레이드해도 보호 기능이나 목록이 활성화되지 않습니다.

## 인터페이스 선택 \{#choose-the-interfaces}

보호 기능을 활성화하기 전에 **Firewall → Sinkhole → Bypass**를 열고 **Apply to** 인터페이스를 선택합니다. 이 하나의 선택이 페이지의 모든 설정에 적용됩니다. 보호 기능은 해당 인터페이스에서 클라이언트로부터 들어오는 트래픽만 검사하며, 방화벽 자체의 조회나 나가는 트래픽에는 영향을 주지 않습니다.

네트워크 및 장치 일치는 일반 Sinkhole 범위와 마찬가지로 해당 인터페이스의 현재 서브넷을 사용합니다. 선택한 서브넷 밖의 클라이언트는 Bypass DNS 응답을 받지 않습니다.

## 일반 DNS 리디렉션 \{#redirect-plain-dns}

선택한 인터페이스의 일반 TCP 및 UDP DNS 트래픽을 pfSense로 보내려면 **Redirect → Send port 53 to the firewall**을 선택합니다. Sinkhole은 원본 주소를 보존하므로 네트워크 및 장치 정책이 계속 적용됩니다.

리디렉션은 기존의 리스너 인식 대상과 예외를 유지합니다.

| 패밀리  | 대상                                                                   |
|------|----------------------------------------------------------------------|
| IPv4 | Resolver가 localhost에서 수신하는 동안에는 `127.0.0.1`, 그 외에는 인터페이스 IPv4 주소입니다. |
| IPv6 | 인터페이스 IPv6 주소이며 `::1`은 사용하지 않습니다.                                    |

- **Exempt Sources**는 계속 다른 리졸버에 연결됩니다.
- **Exempt Destinations**는 계속 DNS 트래픽을 수신하므로 다른 네트워크의 내부 리졸버를 지원합니다.

각 예외에는 한 줄에 IPv4 주소, IPv6 주소, CIDR 네트워크 또는 기존 pfSense 호스트/네트워크 별칭 하나를 입력할 수 있습니다. 저장된 예외가 유효하지 않으면 수정하거나 제거할 때까지 모든 리디렉션 규칙이 일시 중지됩니다. 리디렉션된 클라이언트는 여전히 Resolver의 액세스 제어 설정에서 허용되어야 합니다.

## 암호화 DNS 보호 \{#protect-encrypted-dns}

암호화 DNS 설정은 서로 독립적입니다.

- **TLS and QUIC**은 방화벽을 제외한 모든 대상으로 향하는 TCP 및 UDP 포트 853을 차단합니다.
- **Providers**는 종류가 **Encrypted DNS**인 활성화된 Bypass Lists의 이름과 주소를 차단합니다.
- **Firefox**는 `use-application-dns.net`과 그 하위 도메인에 `NXDOMAIN`으로 응답하여 Firefox의 자동 DNS over HTTPS 선택을 끕니다.
- **Private Relay**는 `mask.icloud.com`과 `mask-h2.icloud.com`에 `NXDOMAIN`으로 응답하여 호환되는 Apple 장치에 이 네트워크에서 Private Relay를 사용할 수 없음을 알립니다.

공급자 목록의 이름은 DNS에서 차단됩니다. 같은 목록의 IPv4 주소, IPv6 주소 및 CIDR은 독립적인 `sinkhole/bypass` 방화벽 앵커에서 모든 포트와 프로토콜에 대해 차단됩니다. Sinkhole은 테이블을 로드하기 전에 방화벽 인터페이스 주소와 DHCP 또는 PPP를 통해 얻은 주소를 포함한 게이트웨이 및 DNS 서버 주소를 해당 테이블에서 제거합니다.

허용된 도메인은 공급자 목록의 이름 차단보다 우선합니다. Firefox, Private Relay 또는 Discovery 응답은 목록 차단이 아니라 네트워크 신호이므로 허용된 도메인이 이를 재정의하지 않습니다.

## Resolver 검색 구성 \{#configure-resolver-discovery}

Discovery는 RFC 9462에 정의된 Designated Resolver Discovery 이름인 `_dns.resolver.arpa` 쿼리를 제어합니다.

| 선택                                        | 응답                                                               |
|-------------------------------------------|------------------------------------------------------------------|
| **Off**                                   | 쿼리를 변경하지 않습니다.                                                   |
| **Advertise the firewall's DNS over TLS** | `alpn=dot`, 포트 `853` 및 Resolver 인증서의 호스트 이름이 포함된 SVCB 응답을 반환합니다. |
| **Answer with no records**                | 빈 응답과 함께 `NOERROR`를 반환합니다.                                       |

**Advertise**를 사용하려면 DNS Resolver의 SSL/TLS 서비스가 사용 가능한 인증서 호스트 이름으로 활성화되어 있어야 합니다. Bypass 페이지는 해당 서비스의 활성화 여부를 표시하며, 사용할 수 없을 때 저장하면 명확한 검증 메시지와 함께 실패합니다.

Sinkhole이 활성화되고 **Apply to** 인터페이스가 선택된 상태에서 Discovery를 켜면 DNS Resolver의 **Custom options**에 다음 관리 블록이 추가됩니다:

```text
# Sinkhole: begin (managed by the Sinkhole package)
server:
local-zone: "_dns.resolver.arpa." transparent
# Sinkhole: end
```

Discovery를 끄거나 Sinkhole을 제거하면 이 블록이 삭제됩니다. Sinkhole은 **Custom options**의 다른 모든 줄을 변경하지 않습니다. 방화벽 자체를 포함하여 선택한 인터페이스 밖의 클라이언트는 `_dns.resolver.arpa`에 대해 계속 `NXDOMAIN`을 받습니다.

## 터널 방지 \{#protect-against-tunnels}

- **Tor → Block listed Tor relays**는 종류가 **Tor**인 활성화된 Bypass Lists를 적용합니다.
- **VPN → Block listed VPN providers**는 종류가 **VPN**인 활성화된 Bypass Lists를 적용합니다.
- **VPN → Block standard VPN ports**는 방화벽을 제외한 모든 대상으로 향하는 TCP 및 UDP `1194`, UDP `51820`, UDP `500` 및 `4500`, ESP를 차단합니다.

Tor 및 VPN 목록의 이름과 주소에는 암호화 DNS 공급자 목록과 동일한 DNS 및 방화벽 동작이 적용됩니다. 이러한 제어는 일반적인 대체 경로를 줄이지만 모든 암호화 터널이나 사용자 지정 터널을 식별하지는 않습니다.

## 카탈로그에서 추가 \{#add-from-catalog}

Bypass 탭에서 **Add from Catalog**를 열어 AdGuard Home 목록 레지스트리와 pfBlockerNG 피드 카탈로그의 DNS, IPv4 및 IPv6 섹션을 검색합니다. 결과에는 우회 피드만 표시되며 종류는 **Encrypted DNS**, **Tor** 또는 **VPN** 중 하나로 고정됩니다.

소스 카탈로그는 카탈로그를 열거나 **Refresh**를 선택할 때만 가져옵니다. 결과를 추가하면 활성화된 Bypass List가 생성되며 일반 목록 업데이트 일정을 따릅니다.

각 카드의 **Contents** 줄에는 **Domains**, **IPv4 addresses** 또는 **IPv6 addresses**가 표시됩니다. pfBlockerNG IPv4 또는 IPv6 결과를 추가하면 Sinkhole은 저장된 이름에 ` (IPv4)` 또는 ` (IPv6)`를 붙이며, 도메인 결과는 카탈로그 이름을 그대로 유지합니다.

## Bypass Lists 추가 \{#add-bypass-lists}

**Bypass Lists** 아래에서 **Add**를 선택한 다음 로컬 이름, 종류 및 HTTP 또는 HTTPS URL을 입력합니다. 새 행은 명시적으로 활성화할 때까지 비활성화됩니다.

각 소스는 한 줄에 하나의 항목을 허용합니다. 목록에는 도메인, IPv4 주소, IPv6 주소 및 CIDR을 함께 넣을 수 있으며 `#` 뒤의 텍스트는 주석입니다. 유효하지 않거나 너무 긴 줄은 건너뜁니다. 고정된 바이트 또는 허용 항목 제한을 초과하는 다운로드는 거부되고 마지막으로 정상인 복사본은 그대로 유지됩니다.

Bypass Lists는 다른 목록과 동일한 제한형 다운로드 클라이언트를 사용하여 구성된 목록 일정에 따라 업데이트됩니다. 가져오기에 실패하면 마지막으로 정상인 저장 복사본이 유지되고 **Status → Bypass Lists**에는 각 행의 항목, 마지막 가져오기 및 최근 오류가 표시됩니다. Sinkhole은 Bypass List를 번들로 제공하거나 추천하지 않습니다.

## 활성 상태 확인 \{#verify-the-active-state}

저장한 후 **Status → Bypass**를 열어 의도한 각 보호 기능이 `On`이고 선택한 인터페이스가 올바르며 Discovery가 켜져 있을 때 **Discovery Zone**이 `Present`인지 확인합니다. 방화벽 보호 기능의 **Firewall rules loaded**와 **Firewall rules current**가 `Yes`인지 확인합니다. Bypass Lists 테이블에는 저장된 항목 수와 마지막 가져오기가 표시됩니다.

일반 DNS 리디렉션은 Resolver 리스너 변경 후 기존의 2회 관찰 분 단위 조정을 유지합니다. `sinkhole/bypass` 앵커는 `sinkhole/ip`와 독립적으로 로드되므로 어느 기능을 비활성화해도 다른 기능에 영향을 주지 않습니다.
