`sinkhole/ip` pf 앵커에서 패키지가 관리하는 테이블을 사용해 DNS 정책과 별개로 선택한 IP 출발지 또는 목적지를 차단합니다.

## IP 차단을 사용하는 이유 \{#why-use-ip-blocking}

1. DNS 이름이 관련되지 않은 트래픽을 주소 또는 국가별로 처리합니다.
2. 선택한 인터페이스와 방향에 독립적으로 적용하므로 WAN 정책과 클라이언트 네트워크 정책을 다르게 구성할 수 있습니다.
3. 정규화된 마지막 정상 IP 사본을 유지하고 활성 테이블을 원자적으로 업데이트합니다.
4. 방화벽, 게이트웨이 및 DNS 주소가 출처 목록에 실수로 포함되지 않도록 보호합니다.

## 기능 활성화 \{#enable-the-feature}

**Firewall → Sinkhole → IP**를 열고 인터페이스와 방향을 선택한 후에만 **Enable**을 선택합니다. IP 및 국가 차단은 기본적으로 꺼져 있으며 General DNS 스위치에 의존하지 않습니다.

| 설정         | 동작                                                    |
|------------|-------------------------------------------------------|
| Interfaces | 선택한 도착 인터페이스에 규칙을 생성합니다.                              |
| Inbound    | 목록에 있는 출발지 주소에서 도착한 패킷을 차단하며, 일반적으로 WAN에 사용합니다.       |
| Outbound   | 목록에 있는 목적지 주소로 향하는 패킷을 차단하며, 일반적으로 클라이언트 네트워크에 사용합니다. |

앵커에는 `block drop in quick` 규칙만 있고 통과 규칙은 없습니다. Sinkhole은 pfSense의 초기 패키지 규칙 위치에서 앵커를 참조하므로 일반 pass-quick 규칙보다 먼저 차단이 실행됩니다. 페이지에는 IP 목록 및 카탈로그 패널이 먼저 표시되고, 그 아래에 페이지 전체 IP 및 국가 설정과 **Save**가 표시됩니다.

## IP 목록 추가 \{#add-ip-lists}

IP Lists 표 아래의 **Add**를 선택하여 IP 목록 편집기를 엽니다. 각 행은 HTTP 또는 HTTPS URL을 사용하고 IPv4, IPv6 또는 두 패밀리를 선택하며 출처의 활성화 여부를 제어합니다. 저장하면 IP 탭으로 돌아갑니다. 연필을 선택하거나 행을 두 번 클릭하여 편집합니다.

pfBlockerNG 피드 카탈로그의 IP 섹션에서도 목록을 찾을 수 있습니다.

유효한 줄은 개별 IPv4 또는 IPv6 주소와 CIDR 네트워크입니다. 잘못된 줄은 건너뛰고 개수를 기록합니다. 유효한 항목이 하나도 없는 다운로드는 마지막 정상 저장 사본을 대체하지 않습니다.

카탈로그는 검색을 열거나 새로 고칠 때만 다운로드되며 DNS 카탈로그 검색과 동일하게 마지막 정상 사본을 하루 동안 캐시합니다. 결과를 추가하면 평가나 추천이 없는 일반 IP 목록 행이 생성됩니다.

Encrypted DNS, Tor 및 VPN 우회 피드는 IP 카탈로그에서 제외되며 Bypass 탭에만 표시됩니다.

각 카드의 **Contents** 줄에는 **IPv4 addresses** 또는 **IPv6 addresses**가 표시됩니다. pfBlockerNG 결과를 추가하면 Sinkhole은 저장된 이름에 ` (IPv4)` 또는 ` (IPv6)`를 붙이고, 필요한 경우 기본 이름만 줄입니다.

## 국가 추가 \{#add-countries}

국가는 MaxMind GeoLite2 Country CSV 데이터에서 가져오며 두 글자 ISO 코드로 입력합니다. 해당 네트워크는 차단 패밀리 테이블에 추가됩니다.

- 국가를 선택하면 **MaxMind Account ID**가 필요합니다.
- **MaxMind License Key**는 관리자가 제공하고 pfSense 암호 필드처럼 저장되며 저장 후 다시 표시되지 않습니다.
- **Clear License Key**는 저장된 비밀 값을 명시적으로 제거합니다.

Sinkhole은 GeoLite2 아카이브를 검증하고 가져오며 최대 일주일에 한 번 업데이트합니다. 패키지는 MaxMind 계정이나 라이선스 키를 제공하지 않습니다.

## 주소 허용 및 보호 \{#allow-and-protect-addresses}

**IP Allowlist**에는 IPv4 또는 IPv6 주소, CIDR 네트워크 및 기존 호스트/네트워크 별칭을 입력할 수 있습니다. 허용 목록 범위는 테이블 파일을 쓰기 전에 병합된 차단 집합에서 제외됩니다.

Sinkhole은 다음 보호 주소도 자동으로 제외합니다.

- 방화벽에 할당된 모든 주소입니다.
- DHCP 또는 PPP를 통해 얻은 주소를 포함한 게이트웨이 주소입니다.
- DHCP 또는 PPP를 통해 얻은 주소를 포함한 DNS 서버 주소입니다.

제외 과정에서 차단된 CIDR을 더 작은 네트워크로 나눠 보호 주소만 통과시킬 수 있습니다.

## 앵커 이해 \{#understand-the-anchor}

패키지는 두 개의 영구 패밀리 테이블과 선택한 인터페이스 규칙을 포함한 `sinkhole/ip`를 직접 로드합니다. 목록 업데이트는 해당 앵커 내부의 테이블만 대체하고, Sync와 분 단위 검사는 전체 앵커를 로드할 수 있습니다.

앵커 내용은 일반적인 pfSense 필터 다시 로드 후에도 유지되며 기본 규칙 집합의 테이블 정리 대상이 아닙니다. IP 차단을 끄거나 Sinkhole을 제거하면 앵커를 비웁니다.

## 상태 검증 \{#verify-the-state}

**Status → IP and Country Blocking**에는 활성 상태, 인터페이스, 방향, 국가, 키 상태, 테이블 크기, 건너뛴 줄, 마지막 정상 업데이트, GeoLite2 업데이트 시간, 앵커 상태, 규칙 수 및 마지막 오류가 표시됩니다. 각 IP 목록 행에도 패밀리, 항목, 건너뛴 줄, 마지막 가져오기 및 오류가 표시됩니다.

앵커 상태가 **Out of Date**이면 로드된 텍스트나 테이블이 현재 설정과 일치하지 않는 것입니다. 분 단위 조정은 비어 있거나 변경된 앵커를 즉시 로드합니다. 관련 검사는 [문제 해결](/docs/operate/troubleshooting#ip-blocking-does-not-match-settings)에서 설명합니다.

IPv4 `/8` 또는 IPv6 `/16`보다 넓은 IP 목록 항목은 건너뛰고 개수에 포함하며, 경계인 `/8`과 `/16` 네트워크는 허용합니다. IP Allowlist는 차단을 줄이기만 하므로 이 제한을 적용하지 않습니다. 테이블을 쓰기 전에 Sinkhole은 항상 모든 방화벽 인터페이스의 IPv4 및 IPv6 주소, IP 차단에 선택된 인터페이스의 전체 서브넷, CARP 및 IP Alias 가상 주소, 구성된 게이트웨이와 DNS 서버를 제외합니다.
