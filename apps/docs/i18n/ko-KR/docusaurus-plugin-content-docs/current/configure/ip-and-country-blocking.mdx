`sinkhole/ip` pf 앵커에서 패키지가 관리하는 테이블을 사용해 DNS 정책과 별개로 선택한 IP 출발지 또는 목적지를 차단합니다.

## IP 차단을 사용하는 이유 \{#why-use-ip-blocking}

1. DNS 이름이 관련되지 않은 트래픽을 주소 또는 국가별로 처리합니다.
2. 선택한 인터페이스와 방향에 독립적으로 적용하므로 WAN 정책과 클라이언트 네트워크 정책을 다르게 구성할 수 있습니다.
3. 정규화된 마지막 정상 IP 사본을 유지하고 활성 테이블을 원자적으로 업데이트합니다.
4. 방화벽, 게이트웨이 및 DNS 주소가 출처 목록에 실수로 포함되지 않도록 보호합니다.

## 기능 활성화 \{#enable-the-feature}

**Firewall → Sinkhole → IP**를 열고 인터페이스와 방향을 선택한 후에만 **Enable**을 선택합니다. IP 및 국가 차단은 기본적으로 꺼져 있으며 General DNS 스위치에 의존하지 않습니다.

| 설정         | 동작                                                    |
|------------|-------------------------------------------------------|
| Interfaces | 선택한 도착 인터페이스에 규칙을 생성합니다.                              |
| Inbound    | 목록에 있는 출발지 주소에서 도착한 패킷을 차단하며, 일반적으로 WAN에 사용합니다.       |
| Outbound   | 목록에 있는 목적지 주소로 향하는 패킷을 차단하며, 일반적으로 클라이언트 네트워크에 사용합니다. |

앵커에는 `block drop in quick` 규칙만 있고 통과 규칙은 없습니다. Sinkhole은 pfSense의 초기 패키지 규칙 위치에서 앵커를 참조하므로 일반 pass-quick 규칙보다 먼저 차단이 실행됩니다. **Global**에서는 페이지에 IP 및 국가 설정이 표시되고, 패널 아래에 **Save**가 표시됩니다.

## 네트워크 및 장치별 차단 설정 \{#set-blocking-per-network-and-device}

탭 아래의 행에서 편집할 대상을 선택합니다. **All**, **Global**, 하나의 네트워크 또는 하나의 장치를 선택할 수 있습니다. 그 아래 줄에는 해당 설정이 적용되는 클라이언트가 표시됩니다. 각 선택에는 자체 설정만 표시되며, 더 넓은 범위의 설정은 표시되지 않습니다.

클라이언트는 존재하는 설정 중 가장 구체적인 설정을 따릅니다. 장치의 설정이 먼저이고, 그다음은 네트워크의 설정, 마지막은 Global의 설정입니다. Clients 탭에서 꺼진 네트워크나 장치는 건너뜁니다.

**Global**에만 있는 설정은 다음과 같습니다.

- Global의 차단이 적용되는 **Interfaces**.
- **MaxMind Account ID** 및 **MaxMind License Key**.

Global과 각 네트워크 또는 장치에는 **Enable**, **Directions**, **IP Lists**(해당 위치에서 사용하는 활성화된 출처), **Countries**, **IP Allowlist**가 있습니다. IP 목록 출처는 [Lists → IP](/docs/configure/lists#add-ip-lists)에서 추가, 활성화 및 업데이트하며, 활성화된 출처가 없으면 **IP Lists**에는 대신 **Open Lists** 링크가 있는 한 줄이 표시됩니다. 네트워크 또는 장치에서 **Outbound**는 해당 클라이언트가 목록에 있는 목적지에 도달하지 못하도록 차단하고, **Inbound**는 목록에 있는 출발지가 해당 클라이언트에 도달하지 못하도록 차단합니다. 네트워크 또는 장치의 국가는 Global의 MaxMind 계정을 사용합니다.

자체 설정이 없는 네트워크나 장치는 빈 양식 위에 "이 네트워크에는 설정이 없어 전역 설정이 적용됩니다."와 같은 한 줄을 표시합니다. 장치의 경우 해당 네트워크에 켜진 자체 설정이 있으면 이 줄에 그 네트워크 이름이 표시됩니다. 설정이 꺼진 네트워크나 장치는 대신 "꺼져 있어 전역 설정이 적용됩니다."를 표시하며, 같은 더 넓은 범위의 설정을 가리킵니다. 양식을 저장하면 설정이 생성되고, **Remove settings for this network** 또는 **Remove settings for this device**를 선택하면 설정이 삭제되어 더 넓은 범위의 설정이 다시 적용됩니다. Clients 탭에서 네트워크나 장치를 삭제하면 해당 설정도 삭제됩니다.

**All**에는 Global과 자체 설정이 있는 모든 네트워크 및 장치가 방향, 국가 및 IP 목록 수와 함께 나열됩니다. 행을 선택하여 편집합니다.

Sinkhole을 1.3.0으로 업그레이드하면 기존 설정은 Global에 유지되고 모든 네트워크와 장치에 복사됩니다. 이후 각 사본은 서로 독립적입니다. 네트워크의 인터페이스 또는 장치 식별자 중 하나의 인터페이스가 **Interfaces**에서 선택되어 있던 경우에만 사본이 켜집니다. 나머지 사본은 모두 꺼진 상태로 저장되므로 이전에 차단되지 않던 클라이언트가 차단되는 일은 없습니다.

Global도 모든 네트워크 및 장치처럼 자신의 IP 목록을 선택합니다. Sinkhole을 1.3.1로 업그레이드하면 자체 선택을 한 번도 저장하지 않은 Global은 그 시점에 활성화되어 있던 모든 IP 목록을 유지하므로, 편집하기 전까지는 아무것도 바뀌지 않습니다. 이후에 추가한 IP 목록은 Global, 네트워크 또는 장치가 선택하기 전까지 어디에서도 사용되지 않습니다.

설정이 켜진 각 네트워크 또는 장치는 `sinkhole/ip` 앵커에 자체 클라이언트 테이블을 가집니다. 장치의 주소는 해당 네트워크의 테이블과 Global의 테이블에서 제거되고, 네트워크의 서브넷은 Global의 테이블에서 제거되므로 클라이언트는 가장 구체적인 설정에 의해서만 차단됩니다.

## IP 목록 관리 \{#manage-ip-lists}

IP 목록 출처는 [Lists → IP](/docs/configure/lists#add-ip-lists)에서 추가, 편집, 활성화 및 삭제하며, 이곳에는 **Add from Catalog**와 각 목록의 **Used By** 개수도 있습니다. IP 탭에서는 각 컨텍스트가 사용할 활성화된 목록만 선택합니다. IP 목록에서 `/8`보다 넓은 IPv4 네트워크와 `/16`보다 넓은 IPv6 네트워크는 건너뜁니다. 허용 목록 항목은 차단을 줄이기만 하므로 이러한 접두사 제한은 IP Allowlist에는 적용되지 않습니다.

## 국가 추가 \{#add-countries}

국가는 MaxMind GeoLite2 Country CSV 데이터에서 가져오며 두 글자 ISO 코드로 입력합니다. 해당 네트워크는 차단 패밀리 테이블에 추가됩니다.

- 국가를 선택하면 **MaxMind Account ID**가 필요합니다.
- **MaxMind License Key**는 관리자가 제공하고 pfSense 암호 필드처럼 저장되며 저장 후 다시 표시되지 않습니다.
- **Clear License Key**는 저장된 비밀 값을 명시적으로 제거합니다.

Sinkhole은 GeoLite2 아카이브를 검증하고 가져오며 최대 일주일에 한 번 업데이트합니다. 패키지는 MaxMind 계정이나 라이선스 키를 제공하지 않습니다.

## 주소 허용 및 보호 \{#allow-and-protect-addresses}

**IP Allowlist**에는 IPv4 또는 IPv6 주소, CIDR 네트워크 및 기존 호스트/네트워크 별칭을 입력할 수 있습니다. 허용 목록 범위는 테이블 파일을 쓰기 전에 병합된 차단 집합에서 제외됩니다.

Sinkhole은 다음 보호 주소도 자동으로 제외합니다.

- 방화벽에 할당된 모든 주소입니다.
- DHCP 또는 PPP를 통해 얻은 주소를 포함한 게이트웨이 주소입니다.
- DHCP 또는 PPP를 통해 얻은 주소를 포함한 DNS 서버 주소입니다.

제외 과정에서 차단된 CIDR을 더 작은 네트워크로 나눠 보호 주소만 통과시킬 수 있습니다.

## 앵커 이해 \{#understand-the-anchor}

패키지는 두 개의 영구 패밀리 테이블과 선택한 인터페이스 규칙을 포함한 `sinkhole/ip`를 직접 로드합니다. 목록 업데이트는 해당 앵커 내부의 테이블만 대체하고, Sync와 분 단위 검사는 전체 앵커를 로드할 수 있습니다.

앵커 내용은 일반적인 pfSense 필터 다시 로드 후에도 유지되며 기본 규칙 집합의 테이블 정리 대상이 아닙니다. IP 차단을 끄거나 Sinkhole을 제거하면 앵커를 비웁니다.

## 상태 검증 \{#verify-the-state}

**Status → IP and Country Blocking**에는 활성 상태, 인터페이스, 방향, 국가, 키 상태, 테이블 크기, 건너뛴 줄, 마지막 정상 업데이트, GeoLite2 업데이트 시간, 앵커 상태, 규칙 수 및 마지막 오류가 표시됩니다. 각 IP 목록 행에도 패밀리, 항목, 건너뛴 줄, 마지막 가져오기 및 오류가 표시됩니다.

앵커 상태가 **Out of Date**이면 로드된 텍스트나 테이블이 현재 설정과 일치하지 않는 것입니다. 분 단위 조정은 비어 있거나 변경된 앵커를 즉시 로드합니다. 관련 검사는 [문제 해결](/docs/operate/troubleshooting#ip-blocking-does-not-match-settings)에서 설명합니다.

IPv4 `/8` 또는 IPv6 `/16`보다 넓은 IP 목록 항목은 건너뛰고 개수에 포함하며, 경계인 `/8`과 `/16` 네트워크는 허용합니다. IP Allowlist는 차단을 줄이기만 하므로 이 제한을 적용하지 않습니다. 테이블을 쓰기 전에 Sinkhole은 항상 모든 방화벽 인터페이스의 IPv4 및 IPv6 주소, IP 차단에 선택된 인터페이스의 전체 서브넷, CARP 및 IP Alias 가상 주소, 구성된 게이트웨이와 DNS 서버를 제외합니다.
