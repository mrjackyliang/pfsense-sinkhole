**Clients**에서 각 네트워크와 장치를 한 번만 정의한 다음 **Blocking**에서 각각이 차단할 항목을 선택합니다. 모든 클라이언트는 현재 위치에 맞는 정책을 받습니다.

## 네트워크와 장치를 사용하는 이유 \{#why-use-networks-and-devices}

1. 모든 클라이언트에 전역 규칙을 유지하면서 각 pfSense 인터페이스 또는 VLAN에 고유 정책을 제공합니다.
2. 별도 DNS 서버 없이 한 장치에 더 구체적인 판단을 제공합니다.
3. 전체 목록을 제거하지 않고 필요한 수준에서 허용 도메인으로 오탐을 수정할 수 있습니다.
4. 클라이언트 주소를 컴파일된 목록과 분리하므로 DHCP, 인접 장치 또는 인터페이스 변경 시 Unbound를 다시 로드하지 않습니다.

## 컨텍스트 \{#contexts}

Blocking, Services, SafeSearch, Alerts, Bypass 및 IP는 기본 탭 아래에 두 번째 탭 행을 공유합니다.

| 탭        | 페이지에서 편집하는 항목                                                |
|----------|--------------------------------------------------------------|
| All      | 없음. 읽기 전용 표에 자체 설정이 있는 모든 컨텍스트가 나열되며, 행을 선택하면 해당 컨텍스트가 열립니다. |
| Global   | 모든 클라이언트에 대한 설정입니다.                                          |
| Networks | 하나의 네트워크입니다. 네트워크 칩 행에서 대상을 선택합니다.                           |
| Devices  | 하나의 장치입니다. 장치 칩 행에서 대상을 선택하며, 검색 상자로 이름별로 칩을 좁힐 수 있습니다.      |

행 아래의 배너에 편집 대상이 표시됩니다. 예를 들어 **Editing: Network: IOT · applies to clients on IOT** 또는 **Editing: Device: Tablet · this device only**와 같습니다. 각 컨텍스트에는 자체 설정만 표시되며, 더 넓은 컨텍스트에서 상속된 항목은 양식에 나타나지 않습니다.

선택한 컨텍스트는 다른 컨텍스트를 고를 때까지 탭을 이동해도 유지됩니다. 비활성화된 네트워크나 장치도 편집할 수 있으며, 다시 활성화될 때까지 해당 설정이 어떤 클라이언트에도 적용되지 않는다는 경고가 표시됩니다.

## 네트워크 정의 \{#define-networks}

**Firewall → Sinkhole → Clients**를 열고 Networks 표 아래의 **Add**를 선택합니다. 편집기는 기본적으로 LAN이나 사용 가능한 첫 번째 비 WAN 인터페이스를 선택하며 이미 네트워크가 있는 인터페이스는 제외합니다. 클라이언트 주소가 해당 인터페이스의 현재 IPv4 또는 IPv6 서브넷 중 하나에 있으면 그 네트워크에 속합니다.

각 네트워크 행에는 인터페이스와 **Enabled** 확인란이 있습니다. 저장하면 Clients로 돌아갑니다. 연필을 선택하거나 행을 두 번 클릭하여 편집합니다. 장치가 네트워크 사이를 이동하면 현재 주소와 일치하는 네트워크의 정책을 받습니다.

## 장치 정의 \{#define-devices}

Devices 표 아래의 **Add**를 선택하고 이름을 입력한 다음 식별자 행을 하나 이상 추가합니다. 각 행에는 유형과 해당 유형에 맞는 값이 있습니다.

| 식별자 유형              | 장치에 사용하는 주소                          |
|---------------------|--------------------------------------|
| IP address          | 구성된 IPv4 또는 IPv6 주소입니다.              |
| DHCP static mapping | 구성된 주소와 해당 매핑의 MAC에서 현재 관찰된 주소입니다.   |
| MAC address         | 해당 MAC의 현재 ARP, NDP 및 DHCP 임대 주소입니다. |

**Add Identifier**와 휴지통 버튼으로 행을 관리합니다. 장치에는 식별자가 하나 이상 있어야 합니다. 어떤 식별자를 통해 찾은 주소든 동일한 장치로 확인되므로 하나의 설정 세트와 활성 상태를 공유합니다. 저장하면 Clients로 돌아갑니다. 연필을 선택하거나 행을 두 번 클릭하여 편집합니다. DNS 차단에 활성화된 네트워크 또는 장치가 있거나 Bypass DNS 보호가 클라이언트 식별을 필요로 할 때만 백그라운드 작업이 현재 서브넷과 장치 주소를 매분 새로 고칩니다. 패키지 Sync도 같은 조건에서만 이 새로 고침을 시작합니다.

Clients에서 네트워크나 장치를 삭제하면 해당 Blocking, Services, SafeSearch, Bypass 및 IP 설정도 삭제됩니다.

## 목록과 허용 도메인 선택 \{#choose-lists-and-allowed-domains}

**Firewall → Sinkhole → Blocking**을 열고 컨텍스트를 선택합니다.

- **Global**은 장치 및 네트워크 판단 후 모든 클라이언트에 적용되는 목록을 선택하며, 전역 허용 도메인을 보관합니다.
- **Networks**는 선택한 네트워크의 클라이언트에 대한 추가 목록과 허용 도메인을 선택합니다.
- **Devices**는 선택한 장치에 대한 추가 목록과 허용 도메인을 선택합니다.

각 컨텍스트에는 **Lists** 상자와 한 줄에 도메인 하나씩 입력하는 **Allowed Domains** 상자가 있습니다. **Save**를 선택하면 해당 컨텍스트에 적용됩니다. 목록이 많으면 **Lists** 상자의 아래쪽 모서리를 끌어 더 길게 만들 수 있습니다. 목록 자체는 [Lists](/docs/configure/lists) 탭에서 추가하고 편집합니다.

**All**은 목록이나 허용 도메인이 있는 컨텍스트마다 한 행을 표시하며, 목록 이름과 허용 도메인 수를 함께 보여 줍니다.

## 판단 순서 \{#decision-order}

일치하는 수준 중 가장 구체적인 수준이 다음의 정확한 순서로 각 쿼리를 판단합니다.

1. **Device allowed domains** — 쿼리 이름이 일치하면 즉시 허용합니다.
2. **Device lists** — 선택한 장치 목록이 일치하면 즉시 차단합니다.
3. **Network allowed domains** — 네트워크 예외가 일치하면 즉시 허용합니다.
4. **Network lists** — 선택한 네트워크 목록이 일치하면 즉시 차단합니다.
5. **Global allowed domains** — 전역 예외가 일치하면 즉시 허용합니다.
6. **Global lists** — 전역 목록이 일치하면 차단합니다.

어떤 단계에서도 판단하지 않으면 쿼리가 통과합니다. 활성화된 네트워크 또는 장치와 일치하지 않는 클라이언트는 Global 단계만 적용받습니다. 한 수준의 허용 도메인은 덜 구체적인 수준에서 상속된 목록을 재정의하지만, 이미 판단한 더 구체적인 수준의 목록은 재정의하지 않습니다.

## 허용 도메인 동작 \{#allowed-domain-behavior}

각 허용 도메인 항목은 정확한 도메인과 모든 하위 도메인에 적용됩니다. 예를 들어 `service.example`을 허용하면 해당 수준에서 `api.service.example`도 허용합니다.

- 장치 예외는 가장 먼저 검사되므로 장치, 네트워크 및 전역 목록을 통과시킬 수 있습니다.
- 네트워크 예외는 네트워크 및 전역 목록을 통과시킬 수 있지만 장치 목록의 판단은 재정의할 수 없습니다.
- 전역 예외는 전역 목록만 통과시킬 수 있습니다.

## 주소 충돌 \{#address-conflicts}

같은 장치의 여러 식별자가 동일한 주소에 도달해도 충돌이 발생하지 않습니다. 서로 다른 두 장치가 같은 현재 주소를 사용하면 Clients 표에서 먼저 나오는 장치가 우선합니다. Clients 표와 **Status → Clients**는 영향을 받는 각 행의 **Conflict** 아래에 주소를 표시하므로 순서나 식별자를 수정할 수 있습니다.

## 네트워크 또는 장치 검증 \{#verify-a-network-or-device}

1. `/usr/local/sbin/sinkhole --refresh-clients`를 실행하거나 분 단위 새로 고침을 기다립니다.
2. **Status → Clients**를 열고 네트워크의 현재 서브넷과 장치의 현재 주소를 확인합니다.
3. 해당 네트워크 또는 장치의 클라이언트에서 이름을 쿼리하고 결과를 위 판단 순서와 비교합니다.
4. 장치별 동작을 사용하기 전에 주소 충돌이 없는지 확인합니다.
