pfSense 자체 페이지에서 제공하지 않는 DNS Resolver 설정은 **Firewall → Sinkhole → General**의 **Resolver** 섹션에서 사용합니다.

## Resolver 설정을 사용하는 이유 \{#why-use-resolver-settings}

1. 직접 작성한 사용자 지정 옵션 없이도 pfSense의 DNS 리바인딩 보호 뒤에서 Plex 같은 서비스가 계속 작동합니다.
2. 업스트림 서버가 느리거나 다운되어도 캐시된 응답으로 DNS를 빠르게 유지합니다.
3. 이 줄들을 Sinkhole이 이미 소유한 같은 관리 블록에 두므로 DNS Resolver의 **Custom options** 상자를 비워 둘 수 있습니다.

## Rebind Exceptions \{#rebind-exceptions}

pfSense의 DNS 리바인딩 보호는 사설 주소를 가리키는 공개 응답을 버립니다. Plex(`plex.direct`) 같은 서비스는 의도적으로 사설 주소로 응답하므로 해당 이름에는 예외가 필요합니다.

한 줄에 도메인 하나를 입력합니다. 각 항목은 도메인과 모든 하위 도메인에 적용됩니다. **System → Advanced → Admin Access → DNS Rebind Check**가 비활성화되지 않은 한 보호가 켜져 있으며, 이 검사가 비활성화되어 있으면 예외는 아무것도 바꾸지 않습니다.

## 만료된 응답 \{#expired-answers}

**Services → DNS Resolver → Advanced Settings**에 있는 pfSense의 **Serve Expired** 설정을 사용하면 Resolver가 만료된 캐시 항목을 새로 고치는 동안 그 항목으로 응답할 수 있습니다. 관련 설정 두 가지는 여기에서만 사용할 수 있습니다.

| 필드                      | Unbound 설정                     | 설명                                              |
|-------------------------|--------------------------------|-------------------------------------------------|
| Expired Answer Lifetime | `serve-expired-ttl`            | 만료된 응답을 계속 제공할 수 있는 시간(초)입니다. `0`은 제한 없음을 뜻합니다. |
| Expired Answer Wait     | `serve-expired-client-timeout` | 새 응답을 먼저 기다리는 시간(밀리초)입니다. `0`이면 즉시 캐시에서 응답합니다.  |

두 설정 모두 **Serve Expired**가 켜져 있을 때만 적용되며, General 탭에 켜져 있는지 표시됩니다. 빈 필드는 Resolver의 기본값을 유지합니다. 같은 Advanced Settings 페이지에는 **Prefetch Support**와 **Prefetch DNS Key Support**도 있습니다.

## 설정이 적용되는 시점 \{#when-the-settings-apply}

설정은 Sinkhole이 활성화되어 있고 DNS Resolver 통합이 활성 상태일 때 적용됩니다. Sinkhole은 이 설정을 DNS Resolver의 **Custom options** 끝에 있는 관리 블록에 기록합니다.

```text
# Sinkhole: begin (managed by the Sinkhole package)
server:
private-domain: "plex.direct"
serve-expired-ttl: 86400
serve-expired-client-timeout: 0
# Sinkhole: end
```

Sinkhole을 비활성화하거나 패키지를 제거하면 블록과 그 안의 모든 줄이 삭제됩니다. Sinkhole은 **Custom options**에 있는 관리자의 줄을 절대 변경하지 않습니다.
