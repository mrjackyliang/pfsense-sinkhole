안정 GitHub 릴리스 패키지에서 Sinkhole을 설치하거나 업데이트한 다음 pfSense가 모든 WebGUI 탭을 등록했는지 확인합니다.

## 요구 사항 \{#requirements}

- **Administrator shell** — pfSense 셸에 대한 SSH 또는 콘솔 액세스가 필요합니다. **Diagnostics → Command Prompt**에서도 단일 명령을 실행할 수 있습니다.
- **HTTPS access to GitHub** — 방화벽에서 GitHub Releases의 패키지와 체크섬을 다운로드할 수 있어야 합니다.
- **DNS Resolver** — Sinkhole DNS 통합을 활성화하기 전에 pfSense DNS Resolver가 활성화되어 있어야 합니다.
- **Available Python slot** — pfBlockerNG DNSBL 또는 다른 Python 스크립트가 Resolver의 단일 모듈 슬롯을 소유하고 있으면 안 됩니다.
- **Current backup** — 비공식 패키지를 설치하기 전에 **Diagnostics → Backup & Restore**에서 `config.xml`을 다운로드하는 것이 좋습니다.

:::warning

Sinkhole은 Netgate 패키지 저장소가 아닌 GitHub에서 설치하므로 Netgate가 패키지를 검토하거나 지원하지 않습니다.

:::

## 릴리스 확인 \{#check-the-release}

[GitHub Releases 페이지](https://github.com/mrjackyliang/pfsense-sinkhole/releases)는 안정 이름과 버전이 포함된 이름의 패키지 파일을 게시합니다. 이 페이지에서 사용하는 안정 파일은 다음과 같습니다.

| 파일                                | 용도                           |
|-----------------------------------|------------------------------|
| `pfSense-pkg-Sinkhole.pkg`        | 설치할 수 있는 최신 Sinkhole 패키지입니다. |
| `pfSense-pkg-Sinkhole.pkg.sha256` | 안정 패키지의 해시 전용 SHA-256 값입니다.  |

## 체크섬 검증 \{#verify-the-checksum}

안정 패키지와 안정 `.sha256` 파일을 `/tmp`에 다운로드한 다음 출력된 두 값을 비교합니다.

```shell
cd /tmp
fetch https://github.com/mrjackyliang/pfsense-sinkhole/releases/latest/download/pfSense-pkg-Sinkhole.pkg
fetch https://github.com/mrjackyliang/pfsense-sinkhole/releases/latest/download/pfSense-pkg-Sinkhole.pkg.sha256
sha256 -q pfSense-pkg-Sinkhole.pkg
cat pfSense-pkg-Sinkhole.pkg.sha256
```

다운로드한 패키지가 손상되지 않았다면 두 값이 일치합니다. 확인한 로컬 파일은 `pkg add -f /tmp/pfSense-pkg-Sinkhole.pkg`로 설치할 수 있습니다.

## 설치 또는 업데이트 \{#install-or-update}

같은 명령으로 Sinkhole을 처음 설치하거나 이전 버전을 업데이트하거나 현재 버전을 다시 설치할 수 있습니다.

```shell
pkg add -f https://github.com/mrjackyliang/pfsense-sinkhole/releases/latest/download/pfSense-pkg-Sinkhole.pkg
```

`-f` 플래그가 필요한 이유는 pfSense 2.8의 `pkg` 버전이 동일한 안정 URL의 업데이트를 건너뛸 수 있기 때문입니다. 이 플래그는 패키지의 일반 설치 및 업그레이드 훅도 유지합니다.

## WebGUI 확인 \{#confirm-the-webgui}

1. **Firewall → Sinkhole**을 엽니다.
2. **General**, **Lists**, **Services**, **Scopes**, **Alerts**, **Bypass**, **IP**, **Status**, **About**이 표시되는지 확인합니다.
3. DNS Resolver가 활성화되고 Python 스크립트 슬롯을 사용할 수 있을 때까지 **General → Enable**을 꺼 둡니다.
4. **About**을 열고 표시된 패키지 버전이 설치한 릴리스와 일치하는지 확인합니다.

Netgate 저장소 외부에서 설치한 패키지는 pfSense의 **Installed Packages** 페이지에 나타나지 않습니다. 따라서 업데이트와 제거에는 여기와 [패키지 수명 주기](/docs/reference/package-lifecycle)에 설명된 셸 명령을 사용합니다.

## 설치 실패 시 \{#if-installation-fails}

- **Not found or no package asset** — 최신 GitHub 릴리스에 `pfSense-pkg-Sinkhole.pkg`가 포함되어 있는지 확인합니다.
- **Checksum differs** — 설치된 버전을 유지하고 릴리스에서 두 안정 파일을 다시 다운로드합니다.
- **DNS, TLS, or certificate error** — pfSense가 `github.com`을 확인하고 HTTPS로 연결할 수 있으며 시스템 시간이 올바른지 확인합니다.
- **Wrong ABI** — 최신 릴리스를 설치합니다. 현재 패키지는 `FreeBSD:*` ABI로 다시 빌드하지만 이전 아티팩트는 그렇지 않을 수 있습니다.

탭이 나타나면 [Sinkhole 설정](/docs/first-run)을 계속 진행합니다.
