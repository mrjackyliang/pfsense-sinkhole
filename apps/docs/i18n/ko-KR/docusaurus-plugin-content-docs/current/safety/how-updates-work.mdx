Sinkhole은 다운로드를 DNS 서비스와 분리하므로 원격 출처가 Resolver의 쿼리 경로에 들어가지 않습니다.

## DNS 목록 업데이트 흐름 \{#dns-list-update-flow}

활성화된 각 DNS 목록에 대해 Sinkhole은 다음 작업을 수행합니다.

1. 시간과 크기 한도를 적용하여 출처를 다운로드합니다.
2. 지원되는 hosts, 일반 도메인 및 adblock 형식 항목을 임시 정규화 집합으로 구문 분석합니다.
3. 새 내용이 유효성 검사를 통과한 후에만 저장된 사본을 원자적으로 대체합니다.
4. 로컬에 저장된 데이터에서 전역, 네트워크, 장치, 허용 도메인 및 알림 정책을 컴파일합니다.
5. 이미 로드된 Python 모듈이 찾을 수 있도록 `/var/unbound` 아래에 세대를 배포합니다.

다운로드, 구문 분석 또는 유효성 검사에 실패하면 마지막 정상 사본을 대체하지 않고 오류를 기록합니다. 시도하는 동안 DNS는 배포된 로컬 세대를 계속 사용합니다.

## 배포 및 Resolver 캐시 \{#deployment-and-resolver-caches}

Unbound 모듈은 쿼리 사이에 새 매니페스트를 확인하고 참조된 모든 파일이 준비된 후에만 완전한 세대로 전환합니다. 각 단계를 확인할 수 있도록 Status는 컴파일, 배포 및 로드된 세대 식별자를 구분하여 표시합니다.

정책에 차단 이름이 추가되거나 차단된 하위 트리 범위가 넓어지면 Sinkhole은 모듈이 새 세대를 보고할 때까지 기다린 다음 Unbound를 한 번 다시 로드합니다. 다시 로드하면 `flush_zone`만으로 **Serve Expired** 대상에 남을 수 있는 메시지 및 RRset 캐시가 지워집니다.

## 클라이언트 맵 새로 고침 \{#client-map-refreshes}

네트워크 서브넷과 장치 주소는 컴파일된 도메인 데이터와 별도로 저장됩니다. DNS 차단에 활성화된 네트워크 또는 장치 범위가 있거나 Bypass DNS 보호가 클라이언트 식별을 필요로 할 때 Sinkhole은 Unbound를 다시 로드하지 않고 이 클라이언트 맵을 매분 새로 고칩니다.

패키지 Sync도 같은 조건에서만 이 새로 고침을 시작합니다. 따라서 목록 업데이트 외부에서 발생하는 인터페이스, DHCP 임대, 인접 장치 및 정적 매핑 변경이 반영됩니다. 모든 Sinkhole 기능을 끄면 다음 Sync가 런타임 클라이언트 맵과 선택적 RAM 디스크 미러를 제거합니다.

## IP 및 국가 업데이트 흐름 \{#ip-and-country-update-flow}

IP 및 국가 차단이 활성화되면 동일한 예약 또는 수동 업데이트가 활성화된 IP 목록을 다운로드하고 해당하는 GeoLite2 데이터를 새로 고칩니다. Sinkhole은 각 주소 패밀리를 구문 분석하고 병합하며 관리자의 허용 목록과 보호된 방화벽 주소를 제외한 다음 패밀리 테이블 파일을 원자적으로 대체합니다.

기존 `sinkhole/ip` 앵커는 정상 업데이트 후 `pfctl -T replace`를 통해 테이블만 대체할 수 있습니다. 규칙이나 테이블이 없거나 다르면 Sync와 분 단위 무결성 검사에서 전체 앵커를 로드합니다.

## 일정 및 잠금 \{#schedules-and-locking}

기본 목록 업데이트 빈도는 Daily입니다. Hourly, Every 6 hours, Daily, Weekly 일정은 안정적으로 임의 지정된 분 값을 사용하므로 저장할 때마다 방화벽의 작업 시간이 변경되지 않습니다.

DNS 목록 업데이트, IP/국가 업데이트, 카탈로그 관련 적용 작업 및 패키지 자체 업데이트는 `/var/run/sinkhole-update.lock`을 통해 조정됩니다. 패키지 Update 작업은 설치된 패키지를 목록 업데이트 도중에 변경하지 않고 활성 목록 업데이트가 끝날 때까지 기다립니다.

## 카탈로그 새로 고침은 별도 수행 \{#catalog-refreshes-are-separate}

AdGuard Home 레지스트리와 pfBlockerNG 피드 카탈로그는 카탈로그 검색을 열거나 **Refresh**를 선택할 때만 가져옵니다. 마지막 정상 캐시는 하루 동안 다시 사용할 수 있으며 가져오기에 실패해도 구성된 목록을 변경하지 않습니다.

카탈로그 결과는 정책이 아니라 검색용 메타데이터입니다. 결과를 일반 구성 목록으로 추가하고 정상 업데이트 흐름을 완료한 후에만 DNS 또는 IP 차단에 영향을 줍니다.

## 업데이트 상태 확인 \{#read-update-state}

**Firewall → Sinkhole → Status**를 열고 출처 오류, 저장된 항목 수, 업데이트 실행 플래그 및 컴파일, 배포, 로드된 세대를 비교합니다. IP 차단의 경우 테이블 수와 `sinkhole/ip` 앵커 상태도 비교합니다.

패키지 버전 확인 및 자체 업데이트 동작은 [업데이트](/docs/reference/updates)를 참조합니다. 한 단계에서 오류를 보고하거나 대기 상태가 계속되면 [문제 해결](/docs/operate/troubleshooting)을 사용합니다.
