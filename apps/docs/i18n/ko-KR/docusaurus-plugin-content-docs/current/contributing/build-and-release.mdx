루트 Nova 워크스페이스를 통해 Sinkhole을 빌드, 테스트 및 릴리스하여 패키지와 문서에 동일한 검증 워크플로를 적용합니다.

## 사전 요구 사항 \{#prerequisites}

- 루트 `package.json`의 Node.js 버전 범위와 `packageManager` 필드에서 선택한 npm 버전을 사용합니다.
- 최종 `.pkg` 빌드에는 pfSense ports 체크아웃이 있는 FreeBSD를 사용합니다.
- 설치, 업그레이드, 차단 및 제거 검증에는 일회용 pfSense 랩을 사용합니다.

패키징하기 전에 `PFSENSE_PORTS_DIR`을 pfSense FreeBSD ports 체크아웃으로 설정합니다. 체크아웃에는 `Mk/bsd.port.mk`가 있어야 하며 임시 빌드 복사본을 둘 대상 `sysutils/pfSense-pkg-Sinkhole`이 비어 있어야 합니다.

## 종속성 설치 \{#install-dependencies}

저장소 루트에서 실행합니다.

```sh
npm install
```

Nova는 `nova.config.json`에서 워크스페이스를 읽습니다. 더 좁은 범위의 패키지 명령을 의도적으로 진단하는 경우가 아니면 루트에서 워크스페이스 명령을 실행합니다.

## 모든 변경 사항 검사 \{#check-every-change}

```sh
npm run check
npm run build
```

`npm run check`는 루트, 패키지 및 문서 워크스페이스의 린트, 타입 검사 및 테스트를 실행합니다. `npm run build`는 pfSense port를 스테이징하고 `build/` 아래에 프로덕션 문서 빌드를 만듭니다.

호스트에 사용할 수 있는 PHP 런타임이 없으면 `SINKHOLE_SKIP_PHP_TESTS=1 npm run check`가 가능한 모든 검사를 실행하지만 릴리스 전에 필요한 패키지 테스트를 대체하지는 않습니다. 패키지 변경에는 저장소 규칙에 설명된 오프라인 PHP 및 Python 제품군, 복원 제품군, 언어 간 제품군도 필요합니다.

## 릴리스 패키지 빌드 \{#build-the-release-package}

`npm run build` 후 FreeBSD에서 최종 패키징 명령을 실행합니다.

```sh
npm run deploy
```

배포 스크립트는 구성된 ports 체크아웃에서 `make package`를 실행하고 `FreeBSD:*`를 사용해 매니페스트를 vital로 다시 빌드하며 두 속성을 모두 검증한 다음 버전 및 안정 이름의 `.pkg` 파일과 SHA-256 파일을 `packages/sinkhole/build/release/` 아래에 씁니다.

이 명령은 FreeBSD가 아닌 호스트 또는 `PFSENSE_PORTS_DIR`이 없는 환경에서 의도적으로 실패합니다. 다른 운영 체제에서 빌드한 패키지를 릴리스 아티팩트 대신 사용하지 마십시오.

## 변경 사항 기록 \{#record-the-change}

변경 사항이 반영될 때 Nova 변경 로그 워크플로를 사용합니다.

```sh
npm run changelog
```

영향을 받는 워크스페이스와 사용자에게 보이는 변경 사항에 맞는 릴리스 노트 범주를 선택합니다. 변경 사항마다 일관된 항목 하나를 유지하고 저장소의 명령형 현재 시제 릴리스 노트 스타일을 사용합니다.

## 릴리스 만들기 \{#cut-a-release}

1. 깨끗한 릴리스 후보에서 `npm run check`와 `npm run build`를 실행합니다.
2. `nova utility changelog --release`를 실행하여 버전을 선택하고 패키지 버전을 업데이트하며 변경 로그를 작성합니다.
3. 구성된 FreeBSD 빌더에서 `npm run deploy`를 실행합니다.
4. 일회용 pfSense 랩에서 아티팩트를 설치 및 업그레이드하고 차단을 테스트한 뒤 제거합니다.
5. 버전이 지정된 패키지와 안정 이름의 패키지 및 체크섬 아티팩트를 포함해 GitHub 릴리스를 게시합니다.

릴리스를 게시하면 패키지 아티팩트 워크플로와 문서 배포 워크플로가 시작됩니다. 전체 랩 검증을 통과하기 전에는 pfSense 릴리스를 지원 대상으로 나열하지 않습니다.

## 문서 변경 사항 \{#documentation-changes}

번역 페이지에서 안정적인 앵커를 유지할 수 있도록 `{#build-and-release}`와 같은 명시적인 영어 제목 ID를 사용합니다. `npx nova recipe misc fix-markdown-tables`로 Markdown 표를 포맷한 다음 동일한 루트 검사 및 빌드 명령을 실행합니다.

영어 페이지가 17개 번역 로캘의 원본입니다. 제품 이름은 번역하지 않고 코드, 경로 및 영어 앵커를 정확히 유지하며 아직 구현되지 않은 기능을 약속하지 않습니다.
