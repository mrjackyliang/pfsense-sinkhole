Use **Firewall → Sinkhole → SafeSearch** to keep search engines in their safe modes for a network or device, without changing any browser or device setting.

## Why Use SafeSearch? \{#why-use-safesearch}

1. Locks safe mode at the network, so a signed-out browser, a new device, or a private window still gets filtered results.
2. Covers every Google country domain, not just `google.com`, so switching to `google.co.uk` doesn't get around it.
3. Uses the same Global, network, and device contexts as block lists, so a kids' VLAN can get SafeSearch while the rest of the network doesn't.

## Choose a Context and Engines \{#choose-a-context-and-engines}

1. Pick **Global**, a network, or a device in the [context row](/docs/configure/scopes#contexts) under the main tabs.
2. Tick each engine to lock, and choose **Moderate** or **Strict** for YouTube.
3. Select **Save**.

A network or device must exist on **Clients** before it appears in the context row. Saving looks up each safe host right away and applies the change in the background. **All** lists every context that locks at least one engine; select a row to edit that context.

## How Contexts Combine \{#how-contexts-combine}

A client receives every engine chosen for **Global**, for the network it is on, and for its device, combined. When YouTube appears with both levels, **Strict** wins.

SafeSearch applies after blocking. A name that a list or blocked service blocks for the client stays blocked, and allowed domains don't turn SafeSearch off. Like any client outside every network and device, the firewall's own lookups receive the engines chosen for **Global**.

## How the Answer Works \{#how-the-answer-works}

For a chosen engine, Sinkhole answers the engine's name with a CNAME to the safe host plus the safe host's addresses, the same answer a hand-written Unbound view gives. Other record types, such as HTTPS records, receive only the CNAME, so a browser can't use hints that lead around the safe host.

Sinkhole looks up each safe host's addresses when you save and on every list update, and it keeps the last good addresses when a lookup fails. An engine whose safe host has never returned an address is blocked for its contexts until a lookup succeeds.

SafeSearch answers are never stored in the Resolver's cache, so one client's answer never reaches a client outside that context.

## Verify SafeSearch \{#verify-safesearch}

1. Open **Status** and confirm the **SafeSearch** panel lists each safe host with addresses and no error.
2. From a client in the context, look up an engine name, such as `nslookup www.google.com`, and confirm the answer names the safe host.
3. From a client outside the context, confirm the same lookup returns the engine's normal answer.

Encrypted DNS that a client sends elsewhere skips every DNS policy, including SafeSearch. [Bypass Protection](/docs/configure/bypass-protection) keeps selected interfaces on Sinkhole's DNS path.
