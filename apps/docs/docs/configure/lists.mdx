Add list sources you trust and let Sinkhole keep normalized, last-good copies on the firewall for immediate DNS use.

## Why Use Saved Lists? \{#why-use-saved-lists}

1. Keeps DNS independent from a list host so a slow or failed download doesn't interrupt name resolution.
2. Downloads each source once so the same saved copy can serve Global, every network, and every device.
3. Preserves the previous valid copy when a new download or parse fails so broken input doesn't replace working policy.
4. Updates lists in the background so a Resolver restart or reload never waits for the network.

## Choose a List Kind \{#choose-a-list-kind}

Lists is the one place where every list source is added, edited, enabled, and deleted. The row under the tabs switches between three kinds:

| Kind   | Holds                                       | Selected on                                                                        |
|--------|---------------------------------------------|------------------------------------------------------------------------------------|
| DNS    | Block lists of domain names.                | [Blocking](/docs/configure/scopes#choose-lists-and-allowed-domains)                |
| Bypass | Encrypted DNS, Tor, and VPN provider lists. | [Bypass](/docs/configure/bypass-protection#set-protections-per-network-and-device) |
| IP     | IPv4 and IPv6 address and network lists.    | [IP](/docs/configure/ip-and-country-blocking#set-blocking-per-network-and-device)  |

Each kind has its own table, **Add**, **Add from Catalog**, and repair panel for invalid saved rows. Lists has no Global, network, or device row; those choices belong to the tabs that use the lists.

Every table has a **Used By** column that counts Global plus every network and device whose settings select the list. A new list of any kind blocks nothing until a context selects it.

## Add a List by URL \{#add-a-list-by-url}

Open **Firewall → Sinkhole → Lists → DNS**, select **Add** below the block-list table, then complete **Add Block List** on the editor page:

| Field   | Description                                        |
|---------|----------------------------------------------------|
| Name    | Local label shown on Blocking, Alerts, and Status. |
| URL     | HTTP or HTTPS source without embedded credentials. |
| Enabled | Downloads the source so Blocking can use it.       |

Saving returns to the Lists tab and starts the same validated background apply path. Select a row's pencil or double-click the row to edit it. A disabled row remains configured but is muted in the table and isn't used by the updater or compiled policy.

Which DNS lists apply to Global, a network, or a device is chosen on [Blocking](/docs/configure/scopes#choose-lists-and-allowed-domains).

## Accepted DNS Formats \{#accepted-dns-formats}

Sinkhole accepts the standard forms below and normalizes valid names into one saved domain set:

| Format             | Example                                       | Behavior                                           |
|--------------------|-----------------------------------------------|----------------------------------------------------|
| Hosts file         | `0.0.0.0 blocked.example`                     | Blocks exactly each domain name after the address. |
| Plain domain list  | `blocked.example`                             | Blocks exactly the domain name on each line.       |
| Adblock-style rule | <code>{'\u007c\u007cblocked.example^'}</code> | Blocks the domain name and every subdomain.        |

Use the adblock-style `||name^` form when you want one entry to block the name and every subdomain.

Cosmetic filters and malformed lines don't become DNS policy. Status reports source errors, while a failed list with a previous valid copy keeps that copy.

When a blocked subtree is queried with an unusual but valid DNS label, including a space or a byte above `0x7f`, Sinkhole preserves the wire-format name in the response and still returns the normal `0.0.0.0` or `::` answer. Such a query doesn't become SERVFAIL just because its label isn't a hostname-style label.

## Search the Catalogs \{#search-the-catalogs}

Select **Add from Catalog** under **DNS** to search AdGuard Home's list registry and the DNS section of pfBlockerNG's feed catalog. Sinkhole fetches both only when the search opens or you select **Refresh**; neither catalog is bundled or downloaded on a schedule.

Feeds assigned to Encrypted DNS, Tor, or VPN bypass protection don't appear here. They are available only through **Add from Catalog** under **Bypass**.

Results appear as cards. Use the search, source, and maintainer controls together, select a category chip, and switch **Group by** between **Category** and **Maintainer**. Category chips show counts for the current search, source, and maintainer filters, while the maintainer menu puts the owners with the most matching lists first.

Each card shows the list name, its maintainer or category, source catalog, a two-line description, homepage, and **Add** or **Added** state. The cards don't show ratings, badges, or recommendations. Selecting **Add** creates an ordinary list row whose URL can be assigned like any manually entered source.

New lists, including ones added from the catalog, block nothing until you select them for Global, a network, or a device on Blocking.

Each card's **Contents** line says **Domains**. Adding a catalog result keeps its catalog name unchanged.

Catalog copies are cached under `/var/db` for one day. A failed refresh keeps the last good catalog copy and shows the fetch error on Status.

## Add Bypass Lists \{#add-bypass-lists}

Open **Lists → Bypass**, select **Add** below **Bypass Lists**, then enter a local name, kind, and HTTP or HTTPS URL. New rows are disabled until explicitly enabled. Saving returns to **Lists → Bypass**. The table also shows each row's saved entry count and last fetch.

Each source accepts one entry per line. A list can mix domains, IPv4 addresses, IPv6 addresses, and CIDRs; text after `#` is a comment. Invalid and overlong lines are skipped. A download that exceeds the fixed byte or accepted-entry limit is rejected, leaving the last good copy in place.

An enabled Bypass List updates on the configured list schedule, with the same bounded download client as other lists, only while its matching **Providers**, **Tor**, or **VPN** protection is on. A failed fetch keeps the last good saved copy from the same URL, and **Status → Bypass Lists** reports entries, last fetch, and the most recent error for each row. Sinkhole doesn't bundle or recommend a Bypass List.

**Add from Catalog** under **Bypass** searches the AdGuard Home list registry and the DNS, IPv4, and IPv6 sections of pfBlockerNG's feed catalog. Results are limited to bypass feeds and have a fixed **Encrypted DNS**, **Tor**, or **VPN** kind, which the chips above the cards filter.

Each card's **Contents** line says **Domains**, **IPv4 addresses**, or **IPv6 addresses**. When you add a pfBlockerNG IPv4 or IPv6 result, Sinkhole appends ` (IPv4)` or ` (IPv6)` to its saved name; domain results keep the plain catalog name. Adding a result creates an enabled Bypass List.

Global, each network, and each device choose the Bypass Lists they use on [Bypass](/docs/configure/bypass-protection#set-protections-per-network-and-device).

## Add IP Lists \{#add-ip-lists}

Open **Lists → IP** and select **Add** below the IP Lists table to open the IP-list editor. A row uses an HTTP or HTTPS URL, chooses IPv4, IPv6, or both families, and controls whether the source is enabled. Saving returns to **Lists → IP**; select the pencil or double-click a row to edit it.

Valid lines are individual IPv4 or IPv6 addresses and CIDR networks. IPv4 networks broader than `/8` and IPv6 networks broader than `/16` are skipped and counted with other invalid lines; the boundary networks `/8` and `/16` are accepted. A download with no valid entry doesn't replace the last good saved copy.

**Add from Catalog** under **IP** searches the IP sections of pfBlockerNG's feed catalog. Encrypted DNS, Tor, and VPN bypass feeds are excluded and appear only under **Bypass**. Each card's **Contents** line says **IPv4 addresses** or **IPv6 addresses**. When you add a result, Sinkhole appends ` (IPv4)` or ` (IPv6)` to its saved name, trimming only the base name when necessary.

Global, each network, and each device choose the IP lists they use on [IP](/docs/configure/ip-and-country-blocking#set-blocking-per-network-and-device).

## Set Global Allowed Domains \{#set-global-allowed-domains}

Global exceptions live on **Blocking → Global** in the **Allowed Domains** box. Each line allows that domain and its subdomains through global lists. Select **Save** to apply them.

A global allowed domain is checked after device and network rules. It therefore can't override a list that already blocked the query at a more specific device or network level.

## Choose the Update Frequency \{#choose-the-update-frequency}

The **General → Update Frequency** setting controls scheduled DNS-list updates while General is enabled. The same schedule runs IP/country updates while IP blocking is enabled, and an enabled Bypass List only while its matching **Providers**, **Tor**, or **VPN** protection is on:

| Setting       | Schedule                                                          |
|---------------|-------------------------------------------------------------------|
| Hourly        | Once each hour at the firewall's stable randomized minute.        |
| Every 6 hours | Every six hours at the same stable randomized minute.             |
| Daily         | Once daily at that minute, with `00` as the scheduled hour.       |
| Weekly        | Once each Sunday at that minute, with `00` as the scheduled hour. |

`Daily` is the default. **Status → Update Now** starts a manual full update without changing the saved schedule.

## What Happens During an Update \{#what-happens-during-an-update}

1. Downloads each enabled source through the bounded download client.
2. Parses and normalizes it into a temporary copy.
3. Replaces the saved copy atomically only when the new copy is valid.
4. Compiles current global, network, device, allowed-domain, and alert policy.
5. Deploys a new local generation and lets the Unbound module load it.

When new blocked names widen policy, Sinkhole waits for the module to load the generation and then reloads Unbound once to clear cached answers. [How Updates Work](/docs/safety/how-updates-work) covers the complete availability and fallback model.
