Block unwanted websites with separate policies for the whole network, one VLAN, or one device, all inside pfSense.

## What Sinkhole Does \{#what-sinkhole-does}

Sinkhole for pfSense gives parents and employers control over which <Terminology title="Names or addresses to block, pulled from a URL you add" to="/docs/reference/terminology#lists-and-scopes">block lists</Terminology> apply to each part of a network. It keeps the last good copies on the firewall, so DNS can answer immediately after a restart or reload while newer copies download in the background.

Blocked names answer with `0.0.0.0` or `::`. A CNAME chain that reaches a blocked name is blocked too, while a name allowed at the deciding level stays allowed.

## Why Use Sinkhole? \{#why-use-sinkhole}

1. Applies policies at global, network, and device <Terminology title="Who a list applies to: whole network, a VLAN, or one device" to="/docs/reference/terminology#lists-and-scopes">scopes</Terminology> so kids, guests, employees, and individual devices can receive different lists.
2. Uses <Terminology title="The last good copy, so DNS never waits on a download" to="/docs/reference/terminology#lists-and-scopes">saved lists</Terminology> so DNS never waits for a download or loses a working list after a failed update.
3. Sends an <Terminology title="Get notified when chosen lists block chosen clients" to="/docs/reference/terminology#alerts">alert rule</Terminology> only for the lists and clients you choose, through pfSense's own notification system.
4. Provides optional <Terminology title="Stops devices from dodging Sinkhole with their own DNS" to="/docs/reference/terminology#bypass-protection">bypass protection</Terminology> for plain DNS, encrypted-DNS discovery and providers, Tor relays, and VPN providers or ports.
5. Adds separate IP and country blocking when DNS filtering isn't enough, without requiring a second host or cloud service.
6. Locks search engines into <Terminology title="An engine's safe mode, forced for every device in a scope" to="/docs/reference/terminology#lists-and-scopes">SafeSearch</Terminology> for the scopes you choose, so filtered results don't depend on each device's settings.

## How DNS Integration Works \{#how-dns-integration-works}

Sinkhole runs as a Python module inside pfSense's Unbound-based <Terminology title="pfSense's built-in Unbound DNS, where Sinkhole runs" to="/docs/reference/terminology#dns-basics">DNS Resolver</Terminology>. The module loads only local, compiled files when Unbound starts and watches for newer local generations without making a DNS query wait.

The DNS Resolver provides one Python script slot. Sinkhole takes it only when the slot is empty or already belongs to Sinkhole, and it refuses to replace another owner such as pfBlockerNG's DNSBL module.

:::warning

Sinkhole and pfBlockerNG can't filter DNS at the same time. Sinkhole stays inactive while pfBlockerNG is installed and enabled, even when its DNSBL runs in Unbound mode without the Python slot.

:::

## What Stays Under Your Control \{#what-stays-under-your-control}

- **Lists** — Add sources you trust by URL or find them with the neutral <Terminology title="Find well-known block lists without hunting for URLs" to="/docs/reference/terminology#lists-and-scopes">popular-list search</Terminology>. Sinkhole publishes and recommends no list.
- **Clients and Blocking** — Define a network for one pfSense interface or VLAN and a device identified by one or more IP addresses, DHCP static mappings, and MAC addresses, then choose the lists of Global, each network, and each device.
- **Allowed domains** — Let a domain and its subdomains through at the global, network, or device level without dropping a complete list.
- **SafeSearch** — Choose which search engines are locked into their safe modes for each scope, and whether YouTube is Moderate or Strict.
- **Alerts** — Choose the list and client combinations that create local WebGUI notices or use pfSense's configured remote notification services.
- **Bypass** — Keep every control off or select client-facing interfaces and explicitly enable plain-DNS redirect, encrypted-DNS signals, provider lists, or tunnel protections.
- **IP blocking** — Keep it off or select IP lists, countries, interfaces, directions, and allowlisted addresses.

## Limits \{#limits}

DNS blocking isn't complete traffic control. Bypass protection covers common alternate paths only when each control is enabled, and it can't identify every encrypted or custom tunnel.

Block events and notices reveal what clients tried to reach. That information stays on the firewall apart from notifications you choose to send through pfSense.

## Languages \{#languages}

The WebGUI follows the language selected in pfSense and ships in English and the other 17 pfSense locales.

The documentation site provides English and the other 17 pfSense locales. Translated pages preserve the English anchors so links reach the same section in every language.
