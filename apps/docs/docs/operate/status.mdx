## Status Panels \{#status-panels}

Open **Firewall → Sinkhole → Status** to see these panels:

| Panel                   | What it reports                                                                                                                    |
|-------------------------|------------------------------------------------------------------------------------------------------------------------------------|
| Summary                 | Compile, deployment, generation, operation, Resolver owner, overall Sinkhole state, and **Update Now** beneath the panel.          |
| Lists                   | DNS-list URL, saved entry count, last successful update, and last error.                                                           |
| Popular-List Catalogs   | Last fetch and last error for the AdGuard Home and pfBlockerNG catalog sources.                                                    |
| Invalid Saved Rows      | Malformed list rows that remain available for repair; shown only when such rows exist.                                             |
| Scopes                  | Client-map rebuild time and error, followed by separate Networks and Devices panels.                                               |
| Alerts                  | Last run, events read or stale, notifications sent or held back, dropped events, and last error.                                   |
| Bypass                  | Every protection, interfaces, redirect-rule state, Bypass anchor state and counts, followed by Bypass Lists and any repair panels. |
| IP and Country Blocking | Policy selections, table and rule counts, updates, errors, and anchor state, followed by a separate IP Lists panel.                |

Disabled list and scope rows appear muted. A source with an error can still show entries and an earlier successful update because the last-good copy remains active.

## Sinkhole State \{#sinkhole-state}

The final **Sinkhole** row in Summary is the quickest Resolver-integration check:

| State                                    | Meaning                                                                                                |
|------------------------------------------|--------------------------------------------------------------------------------------------------------|
| `Active`                                 | Sinkhole is enabled, owns the Python slot, uses Python mode and `pre_validator`, and has runtime data. |
| `Inactive: Sinkhole is disabled.`        | General **Enable** is off.                                                                             |
| `Inactive: DNS Resolver is disabled.`    | pfSense's DNS Resolver is off.                                                                         |
| `Inactive: ... slot is owned by ...`     | Another Python script, such as pfBlockerNG DNSBL, owns the single slot.                                |
| `Inactive: Sinkhole does not own ...`    | The configured script isn't Sinkhole even though no different owner was reported.                      |
| `Inactive: ... Python mode is disabled.` | The Resolver no longer has Python mode enabled.                                                        |
| `Inactive: ... pre-validator position.`  | The module order no longer places Sinkhole at `pre_validator`.                                         |
| `Inactive: ... runtime files ...`        | The script or current compiled generation is missing.                                                  |

When Sinkhole is deliberately disabled, **Deployment Needed** is `No`, **Loaded Generation** is `Module not loaded.`, and the page doesn't show a deployment warning. Another inactive integration state forces **Deployment Needed** to `Yes` and **Loaded Generation** to `Module not loaded.`. Fix that stated reason before treating compiled data as active.

## Compile and Deployment State \{#compile-and-deployment-state}

| Field               | Meaning                                                                                |
|---------------------|----------------------------------------------------------------------------------------|
| Compile Needed      | Saved policy changed or the last compile didn't complete successfully.                 |
| Compiled Generation | Identifier produced by the most recent successful compile.                             |
| Deployment Needed   | Compiled content isn't the content deployed for Unbound, or integration is inactive.   |
| Deployed Generation | Identifier in the currently deployed runtime manifest.                                 |
| Loaded Generation   | Identifier the Unbound module reports it loaded.                                       |
| Update Running      | Shown only while a list or IP update owns the shared update lock.                      |
| Removal in Progress | Shown only while the durable removal marker is set and integration is being withdrawn. |
| Python Script Owner | Current value of the Resolver's single `python_script` slot, or `None`.                |

The page shows a warning box when compile or deployment is pending, including the recorded reason. Matching compiled, deployed, and loaded identifiers show that saved policy reached the running module.

## Scope and Alert State \{#scope-and-alert-state}

The Scopes summary reports the client-map rebuild state. The separate **Networks** and **Devices** panels report each interface's current CIDRs and each device's current addresses. A conflict names an address claimed by multiple devices; the first device in table order owns that address for policy.

The **Alerts** panel describes only the most recent minute job. **Notifications held back** includes cap or unread-notice suppression, while **Events dropped by module** indicates that the bounded in-memory or on-disk event queue filled.

## Bypass State \{#bypass-state}

The Bypass panel reports `On` or `Off` for TLS and QUIC, provider lists, Firefox, Private Relay, Tor, VPN-provider lists, and standard VPN ports. **Discovery** reports its selected mode. **Interfaces** confirms the shared client-facing selection.

The independent firewall anchor reports:

| Field                   | Meaning                                                                                          |
|-------------------------|--------------------------------------------------------------------------------------------------|
| Firewall rules loaded   | Whether the `sinkhole/bypass` anchor exists when current settings require it.                    |
| Firewall rules current  | Whether the loaded digest, rules, and tables match the current settings and last-good list data. |
| Firewall rule count     | Number of active rules in the Bypass anchor.                                                     |
| IPv4/IPv6 table entries | Final provider, Tor, and VPN address counts after protected firewall addresses are removed.      |

The **Bypass Lists** table reports each row's kind, enabled state, saved entry count, last fetch, and last error. A failed fetch can therefore show an error alongside entries from the retained last-good copy.

### Plain-DNS Redirect State \{#plain-dns-redirect-state}

| State  | Meaning                                                                                       |
|--------|-----------------------------------------------------------------------------------------------|
| Off    | Plain-DNS redirect is disabled.                                                               |
| On     | Redirect is enabled and every saved exemption is valid.                                       |
| Paused | At least one saved source or destination exemption is invalid, so no redirect rules are used. |

The **pfSense loaded rules** field has three states:

| State       | Meaning                                                                                        |
|-------------|------------------------------------------------------------------------------------------------|
| Yes         | `/tmp/rules.debug` contains exactly the redirect block Sinkhole currently wants.               |
| No          | The wanted block isn't loaded.                                                                 |
| Out of Date | A Sinkhole block is loaded, but its text doesn't match current settings or Resolver listeners. |

Each family target is either the selected listener address or a reason no rule can be built. **Last parse error** is shown only while the current block is missing after pfSense rejected it.

## IP and Country State \{#ip-and-country-state}

The IP panel's main state is **On** or **Off**. Its **IP Anchor** uses **Yes**, **No**, and **Out of Date** with the same loaded/current distinction as the Bypass anchor.

Table entry counts show the final merged IPv4 and IPv6 networks after allowlist and protected-address subtraction.

**Skipped Lines** counts invalid IP-list input. Comment and blank lines are not counted.

**GeoLite2 Last Update** is independent from the most recent list update.

## Run Update Now \{#run-update-now}

Selecting **Update Now** beneath Summary starts `/usr/local/sbin/sinkhole --manual` in the background and returns immediately. The button doesn't stream output, so **Update Running**, the DNS/Bypass/IP list rows, compile fields, and last errors provide the result.

The manual job uses the same shared update lock as scheduled list updates and package self-update. If another update owns it, the existing job continues and pending apply work is preserved.
